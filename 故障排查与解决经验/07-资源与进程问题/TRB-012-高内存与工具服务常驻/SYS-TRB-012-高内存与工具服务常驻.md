首先停止新增重型步骤，保存任务断点并保持必要通信软件可用。不要按同名、数量多或短时 CPU/IO 为零结束进程，不反复清工作集来凑启动余量。

## 一句话现象

多个 AI 对话与工具并用时，物理内存余量偏低、系统提交较高；分页位置调整并重启后，内存占用再次上涨。工具服务存在多份同类实例，但所属会话和安全回收条件尚未查清。

## 当前是否解决

本案例的分页配置已在重启后回读生效；这项配置验收完成。高内存回涨、是否存在泄漏，以及长期卡顿的完整原因仍未解决。

后续未在所查日志中观察到同类启动超时，只能说明该观察范围内恢复，不能证明分页调整修好了超时。重启与分页迁移同时发生，也不能拆分两者对体验的贡献。

## 适用环境与错误签名

- 环境：Windows 桌面 AI 应用及其工具支持进程；不是某个业务项目专属问题。
- 相关表象：物理可用量下降、提交量上涨、工具进程常驻，以及 `Timed out waiting for MCP response to configRequirements/read`。
- 具体版本、原始时点、软件清单及进程身份只保留在操作者本地证据中；未建立可推广到所有版本的宿主缺陷结论。
- 截图拍摄时间及其与具体日志事件的对应关系未核，不能把同一报错文字当成同一次事件。

## 已确认事实、推断与待确认项

| 类型 | 结论及证据边界 |
| --- | --- |
| 本地事实 | 早期样本物理余量偏低，机械盘承担分页，硬页读回与磁盘队列同期出现；未证明每次 IO 都来自分页文件。 |
| 本地事实 | 经授权迁移分页并重启后，配置与实际分页位置符合指定目标，转储配置保持；随后较长间隔的系统样本仍显示内存回涨。 |
| 本地事实 | 按进程身份匹配的短窗比较中，客户端提交增量较大；工具支持进程体现明显常驻负担。缺少较早逐进程基线，不能倒推此前全部涨幅归属。 |
| 本地事实 | 多个同类工具具有相同启动命令，短窗未见其中部分服务的 CPU/IO 增长；没有核实其所属会话、共享依赖或是否可安全退出。 |
| 本地事实 | 历史一次工作集收缩后，目标驻留下降又回升，私有提交未释放，仍未满足当时任务的准入条件。 |
| 工程推断 | 物理余量小、慢盘分页与应用常驻可能共同加重卡顿风险；现有证据不足以分配各因素的因果贡献。 |
| 待确认 | 是否泄漏、启动与退出机制、空闲会话归属、安全释放和按需重建入口、长期性能及容量改善效果。 |
| 操作者约束 | 必要通信链路保持可用；已排除的存储设备不作为回退；其他业务继续暂停。具体设备与权限仅按各次原始授权处理。 |

物理可用量、系统提交和进程私有驻留分别记录范围、单位与采样时点，不能相加。进程私有指标之和也不能核算全部 Windows 内存。

| 配置诊断 | 核物理余量、提交、分页位置与磁盘类型 | 发现内存压力与慢盘分页并存，未定位全部卡顿原因。 |

| 后续复查 | 比较系统快照，再核进程身份及短窗增量 | 回涨仍存在；不能把正在聊天和诊断的样本称为纯闲置泄漏试验。 |
| 工具映射 | 核已取得的启动链、功能分组和短窗计数 | 证实同功能多份常驻，尚未证明冗余或可关闭；没有实施清理。 |
| 独立复核 | 回读必要原件、截图、采样与归类脚本，复核数值及结论 | 修正截图与日志的未经核验时间绑定；未重新采样或重演卡顿。 |

一次配置比较曾因环境变量与展开路径的字符串差异误报转储变化；保留原件后，依据前后实际字段纠正。检查脚本误报不能直接当作真实系统故障。

## 当前处置与下一步

1. 保留已验生效的配置和失败记录，不因回涨就重复修改分页、删除正在使用的分页文件或停用全部分页。配置变更只在精确授权、空间与转储需求核清后安排。
2. 优先有界、只读核实工具服务的所属会话、父链、退出机制和受支持的释放/重建入口；沿已有原件补缺，不持续采样或反复打开工具增加负载。
3. “暂停任务”不证明工具服务已经退出；“低活动”不证明可以结束；“相同启动命令”不证明共享一个会话或多余实例。资料或能力不足时保存具体缺口。
4. 若形成可执行回收方案，先说明精确对象、共享影响、原始权限、停止点、恢复入口，以及聊天、命令和相关工具的回归标准；不得直接按进程名批量清理。
5. 只按当前有效授权实施必要变化，前后用同口径比较效果和副作用。阶段快照不能承诺零影响、长期不卡顿或已释放全部内存。

扩容是容量改善候选，需要另核需求、兼容、费用及实际效果，不能由提交量直接推算购买量，也不能保证修复泄漏。
