# TRB-007 · HTTP 429：模型线路限流

| 字段 | 内容 |
| --- | --- |
| 错误码 | `429` |
| 典型正文 | `rate_limit_error` / `All available accounts are currently rate-limited` / `exceeded retry limit, last status: 429 Too Many Requests` |
| 根因范围 | 当前模型线路的速率、余额或账号池被限流；自定义中转站也可能在上游侧限流。不等于用户全局额度耗尽 |
| 当前状态 | 本案例已由上游中转站处理后恢复；具体根因和修复方法未披露 |
| 最后核验 | `2026-10-21`（操作者报告恢复；未在本地重跑鹈鹕探针） |

## 识别与排除

同时核对错误正文、实际模型线路、同一时段其他模型的成功/失败对照、任务状态和是否产生副作用。若请求未进入正常生成且没有消息项或用量，不能据此认定用户账号全局额度耗尽。官方 429 还可能表示速率、余额或组织/项目限额，必须结合正文判断。

通过 MagPie 等自定义中转线路使用 Codex 时，还要区分“官方 ChatGPT/Codex 账户额度”和“中转站所选上游账号池”。官方账户额度正常，不代表中转供应商不会返回 429；反过来，站主处理后恢复，也只能确认该中转线路当前可用，不能替代对具体技术根因的公开说明。

## 中转站 429 的单次鹈鹕探针

遇到中转线路反复返回 429 时，先停止原任务请求的连续重试，保存当前进度，再单独发起一次最小生成请求：

```text
Generate an SVG of a pelican riding a bicycle.
```

看返回效果即可，不连续重跑：

- 请求完成且能看到鹈鹕骑自行车的 SVG 图形：说明当前中转线路已经能够处理一次最小生成请求，可再重试原任务一次。
- 仍返回 429、空回复、线路错误或明显不是该提示词的结果：保留错误和发生时间，停止重试，联系中转站或切换到已验证健康的模型线路。

这个探针是一次可用性检查。成功只能证明线路当前可以响应，不能证明原请求的具体限流原因，也不能证明某个账户的全局额度状态。

## 本案例结论

`2026-10-21` 的 MagPie 专用窗口在请求时出现 `exceeded retry limit, last status: 429 Too Many Requests`。操作者与上游中转站站主沟通后，站主确认并处理了该问题，但目前拒绝披露具体修复方法，因此：

- 操作者报告站主处理后线路恢复，支持优先检查中转线路；尚无服务端根因证据，不能据此排除其他层因素或确认具体技术原因。
- 不能把站主的处理动作扩展写成某个已确认的技术根因。
- 以后再次遇到同类 429，先做一次鹈鹕探针；若探针通过，再尝试原任务一次。

## 最小恢复

1. 保存脱敏错误正文和线路信息，停止对同一模型线路的连续重试。
2. 在授权范围内切换到同一时段已验证健康的模型，先做无副作用连通性检查。
3. 使用自定义中转线路时，可执行一次鹈鹕探针；检查 HTTP 200、可读回复和任务状态恢复后，再继续业务。
4. 服务方确认账号池解除限流前，不切回故障模型；必须切回时先做一次新的鹈鹕探针。

此前同线路先出现 `502`、随后 `429` 时，应把 `502` 作为线路不稳定信号记录，但不能把两者合并为同一根因。该故障与工具调用配对 `400` 分开处理。

## 验证标准与边界

- 通过：鹈鹕探针得到可读的 SVG 结果，且不再返回 429；随后原任务只重试一次并正常进入生成。
- 未通过：探针仍为 429、空回复、中断或线路错误；停止连续重试，联系中转站或切换健康线路。
- 未验证：本次中转站的具体限流字段、处理动作和服务端配置变化。
- 回退：保留任务进度并切回同一时段已验证健康的模型线路；恢复原线路前重新执行一次探针。

## 失效与重验条件

中转站、模型、账号池或错误正文发生变化时，需要重新确认 429 的归属；鹈鹕探针通过但其他请求仍频繁 429 时，应检查原请求规模、并发和线路的独立限流规则。
