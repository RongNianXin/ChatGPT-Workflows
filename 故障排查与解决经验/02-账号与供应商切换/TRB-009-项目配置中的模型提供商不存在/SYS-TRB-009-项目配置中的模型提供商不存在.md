## 一句话现象

打开目标任务时，界面高频闪烁错误：`ChatGPT 无法加载 config.toml，因此对话中无法继续。请修复 config.toml：Model provider 'OpenAI' not found。保存文件后，重新打开此对话。`

## 当前是否解决

## 已确认事实、合理推断与待确认项

### 已确认事实

1. 截图中的错误明确指向 `config.toml` 加载失败，并明确指出提供商名 `OpenAI` 未找到。
2. 错误发生在对话加载/继续之前，因此不是任务正文、工作区代码或普通上游模型拒绝的直接证据。
3. 截图表现为错误提示反复出现，用户观察到高频闪烁；这与界面反复触发加载、失败、重试循环相符，但尚未有网络或请求日志证明实际发出了高频远端请求。
4. 目标工程目录存在项目级 `.codex/config.toml`，原始内容只有沙箱和审批设置，没有声明模型或 provider。
5. 会话元数据保存的 provider ID 是 `OpenAI`；用户级配置原来只有 `[model_providers.custom]`，其中 `name = "OpenAI"` 只是显示名称。
6. 仅在项目级配置临时加入模型设置，任务仍为 `notLoaded`；该临时修改已按备份恢复。
7. 在用户级配置增加 `[model_providers.OpenAI]`，保留原 `custom` 配置后，任务重新打开成功并进入 `idle`。

### 合理推断

- 根因已由配置差异和恢复验证支持：任务按 provider ID `OpenAI` 查找，而配置只注册了键名 `custom`；`name = "OpenAI"` 不会自动创建名为 `OpenAI` 的键。
- 高频闪烁应解释为配置失败后的桌面端加载/重试循环；本轮没有证据证明它造成了高频远端业务请求。

### 待确认项

- 其他任务是否也保存了 `OpenAI` provider ID，仍需单独检查；不能把本次别名修复自动推广到所有任务。
- 桌面端版本和完整解析日志仍未记录，因此高频闪烁的内部重试次数未量化。

## 解决或规避步骤

本案例已验证的修复路径：

1. 关闭目标任务的自动重试或暂时离开该任务，停止高频点击。
2. 备份用户级 `config.toml`，保留原始文件哈希。
3. 在用户级配置增加与现有 `custom` 相同的 `[model_providers.OpenAI]` 别名，保留原配置。
4. 重新打开任务一次，确认状态稳定且错误消失；失败则立即恢复备份。

不要把任务引用直接改成 `custom`，因为已有任务明确保存的是 `OpenAI`。不要删除原 `.codex`、历史会话或认证文件。
