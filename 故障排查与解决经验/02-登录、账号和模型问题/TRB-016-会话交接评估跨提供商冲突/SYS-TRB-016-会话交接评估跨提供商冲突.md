## 现象

“会话交接评估”查询某个长期任务时，工具提示会话分段的 `model_provider` 不一致并退出。这个任务的历史确实跨过了不同提供商或路由；它不等于会话文件损坏，也不等于当前网络故障。

## 原因与修复

旧逻辑把提供商变化当成所有元数据冲突，直接拒绝读取。这样虽然避免了把不同来源的 Token 趋势混在一起，却也误伤了“同一任务只是换过线路”的正常历史。

现在的逻辑分开处理：

1. 任务身份、来源或项目绑定冲突仍然阻断，避免把别的任务静默拼进来。
2. 只有提供商标记变化时继续逐段读取，并在变化点重新开始 Token 趋势基线。
3. 报告明确列出提供商变化；声明的提供商不证明真实上游网关。

修改前同一查询退出失败；修改后同一查询退出码为 0，并生成包含分段、压缩次数、容量观察和提供商警告的报告。趋势不会跨提供商连续计算，因此没有伪造连续收益。

## 安全使用

- 重新查询前确认任务 ID 来自当前本机任务记录，不从标题或相似名称猜测。
- 看到“提供商变化”时可以阅读报告，但不要把跨段增长率当成同一模型、同一线路的连续测量。
- 如果报告改为身份、来源或项目绑定冲突，停止合并并保留原始证据；不要手工修改 JSONL 或数据库来绕过检查。
- 当前工具是 Windows 开发预览，其他系统和超大日志仍需单独验证。
