# 相关工具和许可证说明

更新时间：2026-08-20。

本说明用于记录公开项目对本仓库故障工具的启发、许可证边界和实现差异，避免把独立实现误写成原创发现，也避免在引流时暗示与其他项目存在官方合作关系。

## 本次结论

- [codex-session-cleaner](https://github.com/safrano9999/codex-session-cleaner) 与 [codex-rescue](https://github.com/shleder/codex-rescue) 均声明使用 MIT 许可证；判断依据分别是它们仓库中的 [LICENSE](https://github.com/safrano9999/codex-session-cleaner/blob/main/LICENSE) 和 [LICENSE](https://github.com/shleder/codex-rescue/blob/main/LICENSE)。
- 本次没有复制或改写两个项目的源码、测试、README 或命令输出，也没有把它们作为依赖打包。本仓库只独立实现通用安全措施，并保留自己的结构、命令和验证流程。
- 历史版本曾借鉴并独立实现这些通用措施：精确选择单个任务、候选文件落盘、源文件变化检测、保留时间戳与文件权限、失败关闭、备份和回滚。后续审查发现分页谱系和回滚清单边界没有得到完整验证，因此这段历史不能证明当前真实安装或真实回滚安全。
- 如果以后直接复制两个项目的源码或其重要片段，必须在分发副本中保留对应版权声明和 MIT 许可证；在完成逐文件来源登记前，不得合并此类代码。

以上是仓库维护策略，不构成法律意见。

## 项目比较

| 项目 | 适合解决的问题 | 与本仓库的关系 | 未直接合并的原因 |
| --- | --- | --- | --- |
| `codex-session-cleaner` | 对单个 Codex 会话执行范围较窄的 provider 密文清理 | 启发了单任务 UUID 选择、源文件稳定性检查和元数据保留 | 它的密文识别策略、平台范围和无备份设计与本仓库的结构化转换、Windows 优先和可回滚目标不同 |
| `codex-rescue` | 只读诊断、损坏会话取证、恢复分叉和脱敏支持包 | 可作为高级诊断的独立补充工具 | 项目仍处 alpha 阶段，功能和依赖较多；整包引入会扩大维护面，也不应把第三方工具包装成本仓库自有实现 |

## 当前采用方式

本仓库的迁移工具已因分页谱系风险暂停真实安装，也因历史清单的 schema、允许根目录和路径穿越边界未经验证而暂停真实回滚。`--apply` 与 `--rollback-latest` 都会在读取或修改真实任务之前失败关闭；下面的历史命令仅用于识别旧入口，不得执行：

```powershell
node install_bulk_codex_migration.mjs --apply --task "00000000-0000-0000-0000-000000000000"
```

恢复安装入口前，除了单文件内容保真，还必须证明子分段的 `history_base.thread_id` 指向已核验父任务，`end_byte_offset` 合法且未越界，并且父文件候选在该偏移前的字节前缀未改变。恢复回滚入口前，还必须验证清单 schema、允许根目录、路径穿越、损坏清单、重复运行和部分失败边界。

如需更完整的只读诊断，可单独评估 `codex-rescue`；使用第三方工具前应重新核对当前版本、安装脚本和隐私边界，不上传原始 JSONL、数据库、凭据或未脱敏支持包。

截至上述更新时间，其上游 README 提供了 `codex-rescue doctor --latest` 作为最近任务的只读检查入口。该项目仍标注为 alpha，命令、输出格式和兼容范围都可能变化；本仓库只记录入口，不代为安装、不锁定版本，也不保证第三方工具能修复特定会话。
