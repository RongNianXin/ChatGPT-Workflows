# 新项目是否启用总指挥工作流

这份清单只解决“新项目如何选择”，不把当前总指挥的任务 ID 或历史状态复制到新项目。

## 不启用（默认）

只配置全局 `AGENTS.md` 的通用省 Token原则。普通空白任务按自己的目标工作，不读取或假设总指挥身份。

## 启用

1. 将版本化的 `第二代总指挥的工作模式/` 放入项目，并在根 `AGENTS.md` 加入短版入口指针。
2. 复制并填写 `工作流启用声明.md`，把 `状态` 保持为 `enabled`；不要填写固定任务标题或任务 ID。
3. 如果项目要使用跨项目经验，再复制或登记 `跨项目经验库/`，至少登记 `经验索引.md` 的相对路径、索引版本、修订号和 SHA-256；不要把候选原始资料复制进新项目。经验库缺失时登记 `EXPERIENCE_INDEX_UNAVAILABLE`，不阻断不依赖它的任务。
4. 按 `10-自动状态索引规范.md` 建立项目实例的动态状态入口，登记当前世代、唯一写者、租约、断点、规则指纹和经验索引状态。状态入口未建立前，项目仍是 `UNKNOWN/BLOCKED`，不能开始依赖中央状态的专项修改。
5. 首次总指挥任务自行完成规则加载、状态核验和通信授权登记；后续每个空白任务只按声明读取最小入口，专项任务先握手。经验索引只在任务主题命中或操作者明确要求时按需读取。
6. 工作流规则、启用声明、经验索引或状态 schema 变化后，旧的启动判断失效；下一项依赖它的实质动作前重新回读并登记受影响的刷新记录。

初始化完成的判据：声明可读、入口文件可读、动态状态可定位且未过期、当前身份和单写者可回读；否则只报告缺口，不把目录存在视为已启用。
