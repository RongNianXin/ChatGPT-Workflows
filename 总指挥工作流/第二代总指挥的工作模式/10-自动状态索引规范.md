# 自动状态索引规范

## Worktree 登记

每个新建 worktree 在开始实质工作前都要取得项目内唯一且不复用的人类可读稳定别名，并在本项目既有 `AI状态索引.md` 中建立 `WORKTREE` 记录；不为此另建平行登记文件。规范语义、异常边界和权限规则以 [02“Worktree 登记与废弃边界”](02-总指挥核心规则.md#worktree-登记与废弃边界)为准。

> **编号迁移**：正式交接使用 1C/1D，中断恢复使用 1G；本文历史段落中的 6A/6B 仅作旧编号兼容解释。场景六资料查阅不建立总指挥交接索引。

版本：2026-09-26.7

用途：让 AI 自动保存和检索总指挥主执行断点、轮次、例外任务、快照、授权卡、派生对象与交接 ID，减少使用者本人重复填写和双窗口转发。场景 1G 的普通任务恢复不强制创建本索引；专项任务只登记自身短状态或由总指挥保存一条指针。

本文件是索引位置、字段、检索、回退和持久化规则的唯一主维护文档。其他文档只声明何时需要状态服务，不复制本文件算法。

凡项目状态文件同时保存当前事实与历史，必须只有一个可机器定位的 `CURRENT` 区；当前读取默认只进入该区。已关闭、被替代或旧世代记录移入 `HISTORY`，并从 CURRENT 留下稳定回查指针，不在当前区继续堆叠旧副本。发现重复 CURRENT、同一字段多个当前值、CURRENT 引用旧世代或历史迁移后缺少回查入口时，将受影响控制面标为 `BLOCKED`；不得按文件顺序、修改时间或“最后一段”猜测。HISTORY 只在冲突、审计、恢复或明确证据缺口命中时按最小范围读取。

## 1. 存放位置

本文件只定义抽象规范，不保存任何具体项目数据。真正的索引文件统一命名为 `AI状态索引.md`，优先放在具体项目已有的个人、私有或本地管理入口/状态目录中。除非团队规则明确允许，不把个人控制面索引写进团队正式代码目录或提交到远端仓库。

总指挥按以下顺序自动定位：

1. 读取项目规则指定的管理入口或状态目录；
2. 复用该项目唯一存在且格式有效的 `AI状态索引.md`；
3. 尚无索引但管理目录唯一、可写、不会污染团队仓库且项目规则允许时，自动创建；
4. 存在多个候选、没有合适管理目录或项目规则禁止新增时，只请求使用者本人确认一次存放位置，不在仓库根目录随意新增文件。

不同项目和不同工作流实例必须使用不同索引，不得共享任务 ID、游标、授权或事件账本。

## 成果契约索引

按 [04 成果契约](04-状态、目标变更与交接规范.md#成果连续性与运行复现契约)只登记清单指针、用途、契约/规范化/序列化版本、事实截点、各层状态、聚合证据等级、受影响范围与恢复/失效条件，不复制五层规则或清单正文。运行成果、验证包和现场连续性账单分别定位；旧聚合记录值不得标为本轮已复算。事件发生时间与复核时间分开；平台 idle、归档状态和已停止调度分别取证，不互相推导。分享近期经验只回查必要证据，较早事实标背景，不为补时间扫描整份聊天。

## 2. 自动记录内容

以下是按用途选择的字段目录，不是每项任务的全量必填表。核心仅保留目标/未完成项、当前行动方与下一动作、写者边界、当前权限及失效条件、关键证据与适用规则/标题/指纹；其他字段只在对应场景实际存在时登记，已有详细记录用指针。必要但未知的事实须标缺口及影响，不能静默省略。普通任务无 GitHub 对象时不生成 PR/Issue 或 Assignee 空账；不另建同义“执行记忆”。字段由 AI 核验，不要求使用者填写：

- 项目标识、项目根目录、远端仓库和默认分支；
- 第二代规则根目录、`00-第二代工作流总览.md` 编号注册表版本、非编号的 `总指挥轻量交接启动配置.md` 路径/版本/大小/修改时间/SHA-256，以及各规则文件的编号、规范化相对路径、大小、修改时间和 SHA-256；仓库内指针以相对于当前仓库根目录的路径为跨设备事实，项目根和仓库外输入的绝对路径只保存在当前项目实例索引，不写入可分发规则文档；仓库克隆、移动或换盘后先验证新根目录并把相对指针重新绑定到当前仓库根目录，旧机器绝对路径随原实例失效，不得直接继承；
- 按需执行手册的规范化相对路径、用途、版本、大小、修改时间和 SHA-256；它们与 00～11 正式规则分区登记，不加入轻量交接固定来源，也不产生授权；
- 当前总指挥任务的适用规则编号、加载模式（标题级按需 / 完整 / 轻量交接 / 异常回退）、加载时间、启动配置指纹、来源规则比对结果、实际展开文件与标题、逐文件指纹和加载结果；新任务必须建立自己的加载记录，不得继承旧任务“已读”；
- 规则加载批次记录只保存在发送方现有状态中：规则根、目标、当前 `rule_version`、manifest 摘要和逐目标状态（`未发送 / 已发送待确认 / 已更新 / 更新失败 / 不可达`）。接收方项目内是否写入加载记录不影响加载结果；不因广播新建项目账本，也不把 `PASS` 当作未来行为必然遵从规则的证明；
- 本地操作者协作画像的功能状态 `unasked / enabled / paused / disabled / unavailable`、一次介绍状态 `not-shown / shown / answered / ignored`、最近节点维护结果、已核验规则根下的规范化相对指针、schema 版本、`profile_revision`、当前唯一画像写者、待合并脱敏候选数、最后复核时间、过期状态、容量门禁结果、`.gitignore` 命中和未被 Git 跟踪的核验结果；索引不得保存画像正文、独立身份资料档案的内容、摘要、存在性或指针、自然语言路由别名、条目摘要、原始证据、文件内容哈希、操作者标签、外发载荷或两次确认原文；
- 耐久 Commit 台账位置、最后核账截点和 `COMMIT-LEDGER` 短事件：提交标识/父节点、目标、影响范围、验证边界、远端状态、`ROUTINE/KEY_NODE`、保留原因、重写/合并映射、证据指针和失效条件；完整 Diff 与日志仍留在 Git 和任务证据中；
- Goal、轮次、状态快照、总指挥主执行阶段、例外专项任务、批量执行卡和补漏卡 ID；活跃请求清单中每项的来源、状态、依赖、当前行动方、下一动作、恢复条件及其与当前确认卡的覆盖关系；单项卡完成后不得据此删除未覆盖项；当前任务使用普通轮次还是平台 Goal，以及可观察的额度预警、额度耗尽或程序异常信号；平台未提供余额时只记“待确认”，不保存估算值；
- 跨任务接收事件短记录：来源、`MESSAGE_ID`/`RULE_REFRESH_ID`、消息用途、接收方角色、完整取得时间、实际读取范围、处理状态、回执状态、阻断类型、恢复条件、下一行动方和证据指针；专项任务只保存自身事件与回执，不写中央总指挥状态；
- 中央工作项清单的规范化相对路径、最后回读截点、非终态状态计数、当前优先级分布和最近完成成果指针；每项的稳定 ID、状态、优先级、精确断点、下一动作、责任对象、恢复/启动条件、失效条件和详细证据位置留在清单正文，索引不复制完整列表；
- 当前唯一产品写者、主执行 worktree/文件边界，以及每个例外专项任务的创建净收益依据、隔离边界和回传位置；适用项目目录或资源租约时，只保存权威入口指针、资源范围、写者/世代、`lease_revision`、状态、允许写入类别、运输通道、最后核验和失效条件，不复制第二套租约库；普通主执行不生成专项任务 ID；
- 每个 worktree 的 `WORKTREE` 记录：稳定别名、规范路径、项目键、创建时间、创建目的与当前用途、基线分支/HEAD、当前分支或 detached 状态/HEAD、特色与区别、禁止和受限操作及依据、变更摘要、工作区状态、责任方/唯一写者、活动/暂停/已合并/已放弃/长期保留/已删除/未登记/来源不明/映射冲突状态、最后核验时间、替代别名映射、清理或保留条件；涉及 Push/PR 或临时载体收口时，再登记 `source_worktree`、`source_head_oid`、`remote_ref_oid`、`main_worktree_head`、`main_worktree_status_fingerprint`、`integration_status`、`next_action_owner` 和 `recovery_condition`；别名不得复用，完整 Git 状态仍回源核验；
- 活动母任务 ID、决策版本、已确认结论、被否决方案、未决项和交付模式；
- 主场景、目标列表、使用者本人及协作成员身份卡列表、可选范围补充/限制、默认纳入规则、队列分区、跨场景关系与冲突、规范执行记录 ID 和引用；同一对象在当前活动母任务内不得生成两条相互独立的执行记录，历史轮次记录继续保留；
- 跨模块弱关联观察项的对象标识、间接证据摘要、发现截点、推荐选择、默认排除状态、使用者本人明确选择和后续补充卡引用；不得把普通整卡确认记录为弱关联纳入确认；
- Codex 任务/窗口 ID；平台无法提供时生成本地逻辑 ID，并标记来源；
- 启动与结束时间、快照截点、增量游标和上一可靠轮次；增量游标必须能覆盖对象新增以及既有对象上的协作事件变化，不能只保存最大编号；
- Base/Head、任务分支、worktree、Issue/PR、Review、Comment 和其他派生对象；对触发 3A/3B 的最新实质协作事件，记录事件类型、操作者、时间、来源对象、关联映射指针、命中目标和正向纳入依据；
- PR 直接 Base/Head 关系和 Issue 有证据的父项、前置或阻断关系，以及本轮文本树的记录位置；不在索引中复制完整大树，也不把普通 Related 保存成依赖；
- 并存实现决议矩阵与运行身份清单指针：目标候选、实现/入口、规范启动命令及自检输出、默认与回退、实际 profile/feature flag/环境覆盖、依赖、模型/资产/配置指纹、构建/服务来源、页面可见版本、核验时间、未决项和失效条件；不得把“代码已包含”保存为“实际已运行”；
- 使用者本人 Review 绑定的 Head、当前 Head、Review 有效性、checks 与 Actions 状态；checks 为零时记录后续查询结论，不能直接标记成功；
- Issue 草案键到正式编号、实现单元和 PR 的映射，以及 Reviewer 请求、最低有效批准数和局部门禁；
- 每个活动 PR 的交接契约状态：适用手册版本/指纹、正文最后核对 Head、当前 Head、`Closes/Refs` 语义、范围与排除、验收/失败条件、实际验证与未验证摘要、风险/恢复、Review request 绑定 Head、审查意见回复闭环和重新请求状态；正文和完整证据仍留在平台与任务记录中，索引只保存短摘要与指针；
- 测试、构建、CI、远端写入和交棒回执；
- 交付执行类别、估计区间及依据；首次 Push 前 CI 等价本地门禁的命令来源、绑定 Head、结果与未运行原因；实际关键路径、Push/CI波次数、CI等待期并行只读工作和可避免等待；
- 当前状态、当前有效行动引用（仅 `CURRENT_ACTION + EXECUTE_NOW / WAIT / BLOCKED`；工作项、动作范围、冲突域或受影响资源、状态版本、签发角色/收口方世代、下一行动方、授权依据、分维度证据身份、前置条件、`supersedes`、失效条件和投递状态）、候选与终态历史引用（`CANDIDATE / CANCELLED / SUPERSEDED`、替代链和证据位置）、完成凭证、恢复条件、后续行动方与动作，以及详细证据位置；证据身份按存在维度分列阶段/回档版本、运行 profile、实现常量、代码提交或 Head、工作区状态及源码/资产指纹，不用单一“版本”混写；同一冲突域不得保存两条当前有效行动，候选及终态历史不得登记为当前有效；
- 发生实质判断的对象对应的可迁移决策回执位置：待解释问题、实际选择、关键依据、未采用方案、事实截点和失效条件保留在对象/任务记录中，索引只保存对象到回执的映射，不复制正文；
- 授权卡内容、使用者本人确认原文、有效期和失效原因。
- 任务建议模型、实际可回读配置和调整原因。
- 使用者本人的必须/建议人工操作、参与类型、是否阻断当前对象、不执行影响、人工操作包位置、反馈和可复制的下一步提示词；其他成员的外部责任、协作交接、远端授权与回执单独记录。
- 信息不足恢复记录：触发语义、任务记录/Git/工作区/依赖/配置/模型/资产/已有验证的核对范围，正式候选、无关修改、临时内容、待确认项，来源证据、置信度和保护结论；忽略项只保存与目标有关的候选和排除摘要，不复制缓存、敏感材料或大目录清单。
- 链路排查记录：问题与复现基线、实际运行身份、实际执行图指针、稳定节点编号、节点覆盖状态（已观察 / 仅代码确认 / 待插桩 / 不适用）、观测点、第一处可靠偏差、根因假设与因果状态、修改节点、事故证据回归指针及状态（已复现且已修复 / 已复现但仍失败 / 未能复现 / 证据或环境缺失）、常规回归与未验证项、操作者理解状态；若生成分步 HTML，只登记模板版本、产物相对指针/指纹、绑定基线、证据类型与浏览器回读结果。完整中间产物保留在任务证据中，索引不复制敏感原始数据、图片或调试流水。
- 人工反馈回执：`通过 / 失败 / 部分通过 / 未执行 / 不确定 / 不适用`、绑定版本或 Head、工作区指纹、输入、步骤、观察点、事实时间、证据位置和失效条件；空白、沉默、未执行和不确定不得保存为通过。
- 按 `04-状态、目标变更与交接规范.md` 生成的高成本证据摘要 ID、来源指纹、适用对象/基线、敏感性、摘要位置和原件回读触发条件。
- 附件的必要/辅助/重复分类、必要证据缺口，以及仓库规则与通用流程差异。
- 人工核验轮次清单指针：轮次 ID、基线、问题/阶段数、证据数、访问状态、`default_read`、结案摘要、迁移表、原件回读触发条件、敏感性/存储稳定性汇总、清理候选状态和下次审查触发点。中央索引每轮只登记一条清单指针，不逐张复制附件条目。
- 通过净收益门禁时的当前视觉观察任务/逻辑 ID、绑定人工轮次、视觉测试包与结果卡位置、唯一允许写入的证据记录、权限边界、状态和失效条件。中央索引只保存一条观察任务和一张结果卡指针，不复制图片、观察任务聊天或逐图条目；观察任务不得自行写中央索引。
- 当前进度视图位置、最后核验截点、健康状态和最近一次压缩记录；压缩记录只保存移出内容的去向与校验结果，不复制正文。
- 当前进度视图同时作为项目恢复热快照时，记录快照版本、总指挥世代、写入/回读时间、事实截点、控制面交接置信度、切换状态、运行验收、专业验收、任务运行容器、中断信号、活动/暂停队列摘要、当前断点、下一动作、结果未知项、不可继承授权和冷证据入口；旧字段名“灾难恢复热快照”继续识别，索引只存指针与短摘要，不复制快照正文。

## 3. 仍需人工提供的内容

只有 AI 无法可靠读取或不能替人决定的内容保留 `【】`：

- 当前使用者本人和本轮协作成员的 GitHub 账号；
- 当前一张或多张本轮协作成员身份卡；
- 本轮目标或目标功能模块；
- AI 无权访问的私聊、会议新增交办或业务背景；
- 无法从代码、平台或项目规则判断的业务取舍、专业验收和目标变更；
- 只能由使用者本人提供的实际观察、业务接受、风险接受、隐私决定或正式签认；无法判断时允许明确记录为“未执行”或“不确定”，不得要求猜测；
- 无法从团队责任记录判断的一个或多个 Issue 负责人、候选负责人和代码 PR 审阅人选择；未指定时允许形成局部门禁，不要求为继续其他阶段而猜测；
- 远端写操作、费用、生产、权限或不可逆动作所需的最终人工确认。

历史身份只用于查找候选和冲突检查，不得静默填充当前身份。历史授权只用于审计，不得自动继承到新 Goal、目标变化后的对象或新协作轮次。

## 4. 最小索引格式

中央动态文档采用机器可识别的唯一当前块：`<!-- CURRENT:BEGIN -->` 与 `<!-- CURRENT:END -->` 必须成对、只出现一组且位于正文首部；历史只允许追加在其后的唯一 `<!-- HISTORY:BEGIN -->` 之后。`CURRENT:END` 与 `HISTORY:BEGIN` 之间只能有空白或注释，不得保留旧 CURRENT 正文。历史区的旧标题不参与当前检索，新写入历史标题不得使用“当前”“唯一有效”“唯一写者”等当前语义词。缺少标记、出现重复/空 current 块、区域次序错误、current 与封条来源摘要不一致或历史文本越过分界线时，校验结果为 `BLOCKED`，不得按最近出现的标题猜测；全文哈希通过也不能覆盖结构错误。旧文件迁移只读识别，不批量改写原文。

交接封条实例必须符合 `templates/HANDOFF_STATE.schema.json`，并由 `.github/scripts/HandoffSeal.mjs` 校验。作为封条来源的索引只预先保存 `seal_directory_ref`、`schema_version`、`generation`、`writer_id` 和 `event_id`；`seal_sequence`、`previous_seal_digest`、`seal_digest`、`source_digest_status`、`candidate_verification_status`、`handoff_phase`、`transition_intent_digest`、`latest_source_status`、`transition_status`、`historical_assurance`、`chain_status` 和最后回读时间从该目录的已验证封条派生，放在仓库外便携快照或对话回执中，不回写被封条哈希覆盖的源文件。新写入使用 schema v3：事件 ID 全链唯一，时间跨序号单调，轮换准备时间必须位于前序与接管封条之间，`CURRENT_ATTESTATION` 至少一项来源摘要变化。候选封条为 `MATERIAL_PREPARED`，正式新世代封条为 `TAKEOVER_COMPLETED` 并消费事前生成的轮换意图；同一 generation/writer 更新 current 后使用 `CURRENT_ATTESTATION`，只追加新来源证明，不携带 transition/migration，也不改变中央单写者。v1/v2 历史只读保留并标 `LEGACY_UNVERIFIED`，1C 早期必须先生成绑定旧链最后摘要的 v3 迁移候选，不得在最终附件阶段才发现迁移。默认只对最新封条回算来源，`--history-only` 的 `latest_source_status=NOT_CHECKED` 不可作为 READY/COMPLETED 依据。来源可声明 `root_ref=source_root`（默认）或 `root_ref=external_control_plane`；后者必须由受控配置提供外部根目录，并核对路径边界、项目绑定、摘要和事实截点，不得因此修改外部源码。正式附件由 `.github/scripts/Prepare-Handoff.mjs` 在规则 manifest、CURRENT/HISTORY 结构、Unicode 路径、来源与封条二次回算均通过后原子生成；交付回执保存在封条来源之外。工作区未提交/未跟踪项只登记保护摘要和必要文件指针，不默认进入来源 inventory。没有 schema/序号/前序摘要的旧 Markdown 只能登记为 `legacy=CONTROL_UNKNOWN`，不可直接获得控制面 HIGH；首次迁移只从唯一 current 建立序号 1 的 `CURRENT_MIGRATION` 新链，并绑定旧链最后摘要、世代与写者，原件保留在 HISTORY，不补造旧链或轮换意图。正式状态值只允许 `READY / READY_WITH_RESTRICTIONS / BLOCKED / COMPLETED`。

## 5. 自动检索与回退

### 5.0 空白任务的项目启用与动态身份判定

3. 当前总指挥任务、世代、唯一写者、租约、断点和通信对象只从动态状态读取。任务标题、平台任务 ID、旧交接摘要、旧授权和聊天历史不能作为当前身份；状态回读成功也不等于获得通信或产品写入授权。

5. 启用声明、00/09/10、状态 schema 或规则指纹发生变化时，上一轮启动判断立即失效；下一项依赖工作流的实质动作前重新读取并登记 `RULE-REFRESH`。交接只更新动态状态和历史，不改固定入口来记录当前任务。

6. 同任务复用先比较路径、大小、修改时间，变化、元数据不可靠或安全边界较高时计算 SHA-256。指纹一致、本任务加载记录完整且关键执行语义仍可用时，才跳过同级读取。实际观察到压缩或恢复后，下一项实质动作前回读既有短状态及该动作关键章节；只有旧指纹不能证明语义已恢复。阶段/范围变化、异常和交付前同样核对受影响条件，不逐工具全文重读。
7. 同名文件、聊天中再次出现的同一附件名或 Prompt Cache 命中都不能代替指纹核验。重新上传的附件可能再次进入输入，因此本地路径可访问时优先直接读取，不要求重复上传。

规则刷新按事件触发，不按固定分钟、消息数或工具调用启动后台轮询。以下节点到达后，在下一项依赖规则的实质动作前刷新：新任务或角色首次执行；收到操作者或已获准维护者提供的新版规则路径；实际观察到上下文压缩、恢复或交接；任务契约、场景、范围、风险或授权发生变化；长任务一个独立批次结束且下一批将采用不同对象或动作；首次本地 Commit、远端写入、不可逆或其他高影响动作；阶段结论和最终汇报。相邻节点适用规则、指纹和执行语义均未变化时可合并一次回执，不能用合并跳过新出现的风险或权限边界。

跨项目规则加载只核对规则根：读取 `规则刷新manifest.json`，按其完整读取必需文件，验证版本、哈希和读取期间来源稳定性。自洽即返回 `COMPLETED + PASS`；路径不可访问、文件缺失/不一致、来源漂移或更高优先级冲突时返回 `COMPLETED + FAIL`。项目状态、身份、写者、CURRENT、配置迁移、耐久登记、交接或封条问题与加载结果正交，不得产生 `WARN/BLOCKED`；需要处理时另立项目待办。接收方无需为规则加载修改项目文件，发送方按批次记录目标、版本、manifest 和结果。加载成功不能直接控制模型未来注意力，也不能替代具体动作前的事实、权限、验证和最终输出核对。

索引是导航，不是事实豁免。指纹证明内容身份，不证明理解或执行。动作前核对相关事实和权限；输出按 03 核验。静态检查及合成样例不能证明真实长任务遵从，宿主强制能力必须有独立实现和运行证据，不由规则文字产生。

## 6. 更新时机与安全

- Goal、轮次、任务或批量卡创建时立即登记逻辑 ID；
- 第二代规则根目录首次确认、启动配置、规则文件或按需执行手册新增/删除/改名/指纹变化、当前任务首次加载适用规则/手册或发生轻量交接异常回退时，局部更新正式规则与支持文档的分区注册及加载记录；
- 调度重建说明新增、版本/入口/周期/时区/绑定/指纹变化，或现有任务与说明的存在性、可达性、重复性、状态判定发生变化时，局部更新说明指针、适用范围和失效条件；说明缺失或漂移只暂停依赖调度恢复的对象。

- 目标候选、入口、profile/feature flag/环境覆盖、依赖、模型/资产、缓存、服务进程、部署路线或页面可见版本变化时，局部更新运行身份和并存实现决议；受影响的人工反馈与发布结论按失效条件重新判定；

- 对象发生实质判断、决策理由补录或失效条件命中时，局部更新对象到可迁移决策回执的映射；
- 出现持久状态变化、平台回执、任务中断、目标变化、暂停、交接、主线换窗或归档准备时局部更新；平台明确显示额度预警、使用者报告额度不足或额度耗尽时，只记录可观察信号并按 `05` 在安全原子边界收口，不估算不可见余额；

- 长任务、无人值守批次或多批次队列开始前，登记热快照的目标、基线、批次顺序、首个动作和禁止项；恢复意义发生变化或每个独立批次结束时，先完成原子实现/验证步骤，再在稳定截点一次性更新并回读热快照和索引指针。无持久状态变化的问答、文件保存、命令级进度和重复只读操作不更新；不得按固定分钟、消息数或工具调用高频写入，也不得同步维护任务标题、事件收件箱、Heartbeat 和多份同义视图；
- 空白账号接管开始时登记 `RECOVERY` 记录并保持只读；事实抽查通过、热快照回读完成且新总指挥世代已写入后，才把接管标记为可靠。旧授权、旧运行状态和旧任务规则加载记录不迁入新世代；
- 例外专项任务在其负责路径更新恢复记录后，直接把路径、断点和状态增量回传总指挥，由总指挥登记中央索引；专项 AI 不直接改当前总指挥、热快照或其他专项条目，使用者无需转发；
- 当前进度视图完成实质压缩、便携交接快照生成或临时 AI 返回状态增量时，登记对应记录和证据位置；
- 人工核验轮次结束、下一轮创建、问题迁移表/结案摘要/清理清单写入或清理回执变化时，局部更新轮次指针；清理未完成时不得覆盖上一可靠轮次摘要；
- 视觉隔离通过净收益门禁后，在测试包生成、观察任务建立、结果卡完成/冲突/失效或轮次关闭时，由总指挥局部更新观察任务与结果卡指针；观察任务只更新其唯一指定记录并回传，不直接改中央索引；
- 人工核验轮次关闭时将其清单设为 `closed/cold` 和 `default_read=false`，登记下一轮指针；每累计 3 个关闭轮次或距上次审查 30 天时只生成清理候选审查记录，不自动删除；
- 人工原始材料删除前后分别登记清单版本、来源指纹、文件计数、字节数、保留例外、执行回执和失败路径；索引只保存摘要与回查位置，不复制原件内容；
- 首次完成高成本材料分析或其来源指纹、适用基线、关键结论发生变化时，登记或局部更新对应 `EVIDENCE-` 记录；
- 结束核账通过后才把记录标记为可靠截点；
- 工作流相关对话在本轮未立即实施工作流修改时，必须在结束前按[相关文档定位索引](../相关文档定位索引.md)把结论写入唯一主记录并回读；这条记录要求只保存最小结论、行动方、证据入口和失效条件，不复制聊天，也不替代项目事实源；
- 增量轮的结束核账是该轮内置收尾，不另建每日核账记录；只保存核账模式、四类差集结论、升级原因和下一可靠截点。核账未通过时保留旧可靠截点，并把本轮标记为待修复或已转全量，不能用未核账完成的时间点覆盖旧基准；
- 写入失败时保留当前任务事实并重试一次；仍失败则标记索引待修复，但不得伪称已经记录；
- 热快照写入后必须回读版本/世代、事实截点、活动目标、队列顺序、当前断点、下一动作和证据入口；回读失败时保留上一可靠索引截点，不得把新快照登记为可靠；
- 不记录密码、Token、Cookie、密钥、完整敏感日志或无关个人信息；
- 不因索引中存在旧授权而执行远端写操作；远端写入仍按本轮授权卡和当前团队规则执行。

为节省 Token，日常只读取“当前指针”、当前人工核验轮次清单、匹配的少量历史行和相关 `EVIDENCE-` 摘要指针；已关闭轮次保持 `default_read=false`。只有发生冲突、回归、审计、恢复失败、摘要不足或摘要规定的原件回读条件时才展开详细记录或原始材料。

控制面重复入口登记：保留旧 `AI状态索引.md` 原件时，不得直接删除或改写其 `CURRENT` 证据；由当前索引指向一份被封条覆盖的登记文件，逐项记录历史路径、`HISTORICAL_ONLY` 状态、精确 SHA-256 和裁定理由。生成器只放行登记且摘要匹配的历史入口；未登记、路径变化或内容漂移继续 `BLOCKED`。登记放行不代表旧写者已停止，也不提升控制面置信度或切换权限。
