# 总指挥工作流规则刷新包

规则广播只做一件事：让接收方完整读取并采用指定规则根中已保存、读取期间稳定的本地规则。普通刷新默认使用本地正文模式，不是项目体检、项目接入、身份重建或交接；但刷新成功后允许在权限和路径均已核验时，同步项目登记中独立的“规则采用记录”，项目问题另列待办。广播可以由总指挥按全量或指定范围分发，但每个接收方仍必须独立读取。

**规则来源选择门禁：**“最新本地规则”不能从项目登记中的历史绝对路径或旧 `rule_version` 推断。接收方按以下顺序选择来源：本条指令明确给出的规则根 > 当前项目启用声明可解析的 `root_ref` > 当前窗口已核验且仍有效的权威来源绑定 > 当前工作区中可核验的规则仓库入口。来源绑定必须可回源到操作者明确指定或已核验委派中的规则根，属于同一接收窗口，未被撤销、替换或更高优先级入口否定，并重新捕获当前 `live_rule_epoch`；只有项目历史路径、旧摘要或其他窗口的声明不算绑定。公共版本更新不自动撤销根绑定，但不免除新正文读取和稳定性核验；来源不变且依据仍有效时，不要求操作者重复确认路径。项目登记只表示采用记录，不是公共规则源；来源根无法定位、只能定位到旧世代或缺少当前 `live_rule_epoch` 证据时，必须报告 `RULE_SOURCE_LOCATOR=SOURCE_NOT_LOCATED/STALE_SOURCE_UNCONFIRMED` 和 `INPUT_REQUIRED`，不得把旧清单自洽写成“最新”或 `RULE_REFRESH=PASS`。这一门禁只暂停规则刷新及其依赖动作，不把项目登记缺失扩大成全项目阻断。

## 普通本地刷新与精确版本核验

**普通本地刷新（默认）：**当前操作者指定的规则根中，已保存的实际正文是本次加载来源。manifest 用于文件范围、路径与版本导航；旧预期指纹或版本标签待同步，不单独否决普通刷新。接收方仍核对清单结构、必要文件、路径安全及实际读取期间的稳定性，不混读变化中的内容，不以部分正文宣称完成。

**精确版本核验：**操作者明确要求指定版本/摘要、所有目标采用同一内容，或正在进行正式交接、封条验证、发布验收时，必须严格核对 manifest 版本与全部预期指纹。哈希不一致即失败，不自动降为本地正文模式。正式交接继续使用既有生成器与封条协议，本文件不放宽该门禁。

指定版本时还须比对操作者要求的版本，不能仅以当前清单自洽判定命中目标。要求全体同一内容时，由发送方提供唯一共同摘要，各接收方用它核验；缺少共同摘要时先取得该输入，不得以各自现场生成的摘要替代。`--mode pinned` 仅核验当前清单自洽，共同摘要须另外传入 `--expected`；脚本不替操作者判断目标版本。

**维护者收尾：**规则修改批次仍须最后同步版本、manifest 与质量检查，不能宣布未完成批次正式发布。普通刷新不要求冻结到全部回执收齐，各接收方按自己的读取截点核验。精确版本广播必须冻结同一来源；发生变化立即取消本批，重建新批次，不能把旧成功回执算作新版本成功。

**规则更新与进行中流程：**规则版本变化不能让正在进行的低风险接入或交接凭空失去断点。0A 在读取开始和结束各捕获一次 `rule_baseline`（规则根、版本、manifest 摘要、捕获时间）；两次不同则丢弃本次读取投影并自动重读一次。1C/1D/1E/1F 在进入阶段时锁定同一 `rule_baseline`；期间发现新版本时，不要求操作者选择版本，也不继续沿用旧 `READY`，而是自动建立 `RULE_REBASE_PENDING`，只重读受影响规则和当前阶段依赖，回读通过后把旧候选标为 `SUPERSEDED_BY_RULE_REBASE` 并沿原断点生成新的候选截点。只有新规则来源无法核验、重基线失败，或新规则明确改变身份/权限/安全边界时，才阻断受影响阶段；原项目业务、工作区和未依赖该规则的低风险只读核对不因此全局停止。

**未保存文档：**文件工具读取的是磁盘已保存内容，编辑器未保存缓冲不属于生效规则。已知某条必须使用的规则仍未保存或互相矛盾时，只暂停依赖该内容的动作；工具无法观察缓冲时，不要求操作者证明“没有未保存文档”，也不能宣称已检查所有编辑器或自动保存。Commit、Push 和暂存不是采用本地规则的前提。

## 操作者唯一需要发送的内容

```text
这是操作者下达的规则更新指令。请完整读取并采用以下路径中已保存的最新本地总指挥工作流：
<第二代总指挥工作模式路径>

本次是普通本地刷新，清单旧指纹只作维护提示，不因此拒绝采用已保存且读取期间稳定的正文；不是指定版本验收或正式交接。只核验规则来源，不因项目身份、CURRENT、写者、旧候选或配置问题拒绝加载。成功后可在已核验的项目登记路径中只更新规则采用记录（规则版本、manifest 摘要、刷新时间和结果）；不得修改总指挥、唯一写者、CURRENT、交接封条、产品配置或远端。没有明确可写路径或权限时只报告 `RULE_ADOPTION=PASS`、`PROJECT_REGISTRATION=SYNC_PENDING`，不要猜路径或扩大写入。
```

### manifest 路径基准（必须一致）

manifest 的 `path_base` 是 `rule_root`，但仓库根脚本是受管规则的一部分。解析 `path_ref` 时必须按以下固定规则执行：

- 以 `.github/` 开头的条目，以及 `repository_root_prefixes` 声明的其他仓库根前缀（当前还包括 `引用的外部工具/`），按“规则根向上两级得到的仓库根”解析；仓库根依据 `repository_root_ref` 定位；
- 其他条目按规则根解析；
- 不得把仓库根条目复制到规则目录，也不得把规则目录文件按仓库根解析；
- 规则根向上两级无法定位仓库根，或按上述规则仍找不到文件时，才报告对应文件无法读取。

这条路径规则属于规则加载契约的一部分，不是操作者需要填写的参数。接收方必须逐条记录解析后的根（规则根或仓库根）和目标；只有解析后的目标不存在，才能记为 `MISSING`。禁止把仓库根条目直接拼到规则根后再报告缺失。

操作者直接发送“规则更新指令 + 第二代规则路径”即构成完整的规则加载输入，不需要手工填写 `RULE_REFRESH_ID`、旧版本、manifest 摘要、变化清单、写入范围或项目状态。需要跨任务追踪时，这些字段由发送方在自己的批次记录中自动生成，不转嫁给操作者。

## 广播范围与强制接收语义

0A只作用于直接接收操作者指令的对话，无论其身份，不联系或替其他对话更新。0B只由已核验的本项目现任总指挥执行，向当前项目全部或指定子任务转达；指定范围可以只有一个专项。接收方不是总指挥或身份无法确认时停止转达，不自动升级身份；该缺口不否决接收方已完成的普通规则刷新。旧批量接入分支仅兼容定位，实际转达统一归0B。

总指挥批量广播时，使用 `broadcast_scope` 表示范围：`ALL` 代表当前项目动态任务清单中全部可核验子任务，`SELECTED` 代表指定任务。指定对象必须通过唯一任务 ID 确认；名称不唯一、任务已归档或无法从当前清单核验时，暂停该目标并记录 `NOT_REACHABLE` 或 `UNKNOWN`，不得猜测。每个目标至少记录 `NOT_SENT`、`SENT_PENDING_ACK`、`UPDATED`、`FAIL` 或 `NOT_REACHABLE`。同一宿主或账号默认串行发送，一次只保持一个规则刷新请求；收到最终非空回执后再处理下一个目标。

批量刷新遇到 `429`、`Too Many Requests`、连续重连失败或目标输出为空时，立即停止新增发送和盲目重试，保留已发送目标及其状态，记录 `RATE_LIMITED` 或 `OUTPUT_UNVERIFIED`，先回读平台状态并等待冷却或操作者指定的恢复动作。不得把“重试次数耗尽”写成规则来源损坏，也不得用同一消息重复造成双写。

“强制接收”只表示协议义务：消息实际到达后，接收方必须识别、完整读取、按自身权限处理并回执，不能静默忽略或只回复“已收到”。它不等于平台保证送达，也不等于未来每一步都服从，更不能把总指挥的中央写权、远端写权或产品修改权转给接收方。普通广播逐目标保存实际内容摘要；不同截点分别成功，不等于所有窗口采用同一固定内容。需要全体一致时改用精确版本核验。


## 接收方固定动作

1. 识别本次为普通本地刷新还是精确版本核验；后者不能因校验失败自动降级。
2. 打开 `规则刷新manifest.json`，核验非空范围、必需入口、路径与结构。拒绝绝对路径、越界、重复项、符号链接/junction 和缺失文件；旧预期指纹的放宽不放宽这些检查。
3. 捕获实际文件字节及摘要。完整读取与摘要绑定的同一份正文，结束时重核全部实际文件和清单。正文没有完整呈现或截断时补读，不使用其他窗口的已读声明。
4. 读取期间稳定、内容无冲突时采用。普通模式下清单旧指纹仅记录 `MANIFEST_STALE`；成功后先形成 `RULE_ADOPTION=PASS`。若项目登记已提供专用规则采用字段、当前窗口具备该字段的本地写权限且不存在身份/写者冲突，可原子更新规则版本、manifest 摘要、刷新时间和结果，回读后报告 `PROJECT_REGISTRATION=SYNCED`；否则报告 `PROJECT_REGISTRATION=SYNC_PENDING` 及行动方。不得把规则版本同步扩大为身份、唯一写者、CURRENT、交接封条或产品配置迁移。完整证据放在既有加载记录，不要求新建账本。
规则来源故障仅指规则根本身的可验证故障：路径不可访问、必需文件缺失、哈希不一致或更高优先级规则冲突。真实停止条件导致正文未完整读取时，本轮刷新也可返回 FAIL，但必须注明停止原因，不得写成规则来源故障。项目接入、身份、写者、CURRENT、交接和封条状态的缺口不否定纯规则加载；只限制依赖这些状态的动作。

5. 发生实际来源漂移时最多自动重读一次，取消本次全部已读投影，再从新基线完整读取；第二次仍变则保留上一有效规则并说明“规则仍在编辑，保存稳定后重读”，不反复追逐。进行中交接发现版本变化时，按本节规则建立 `RULE_REBASE_PENDING`，不得让操作者在多个版本中人工择一。最终回执只使用 `状态：COMPLETED` 加 `result：PASS` 或 `result：FAIL`；`COMPLETED` 只表示本次刷新处理已收口，不表示规则加载成功。

完整读取必须把必要正文实际呈现给当前模型；过长时按文件和同一捕获基线分段，并在既有加载记录中登记 `text_reading=COMPLETE/INCOMPLETE`、分段范围、下一位置和终点复核。阅读器或工具对单次输出的截断只表示本段需要继续读取，不等于来源损坏；未补读的正文才是“正文未完整读取”。脚本遍历、字节统计、哈希通过或别的 AI 已读均不能替代正文理解。正文没有读完时不得返回加载成功，也不能仅因正文长、一次输出截断或尚有剩余就主动收口失败；缩小分段后继续，直到读完或命中有证据的停止条件。操作者额度停止、权限不足、必需文件不可读或重复漂移等条件仍按原门处理，不以刷新命令自动解除；停止时保留原有效规则及精确续读入口。任一必需条目核验失败（普通模式单纯旧预期指纹除外）时，不得以“其余文件已读”宣称刷新完成或部分采用本批新规则；保留原有效版本。

同一窗口已有完整正文阅读记录且能重新核对来源、全部实际文件与当次阅读的字节指纹一致时，可复用实际已读正文，记录复用依据并做本轮终点复核；变化文件必须完整补读。只有哈希、旧成功声明、其他窗口已读或不完整的范围记录不能替代阅读。续接部分阅读时先复核同一快照，只有实际呈现且连续覆盖的范围可计入；被截断的输出从最后可证位置重读，无法定位则重读该段。来源变化按原漂移门丢弃投影，不把旧下一位置套到新正文。新增段的位置采用脚本声明的单位，不混用字节、UTF-16索引和Unicode代码点。

### AI 只读检查入口

在工作流仓库运行 `.github/scripts/Inspect-RuleRefresh.mjs`。默认 `local` 只读捕获当前实际摘要；精确核验用 `--mode pinned`，失败不回退。`--rule-root` 接受当次指定目录，省略时从脚本位置定位，不依赖当前工作目录。脚本不回写规则、清单、缓存或项目状态。

先取得 `snapshot_sha256`；按清单逐文件使用 `--expected <本次摘要> --file <path_ref>` 向模型呈现同一基线的正文。正文较长时加 `--offset 0 --length 2000`，每次完整阅读后按输出的 `next_offset` 继续，直到覆盖 `total`；长度按实际工具输出限制缩小，不能把工具已发出的范围直接当作模型已读。位置从零开始，以Unicode代码点计，中文和表情不会被拆成半个字符；原整文件入口仍可使用。结束再运行 `--expected <本次摘要>`。每次输出的正文和指纹来自同一份捕获字节，避免中途修改后恢复却把另一份正文当作已读。结果中的 `text_reading=NOT_ATTESTED` 表示脚本不能替模型声称已阅读，`editor_buffers=NOT_OBSERVED` 表示未检查编辑器缓冲。脚本失败输出不作成功回执。

外部工具目录与统一自动对接规范也是必需条目。接收方须实际读取，建立从工具名称到正式入口的路由；共享安装状态、选定工具配置和角色正文在调用时按需核验，不因广播自动安装或激活。

当前项目没有启用声明、动态状态冲突、唯一写者不明、缺少项目写入授权、无法写入规则采用记录、旧候选或封条异常，均不属于规则加载失败。这些事项不得触发 `WARN/BLOCKED`，不得要求操作者先修复；如确实影响后续项目动作，只能在“项目后续待办”中用一句话另列。最终回执应将 `RULE_REFRESH`、`RULE_ADOPTION_RECORD`、`PROJECT_ENROLLMENT` 和 `IDENTITY_CONTROL_PLANE` 分开记录；规则采用记录为 `SYNC_PENDING` 不改写规则刷新结果，但正式交接前必须由项目唯一写者处理或明确保留待办。

## 权限边界

规则加载不产生总指挥、唯一写者、CURRENT、交接封条、产品配置、任务创建、通信、远端、部署、费用或高资源授权。仅当项目已提供专用规则采用字段、写入路径和当前窗口的本地写权限时，接收方才可同步该最小记录；找不到路径或权限不足时保持 `SYNC_PENDING`。操作者另行要求项目接入或迁移时，才使用 `项目配置迁移清单.md`。

## 最小回执

接收方按 `规则刷新接收回执模板.md` 回复。正常成功不输出逐文件哈希、项目控制面审计或迁移清单；完整证据仅在发送方批次记录或故障排查时按需展开。
