# 总指挥交接阶段矩阵

本文件是交接阶段的唯一简明判定表。其他规则文件可以解释细节，但不得重新定义下面的逻辑阶段含义。机器封条字段 `handoff_phase` 仍只使用 schema v3 的 `MATERIAL_PREPARED / TAKEOVER_COMPLETED / CURRENT_MIGRATION / CURRENT_ATTESTATION`。交接事实只保留一份规范机器记录；摘要和阶段状态引用它，不重复建立事实源。

| 阶段 | 负责方 | 进入条件 | 成功状态 | 旧总指挥要求 | 候选任务 ID | 允许动作 |
|---|---|---|---|---|---|---|
| 材料准备 | 当前总指挥 | CURRENT、工作区和来源可核对 | 逻辑阶段 `MATERIAL_PREPARING`；封条 `MATERIAL_PREPARED`；`READY` 或 `READY_WITH_RESTRICTIONS` | 仍可为唯一写者；不要求已停止 | 不需要 | 生成并验证一份规范机器记录及其短摘要；漂移时废弃并递增重生成 |
| 发送 | 操作者/获准发送方 | 正式附件和标准 1D 提示词已就绪 | 发送动作已执行 | 仍可运行 | 不需要预先知道 | 把主附件交给空白候选任务 |
| 接收核验 | 新候选 | 已取得主附件和必要引用 | 候选返回实际任务 ID及结构化核验结果 | 仍可运行 | 接收成功后登记 | 只读核对材料、项目、角色、断点和规则版本 |
| 正式切换 | 操作者/新候选 | 候选核验通过；旧写者停止或归档已由操作者确认 | `TAKEOVER_COMPLETED`；`COMPLETED` | 必须停止调度 | 已有 | 更新唯一 CURRENT、登记新写者并回读 |

## 状态输出格式

每次汇报必须分开写四行：

1. **逻辑交接阶段**：`MATERIAL_PREPARING / SENT / RECEIVED_VERIFIED / TAKEOVER_COMPLETED`。
2. **封条阶段**：`MATERIAL_PREPARED / TAKEOVER_COMPLETED / CURRENT_MIGRATION / CURRENT_ATTESTATION`。
3. **附件交付状态**：`NOT_STARTED / DRAFT / GENERATED_NOT_DELIVERED / DELIVERED`。
   `GENERATED_NOT_DELIVERED` 是旧总指挥生成主附件后的正常状态；它不要求发送方生成机器回执。候选收到当前消息中的主附件即可登记 `DELIVERED`，缺少独立 receipt 不降低评分，也不阻断正式切换。
4. **候选核验状态**：`NOT_RUN / PASS / PASS_WITH_RESTRICTIONS / FAIL`。
5. **真实阻断与操作者下一步**：分别写明当前阶段的事实缺口、责任方和最小动作。
6. **正式切换状态**：`未开始 / 候选已核验待切换 / 已完成 / BLOCKED`。

“尚不可切换”只能描述第六行，不能覆盖前面五行，也不能把运行验收、专业验收或旧写者尚未停止自动写成材料准备失败。

### 平台 Goal 的附加闸门

如果当前任务运行容器是平台 Goal，以上逻辑阶段还必须记录两项运行时状态：`Goal 平台状态：NOT_APPLICABLE / ACTIVE / PAUSE_REQUIRED / PAUSED / UNKNOWN / CLEARED`；`Goal 交接权限：BUSINESS_ALLOWED / CLOSEOUT_ONLY / NONE`。

- 交接、换窗、存档或终止请求出现后，先把权限降为 `CLOSEOUT_ONLY`，并要求操作者完成平台 Pause；平台仍为 `ACTIVE` 或状态为 `UNKNOWN` 时，不得开始收口业务，也不得生成“可继续”的交接结论。
- 交接、换窗、存档或终止请求出现后，先把权限降为 `CLOSEOUT_ONLY`，并要求操作者完成平台 Pause；平台仍为 `ACTIVE` 或状态为 `UNKNOWN` 时，不得开始收口业务，也不得生成“可继续”的交接结论。此时逻辑阶段最多记录为 `MATERIAL_PREPARING` 或 `PAUSE_REQUIRED`，不得把正式 `READY / READY_WITH_RESTRICTIONS` 当作合格结果。
- 只有平台明确为 `PAUSED` 后，旧 Goal 才能完成已经开始且可安全收口的原子步骤；交接材料生成并回读成功后，权限必须改为 `NONE`。旧 Goal 不得继续测试、修改、分析或启动新批次。
- 新窗口读取交接材料后，只有操作者明确要求恢复时才能把权限改回 `BUSINESS_ALLOWED`；旧 Goal 的交接材料、平台完成标记或 AI 自述不能自行触发恢复。
- `MATERIAL_PREPARED`、`GENERATED_NOT_DELIVERED` 和 `READY_WITH_RESTRICTIONS` 只描述材料或控制面阶段，不能覆盖上述平台状态；缺失平台状态时保留 `PAUSE_REQUIRED/UNKNOWN`，不得猜测为已暂停。

## 分支与空白任务

- 分支任务同时记录 `parent_task_id`、`current_task_id`、分支来源和授权继承范围。两个 ID 不同本身不是冲突。
- 空白候选任务的任务 ID 在接收成功后才产生；发送前不得把“未知候选 ID”列为阻断。
- 候选接收材料不会自动授予中央写权、产品写权或远端授权。

## 失效规则

CURRENT、工作区、远端基线、来源指纹、父子任务关系或唯一写者发生变化时，只使受影响阶段的材料失效；不得把局部失效扩大成所有阶段永久阻断。重新准备材料时保留旧附件和封条为历史，生成新的递增候选。
