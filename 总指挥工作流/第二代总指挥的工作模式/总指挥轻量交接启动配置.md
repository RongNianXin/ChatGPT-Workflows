# 总指挥轻量交接启动配置

版本：2026-10-06.39

用途：作为 `01-操作者操作手册.md`“场景 1D：新总指挥接手身份”的唯一轻量启动配置。它只覆盖“新总指挥候选”的第一次只读核验和最终切换前复核，不授权产品实现、远端写入、删除、费用、部署或新调度。

本配置具有独立的加载价值，但不是新的编号规则。`04-状态、目标变更与交接规范.md` 负责交接契约，`10-自动状态索引规范.md` 负责指纹和加载记录；本配置负责把候选阶段必须立即生效的规则收敛成最小完整集合。系统/平台限制、当前团队与仓库规则始终优先。交接只维护一份规范机器记录；人类摘要、状态索引和进度视图只引用或聚合它们各自负责的事实，不建立第二套交接事实。

跨项目经验库是可选按需来源，不是本配置的固定全文来源。交接只记录其路径、索引修订、可用性和当前匹配条目；新总指挥接管后，若当前任务依赖某条经验，必须按 `10` 重新核验并建立本任务加载记录，不继承旧任务“已读”。

## 1. 适用与加载门禁

1. 只适用于：旧总指挥仍可确认、已有稳定正式快照、操作者明确指定“新总指挥候选”的场景 1D 正常交接。场景 1G 是角色中立的任务中断恢复入口，不加载本配置；它先恢复原窗口身份，普通或专项任务只读取自身适用规则，只有确认属于无正式总指挥交接时才按 02、04、09、10 的对应章节恢复中央控制面。快照不可靠或无法确认单写者时不得套用轻量候选路径。
2. 新候选必须自行完整读取本配置，并建立本任务独立加载记录；不得继承旧任务的“已读”声明。加载记录至少包含配置路径、版本、大小、修改时间、SHA-256、来源规则清单比对结果和加载时间。
3. 快照必须记录本配置的相对路径、版本、SHA-256，以及交接时 02、04、07、09、10 的路径和 SHA-256。候选重新计算并比对；全部一致时，候选阶段不再全文读取这五份编号规则。
4. 加载与异常回退以 10“自动检索与回退”为主来源：单文件变化可可靠定位时完整读取受影响标题，否则读取该文件全文；配置缺失/不一致、根目录冲突、来源不完整或整体影响无法限定时保持只读并完整回退。旧任务记录、同名附件和 Prompt Cache 不代替本任务加载。交接附件若仍以旧规则版本为基线，只能登记 `RULE_REBASE_PENDING` 并重新核验当前权威规则根；不能直接作为正式接管依据。
5. 旧格式快照没有本配置字段或机器可读封条时，不自动享受轻量路径，也不得直接评为控制面 HIGH。候选先登记 `legacy=CONTROL_UNKNOWN` 并回退完整加载；只有从唯一 current 来源完成一次只读迁移、生成并验证新封条后，才能进入轻量链。旧原件保留在 HISTORY，新旧 current 不得混用。
6. 候选收到的主附件必须是 `final-*` 正式候选附件，并由 `.github/scripts/Prepare-Handoff.mjs` 原子生成，绑定实时验证通过的 schema v3 `MATERIAL_PREPARED` 封条和 `READY / READY_WITH_RESTRICTIONS`。`draft-*`、`switch_status=BLOCKED`、主附件缺失，或附件引用的封条/事实截点不一致时，才报告材料未正式就绪；机器 receipt 是否存在不影响评分，也不进入评分或可切换判断，候选以当前消息实际收到主附件作为送达事实。旧 v1/v2 链只读标为 `LEGACY_UNVERIFIED`，不能被新版规则追溯证明为严格时序有效。
7. 场景 1C 在生成候选前先做只读可行性预检。代码事实使用 `source_root`；中央控制面可声明 `root_ref=external_control_plane`，但必须有受控外部根目录、项目绑定、指纹和事实截点。未提交/未跟踪内容先登记保护摘要，只有接续必需文件才进入封条来源。配置 `preflight_only=true` 时只返回预检结果，不创建封条或正式附件；预检通过仍不等于已切换总指挥。
7. 正式切换后，执行任何未由本配置完整定义的动作前，按实际场景加载所需编号规则和当前团队/仓库规则。指纹一致只允许避免候选阶段的固定全文读取，不构成后续动作授权。
8. 正式履职后的首次实质汇报前，按 [02 的汇报加载入口](02-总指挥核心规则.md#三视角建议审查门禁)读取03汇报出口与06表达条款。复用10的既有加载记录，区分完整读取、标题级定点读取和仅比对指纹，记明实际范围；输出截断须补读缺失部分，不能记为完整读取。操作者明确要求全文复习时按指定范围完成，不推成每轮全文必读。候选可靠、规则已读、输出合格分别验证。

## 2. 不可压缩的硬门禁

- 候选阶段只读：不得终止旧总指挥、取得中央调度权或主执行权、修改中央状态、修改产品代码、Commit、Push、执行其他远端写入、删除证据，或启动新的全量、增量、专项调度。
- 候选核验完成前，旧总指挥保持唯一中央写入者，候选只能形成候选截点和建议状态增量。操作者停止或归档旧总指挥后进入短暂无写者窗口；候选只有在最终确认、最小复核和中央原子更新成功后才成为唯一写者。
- 正常换任的逻辑阶段按 [交接阶段矩阵](交接阶段矩阵.md) 记录为：材料准备、发送、接收核验、正式切换。候选通过后操作者停止或归档旧总指挥；操作者发送第二段确认，新候选复核并正式登记。封条 `handoff_phase` 仍使用 schema v3 的机器阶段值，不得写入 `SENT` 或 `RECEIVED_VERIFIED`。候选阶段看到旧任务仍存在或从 `active` 变为 `idle` 不单独降级；只有新增中央写入、重复调度、来源冲突或未解释漂移才重算受影响结论。
- 旧远端授权、运行中进程、完成声明、专业/人工结论和旧任务规则加载状态一律不继承；当前事实必须按最小范围回源。
- 本地操作者协作画像不属于候选阶段的事实源或授权源。候选只核对 `unasked / enabled / paused / disabled / unavailable`、一次介绍状态、最近节点维护结果、规则根级通用相对指针、schema、`profile_revision`、唯一画像写者、待合并候选数、过期、容量和 Git 排除状态，不读取或复制画像正文、独立身份资料档案的内容、摘要、存在性或指针、自然语言路由别名、来源资料、内容哈希、外发载荷或确认原文；缺失、未更新、到期或校验失败只禁用协作适配，不阻断交接，旧世代的任何画像外发确认一律失效。候选阶段不得询问是否启用；正式接管后只有同一规则根没有可靠选择记录的 `unasked` 才在首个主回复末尾介绍一次。
- 已有可靠完成凭证的任务不得重复执行。发现漂移只标记受影响范围、证据和最小补救动作。
- 候选报告“达到可切换条件”不等于已经接管。操作者必须先停止或归档旧总指挥，再明确发送最终切换确认；候选不得代替操作者终止旧任务。
- 最终确认到达后，候选先复核配置/来源指纹、中央世代与单写者、快照失效条件、工作区指纹、当前 Head/状态计数和远端基线。仍可靠时才原子更新中央入口、当前进度视图和 AI 状态索引，并立即回读；存在冲突时不得切换。
- 候选期间若公共规则版本或 manifest 发生变化，不要求操作者选择旧/新版本，也不沿用旧 `READY`。登记 `RULE_REBASE_PENDING`，自动重读受影响规则并重新锁定 `rule_baseline`；回读通过后旧候选记为 `SUPERSEDED_BY_RULE_REBASE`，沿原断点生成新候选。只有新规则来源不可核验、重基线失败或身份/权限/安全边界发生变化，才阻断正式切换。
- 总指挥世代编号不得复用。中央回读确认唯一写者前，不得宣布交接完成。
- 切换尝试结束后按本配置第 7 节的唯一模板发送独立最终回复；交接语义与权限仍以 `04-状态、目标变更与交接规范.md` 为准。候选核验不等于切换；新规则不得追溯证明旧结论。

## 3. 第一次只读的最小读取链

按顺序读取并在获得结论后停止扩展。以下是最小核验链，不要求把每个来源全文载入上下文：

1. 便携交接快照；
2. 项目规则入口与更近的团队/仓库规则；
3. 中央工作项清单及当前进度视图：先回读待实施、进行中、阻断、暂缓、待验收的非终态计数、优先级摘要、当前活跃项和阻断项；只有当前断点、下一动作或冲突涉及的工作项才展开完整字段。当前进度视图只作聚合，不替代中央清单；
4. `AI状态索引.md` 的当前指针、总指挥世代、最近交接记录和规则加载记录；协作画像只读取五态、一次介绍状态、节点维护结果与安全指针，不读取正文；
5. 当前唯一活跃任务的主执行阶段、唯一产品写者、例外专项任务及其隔离边界和完成凭证；
6. 耐久 Commit 台账的最后核账截点、当前相关 `KEY_NODE` 及原提交到当前提交的映射；
7. 当前工作区、Git/平台基线、目标候选、并存实现决议、规范启动命令及自检输出、实际运行选择器、模型/资产、运行进程和证据入口的低成本事实抽查；远端、运行和专业验收只在项目或下一步依赖时深核，否则保留聚合状态。
8. 若快照包含自动化任务，读取其中完整的非秘密重建条件；若同时引用调度重建说明，再核对其相对路径、版本、SHA-256、状态、适用范围和规范提示词入口引用。只读判断任务存在性，缺失时仅登记待授权重建候选。
9. 若当前任务有外部专业职责，核验快照中的 `external_role_binding` 私有锚点、职责集合/阶段、未完调用、原开始时间、累计消费/预算及撤销状态；候选不据此执行或继承旧已读/授权。正式续做适用动作前按04“外部专业职责的续接”和[共同对接规范第5节](../../引用的外部工具/外部工具自动对接规范.md#5-安装后的自动调用与任务续接)独立读取必要正文、核权并恢复同次，不新领次数或重跑完成部分。专项职责不因总指挥换任被撤销，路由和实际加载确认另核；不复制角色全文。

快照中的仓库内规则、模板和证据指针必须按当前仓库根目录解析相对路径。仓库克隆、移动或换盘后，旧机器绝对路径只作为已失效的实例诊断信息；候选先验证当前根目录、相对指针和指纹并完成重新绑定。能够由相对路径和指纹可靠恢复时，不得仅因盘符或父目录变化判定整个快照失效；确实无法重建的具体仓库外指针才进入最小补救。

默认禁止为了“完整”而读取以下内容：完整聊天、旧任务全文、全部 Git 状态路径、完整 worktree 清单、完整 Diff/日志、已关闭轮次原图、历史截图目录或所有附件。交接以磁盘最后保存状态为准，不要求探测编辑器未保存缓冲区。候选每次仍必须核对世代/唯一写者、目标/断点、规则基线、工作区聚合和必要授权；候选期间发现规则版本变化时自动登记 `RULE_REBASE_PENDING` 并只回读受影响部分，不能让操作者在版本之间择一；其余内容按异常或下一步依赖展开。旧总指挥生成前仍须完成一次“内容一致性回读”；候选只复核截点后的变化：

- 单写者或旧任务状态冲突：只读取旧任务当前状态和最后一条控制权声明，不读取完整对话；
- 工作区指纹或计数冲突：只列出发生变化的路径；
- 远端基线冲突：只读取受影响引用和对象；
- 证据指针缺失：只回查能判断该缺口的最少清单或附件。

## 4. 紧凑核验输出

程序/算法成果接续先按用途定位 04“成果连续性与运行复现契约”的清单，新增紧凑字段：交接情境、清单指针、规范化/序列化版本、各层状态、聚合值依据（已复算/清单推定/旧记录）、包恢复状态。同 HEAD 不能替代增量核验；跨机不比较路径/PID或整个目录原始字节。未验证与失败分开，不阻断无依赖工作。完整清单可由核验程序在明确范围内重算，默认只输出聚合与异常；不把禁止长输出误解为禁止必要采集。

既有清单口径明确、完整且稳定时可按该契约复算。口径缺失/未知、规范化变化、必要资产缺失或更换 worktree/电脑时，定点读取 04 成果契约后核验；没有足够证据时标 UNKNOWN，不能沿用旧 PASS。此条件是按需加载，不要求所有轻量交接全文重读 04。

工具和回复默认只输出以下聚合字段，不输出长清单：

```text
snapshot: ID / hash / fact_cutoff / valid
rules: root / profile_hash_match / source_hash_match / expanded_rules
writer: registered_generation / observed_old_task_state / conflict
central_work_items: pointer / last_readback / nonterminal_counts / priority_summary / recent_completed_pointer
workspace: path / branch / head / staged_count / tracked_count / untracked_count / aggregate_fingerprint
remote: repository / default_ref / head / changed_since_cutoff
runtime: expected_candidate / code_head / canonical_start_command / startup_check / selector_profile / dependency_lock / model_asset_digest / endpoint / pid / served_source / visible_version / status
control_handoff_confidence: HIGH / MEDIUM / LOW
switch_status: READY / READY_WITH_RESTRICTIONS / BLOCKED / COMPLETED
professional_acceptance_status: PASS / FAIL / NOT_RUN / UNKNOWN / NOT_APPLICABLE
handoff_seal: directory_ref / schema_version / generation / writer_id / seal_sequence / previous_seal_digest / seal_digest / source_digest_status / candidate_verification_status / handoff_phase / transition_intent_digest / latest_source_status / transition_status / event_id / observed_at / chain_status
```

## 5. 证据与清理边界

交接不是清理任务。文件存在不会自动进入模型上下文；候选不得为了节省 Token 枚举、打开或删除历史截图。关闭轮次继续登记为 `closed/cold`、`default_read=false`。清理只在项目规则规定的低频触发点形成候选清单，并作为独立任务取得删除授权后执行；没有授权时只给出清单路径和人工操作说明。

## 6. 置信度不足与可切换条件

恢复置信度分流：`control_handoff_confidence` 只评价控制面事实；`switch_status` 单独决定能否进入正式换任；`runtime_acceptance_status` 与 `professional_acceptance_status` 只限制依赖运行或专业结论的动作。控制面完整一致时可以是 `HIGH`，同时运行状态为 `UNKNOWN/NOT_RUN`；不得把未知自动写成通过。明确判定为：控制面必要证据全部通过且没有真实控制面冲突或缺口时，必须记录 `control_handoff_confidence=HIGH`；`switch_status=READY_WITH_RESTRICTIONS`、旧写者在候选阶段仍为 `IDLE/UNKNOWN`、编辑器缓冲不可观察，以及运行/专业状态为 `UNKNOWN/NOT_RUN/FAIL`，都不降低该控制面评分，只分别限制正式切换、依赖运行或专业验收的动作。只有控制面证据缺失、矛盾、漂移、单写者/世代无法确认或必要根目录不可核验时，才使用 `MEDIUM/LOW`。不得把“尚未正式切换”本身写成控制面中低分。`MEDIUM/LOW` 仍可在操作者明确选择后发起交接，但必须在 1D 主提示词后附加缺口、影响、不可继承授权和新窗口首次只读限制。LOW 或影响范围不明时不得恢复未核验高风险动作。只有不可观察的平台状态才请求操作者做最小三选一回答；不要求运行命令或查任务 ID。

人工最小化规则：候选 AI 自动读取材料、计算指纹、核对 Git/工作区/进程并整理断点。操作者只需把 01 中的标准场景 1D 主提示词复制给新候选；若 `control_handoff_confidence` 为 MEDIUM/LOW，再把 AI 生成的补充段接在主提示词后。只有平台状态确实不可见时，才向操作者询问“已停止 / 仍运行 / 未知”三选一。不得要求操作者执行命令、填写任务 ID 或手工拼装快照。

## 7. 可切换与失效条件

达到 `switch_status=READY` 或 `READY_WITH_RESTRICTIONS` 的条件必须同时满足：快照和机器可读封条有效；封条链、世代、单写者、前序摘要、事件顺序、来源摘要、目标、断点、工作区、Git 基线、耐久 Commit 台账、必要证据入口和禁止项可恢复；项目或下一步依赖远端时，远端基线也必须可核验，否则标记 `REMOTE_UNVERIFIED` 并暂停依赖远端的动作；没有第二个中央写者；所有差异已解释或限定为不影响切换的范围。本地与远端尚未同步、或本地存在未 Push 的已保存成果，默认只是交接后的待办，不单独使 `handoff_ready` 失败；只有当前断点或下一步依赖远端，且远端无法核验或存在无法解释的冲突时，才阻断受影响动作。报告必须同时给出 `chain_status`、`control_status` 和 `handoff_ready`，只有三者与 `switch_status` 一致时才可进入候选核验；`chain_status=PASS` 不能单独证明交接可用。规范启动命令、自检输出、运行身份、模型/资产、编辑器缓冲、真机和专业验收按独立状态登记；若某项是当前断点的必要依赖，只阻断受影响动作。

封条写入协议：项目实例把封条放在已被 `.gitignore` 精确排除的私有状态目录，不写入公开规则或提交。新写入统一使用 schema v3。候选封条使用 `MATERIAL_PREPARED`；准备停旧前，旧候选封条仍须对 live sources 回算为 PASS，并生成唯一 `handoff-transition` 轮换意图。正式更新 current 后，新世代 `TAKEOVER_COMPLETED` 封条消费该意图。`CURRENT_ATTESTATION` 只用于身份、授权、规则根、单写者或控制面结构等高影响变化；它必须绑定既有封条链中的来源变化，不得作为首条封条。普通进度更新使用中央 CURRENT 和状态索引的正常记录，不要求追加封条，也不撤销已经完成的接管。每条封条和意图只追加不覆盖；写入先取得同目录独占锁、校验 expected previous digest，再以同目录临时文件写入并 flush/fsync 后改名。缺失、篡改、重复、错误前序、过期未消费意图，以及残留锁/临时文件、序号回退/重复、链断裂、时间回退、轮换准备时间越界、事件 ID 复用、无变化重复证明、最新来源漂移、旧世代续写、当前断点所依赖的远端不可达或 current 块重复/越界均为 `BLOCKED`；本地未 Push 或远端拓扑尚未同步不属于该阻断，除非当前动作依赖它，不得自动删除、覆盖或猜测恢复。三个中央来源必须各有唯一非空 CURRENT，HISTORY 位于其后且区域间没有游离正文；路径按真实 Unicode 值和 NUL 分隔 Git 输出处理，NFC/NFD 碰撞只阻断，不自动改名。历史 v1/v2 封条标 `LEGACY_UNVERIFIED`；默认只回算最新来源，`--history-only` 明示 `latest_source_status=NOT_CHECKED`，不得支持 READY/COMPLETED。首次迁移从唯一 current 建立序号 1 的 `CURRENT_MIGRATION` v3 封条，绑定旧链最后摘要、世代和写者，不补造历史。正式附件必须由 `Prepare-Handoff.mjs` 通过规则 manifest、来源、实时 Git 基线和二次漂移检查后原子生成，失败不得留下 `final-*`。正式状态只允许 `READY / READY_WITH_RESTRICTIONS / BLOCKED / COMPLETED`；未注册颜色码不参与判断。该协议只能约束遵守工具的写入者，不能提供宿主级强制隔离。

交接从生成候选材料到正式切换使用一份冻结的规则基线：封条的 `rule_baseline` 必须绑定 `rule_version` 和 manifest 摘要，正式准备时再次回读并比较；同时封条的 `workspace.worktree_fingerprint` 必须绑定 tracked diff 和未跟踪内容摘要。记录 `rule_version`、manifest 摘要和轻量配置及 02/04/07/09/10 指纹。候选冻结的是 `rule_baseline` 快照，公共规则根另记录 `live_rule_epoch`。冻结期间规则根或 manifest 前进时，先登记 `RULE_REBASE_PENDING` 并按矩阵分类；兼容更新只保留候选并补记 `NEWER_COMPATIBLE`，触及交接门禁的更新定点重读后再生成新候选，旧候选仅在新候选形成后标记 `SUPERSEDED_BY_RULE_REBASE`。不得让操作者在版本之间择一，也不得沿用未重核的旧 `READY`。已完成接管后，新规则默认用于后续动作；只有新规则明确改变当前授权、单写者、安全边界或正在进行的高影响动作时，才重核受影响对象并按需追加 `CURRENT_ATTESTATION`。

以下任一情况使候选截点失效：候选冻结快照不可读、重基线失败或规则变化被判定为 `INCOMPATIBLE`；中央世代/单写者变化；旧总指挥在候选截点后产生实质调度或中央写入；工作区聚合指纹、Head、远端基线、活动目标或任务断点变化；相关 `KEY_NODE`、提交映射、目标候选、规范启动命令/自检契约、运行入口/选择器、依赖、模型/资产或服务来源变化；必要证据入口消失；发现未核验远端写入、不可逆动作或另一个调度者；候选任务在正式切换前被归档、取消、替换或无法再次核验。后一情况只使该候选材料失效，不把中央写者自动转移给其他任务；移交方须登记失效原因并为新候选重新准备材料。
另外，候选封条生成后出现封条来源、工作区、远端、活动目标或单写者变化，须重核受影响阶段；普通中央进度更新不自动撤销已经完成的接管。`remote.status=PASS` 只能代表封条记录的观测结果；若当前工具或环境不能实时回读远端 Head，必须将远端状态记为 `UNKNOWN`，在报告中标记 `REMOTE_UNVERIFIED`，并暂停依赖当前远端的动作，不得把旧草稿中的 PASS 当成实时证明。第一阶段移交方尚未停止或归档本身不使候选封条失效，不降低控制面材料评分；`READY / READY_WITH_RESTRICTIONS` 表示材料满足候选核验前提，不是已授予调度权。候选仍须独立核验单写者，封条校验通过不代替平台与授权核验。只有第二阶段实际换任及 `COMPLETED` 才要求操作者当前明确确认旧写者已停止调度，并核对世代递增。`IDLE` 只表示当前没有可见回合；`STOPPED_DISPATCH` 必须有操作者当前确认其不再接收新业务消息或执行任务；`ARCHIVED` 只是历史保存状态，三者不互相推导。

避免封条自引用：索引预先写入封条目录与事件编号，完整摘要和验证结果从封条读取并记入仓库外便携快照；不得将封条摘要回写到已被该封条按全文哈希覆盖的源文件。快照使用 `<project-slug>-commander-handoff-<YYYYMMDD>-final-<N>.md` 等包含稳定项目标识的文件名；旧版本保留，不覆盖。

## 7. 统一接管汇报模板

本节是面向操作者的接管汇报格式唯一来源。适用于正常交接、已确认总指挥身份的中断恢复，以及跨账号、跨任务或同一任务内发生的正式换任；普通阶段推进不自动产生新世代。其他入口只引用本节，不维护第二份模板；不符合本配置候选路径的恢复场景只读取本节格式，不因此取得候选资格或调度权。

每次切换尝试结束的那一轮最终回复，固定保留以下四个标题、顺序和字段。AI 自动填写；不适用写“不适用”，不可取得写“UNKNOWN（说明平台不可见原因）”，不能留空、输出未替换占位符或要求操作者填写技术字段。AI 应先按 10 规定的 discovery 顺序从当前平台线程元数据、运行时任务上下文和宿主任务 API 逐级核验当前任务 ID，并记录探针结果；不得把查找责任交给操作者。只有探针明确不可用或无唯一匹配时才记平台不可见。任务 ID 不可见时不得用逻辑 ID、任务标题或“待确认”替代。ID 可见性只决定该字段能否确认，不改变按中央状态证据独立判定的切换状态。

面向操作者时，默认只输出四句人话摘要；技术字段仅在用户要求或真实异常需要定位时补充：

1. **可切换置信度：高 / 中 / 低。高只表示当前阶段的切换前提已全部满足，可以放心进入切换；材料完整但仍有远端、旧写者或其他切换前提未满足时，不得评高。**
2. **是否建议现在交接：是 / 否。**
3. **真正阻断：只写会阻止当前阶段继续的事实；没有就写“无”。**
4. **操作者下一步：只写一条最小动作。**

四句摘要是默认最终出口，不是机器记录的节选。摘要应使用普通中文说明事实和影响，让没有工程背景的操作者一眼知道是否可以继续。不得先输出或自动附上计数、指纹、封条序号、内部状态码、完整清单或工具参数；只有操作者明确要求详细核验，或真实异常需要定位时，才补充不超过必要范围的技术依据。`NOT_RUN`、`UNKNOWN`、`GENERATED_NOT_DELIVERED`、编辑器状态不可观察和旧总指挥未归档，若不阻止当前候选阶段，写入“补充限制”而不是“真正阻断”。

“未收到机器 receipt”“编辑器未保存状态不可观察”和“旧总指挥尚未归档”分别处理：前两项不降低候选材料评分；旧总指挥尚未归档只表示尚不能完成最终切换，不表示候选材料失败。

```text
1. 总指挥身份
当前任务 ID：<平台实际任务 ID；不可得则写 UNKNOWN 及平台不可见原因>
当前角色与世代：<候选/正式总指挥> / <已核实世代>

2. 交接结论
切换状态：<COMPLETED/READY/READY_WITH_RESTRICTIONS/BLOCKED；按中央状态证据独立判定>
当前范围交接条件：<已满足/未满足/待确认>；<关键依据，含旧写者状态、中央回读与基线核对>
关键遗漏或阻断：<无；或证据、影响范围及受影响动作>

3. 接续断点
当前目标与阶段：<可恢复的目标和阶段>
已完成与未完成：<有凭证的成果；剩余对象及精确下一步>
恢复基线与证据：<必要的版本/分支/工作区状态及最小证据入口>

4. 下一步与边界
AI 下一步：<当前授权内的具体动作；无可执行事项则明确等待>
操作者下一步：<无需操作；或确需人工完成的最小动作、目的、预期结果和异常反馈方式>
授权与暂停项：<旧授权未继承；当前允许范围、暂停动作及恢复条件>
```

- ID 用于在有访问权限的平台中定位任务，世代编号用于区分写者任期，任务标题仅作显示。当前任务 ID 必须是本窗口平台实际回读值；逻辑任务 ID、角色/写者 ID、任务标题和“待确认”都不能替代它。ID 不可见时如实写 `UNKNOWN` 和原因，但不要因此单独改变切换结论；切换状态仍按中央状态证据判定。不得承诺任意账号或窗口凭 ID 即可跨权限访问；跨宿主联络确需附加路由时，只补平台已核实的信息。真实 ID 仅用于当前对话和获授权的运行时联络，禁止落盘时不得写进仓库文件；公开示例仅用 `<COMMANDER_TASK_ID>`。
- 先按当前目标、单写者、精确断点、必要证据和权限判定条件，再填写结论，不能倒推缺口。没有证据支持遗漏时写“无”；不为填表扫描全部历史、制造问题或强行要求操作者补材料。未知必须写明影响依据，不能自动等同失败或通过；置信度如需说明使用有依据的定性判断，不附无校准的精确概率。
- 条件未满足或待确认时，在第 4 段给出对应最小补救路径和行动方；AI 可在已有授权内核验的事项由 AI 处理。当前恢复必需证据缺失仍阻断受影响切换；历史无关、辅助材料或画像适配问题只暂停依赖动作。正确暂停的远端动作不等同交接失败。
- 接管完成后需要继续工作的，以第 3、4 段恢复原队列，不从头重做已有凭证的成果；没有活动目标时明确等待新的指令，不虚构研发任务。旧授权、进程和专业结论均不继承，报告本身不产生新授权。
