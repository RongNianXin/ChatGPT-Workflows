# 规则刷新接收回执

正常成功只回复：

```text
状态：COMPLETED
result：PASS
RULE_SOURCE_LOCATOR：VERIFIED
RULE_REFRESH：PASS
RULE_ADOPTION_RECORD：SYNCED / SYNC_PENDING
已采用：<当前稳定规则版本>
项目登记：<已同步；或待同步及行动方>
```

规则根无法核验时回复：

```text
状态：COMPLETED
result：FAIL
RULE_SOURCE_LOCATOR：SOURCE_NOT_LOCATED / STALE_SOURCE_UNCONFIRMED / INPUT_REQUIRED
未能更新：<无法读取或核验的规则文件及原因>
下一步：<最小恢复动作>
```

`RECEIVED` 只用于仍在处理的中间回执，不能作为最终回复。规则加载结果不使用 `WARN/BLOCKED`：项目启用、身份、写者、CURRENT、配置迁移、耐久登记、交接或封条问题不属于本事件；如确实影响后续项目动作，可在成功回执后追加一行 `项目后续待办：<一句话>`，但不得把 `PASS` 改成其他结果。最终回执必须把以下五项分开：`RULE_SOURCE_LOCATOR：VERIFIED/SOURCE_NOT_LOCATED/STALE_SOURCE_UNCONFIRMED/INPUT_REQUIRED`、`RULE_REFRESH：PASS/FAIL`、`RULE_ADOPTION_RECORD：SYNCED/SYNC_PENDING`、`PROJECT_ENROLLMENT：ENROLLED/NOT_ENROLLED/UNKNOWN`、`IDENTITY_CONTROL_PLANE：VERIFIED/NOT_REQUESTED/UNKNOWN`。`RULE_REFRESH=PASS` 只能在来源权威性已核验且正文稳定完整时使用；旧根自洽只能记内容自洽，不能写成最新公共规则。规则采用记录只描述登记同步，不改变公共规则源或中央身份。

最终结果必须对应当前刷新事件；广播有 `MESSAGE_ID` 时带上它，操作者直接0A无编号时按当前请求定位，不要求操作者补编号。旧业务答复、旧规则成功回执、只有“已收到”或平台完成均不证明本次采用。尚在正常分段读取时继续处理，不以“正文未读完”单独收口；真实停止条件触发才用FAIL说明原因、已读断点和恢复条件。同一窗口的有效来源绑定与完整正文复用按广播包执行，不继承其他窗口已读状态。

逐文件哈希、项目状态盘点和完整证据默认不展示给操作者。只有规则根核验失败、发送方进行批次审计或操作者明确要求时，才展开实际 manifest 摘要和异常文件。

普通本地刷新不因旧预期指纹单独失败；精确版本、正式交接及封条仍严格校验，失败不降级。记录本次模式、实际内容摘要、`text_reading=COMPLETE/INCOMPLETE`、分段读取范围和终点复核证据；多目标各自成功不等于同一固定版本全体通过。工具或阅读器的单次输出截断应进入下一段读取，不得直接记为来源损坏。机器字段留在既有记录中。
