# 规则刷新接收回执

正常成功只回复：

```text
状态：COMPLETED
result：PASS
已采用：<清单同步时写版本；否则写“当前已保存本地规则，版本登记待同步”>
```

规则根无法核验时回复：

```text
状态：COMPLETED
result：FAIL
未能更新：<无法读取或核验的规则文件及原因>
下一步：<最小恢复动作>
```

`RECEIVED` 只用于仍在处理的中间回执，不能作为最终回复。规则加载结果不使用 `WARN/BLOCKED`：项目启用、身份、写者、CURRENT、配置迁移、耐久登记、交接或封条问题不属于本事件；如确实影响后续项目动作，可在成功回执后追加一行 `项目后续待办：<一句话>`，但不得把 `PASS` 改成其他结果。最终回执必须把以下三项分开：`RULE_REFRESH：PASS/FAIL`、`PROJECT_ENROLLMENT：ENROLLED/NOT_ENROLLED/UNKNOWN`、`IDENTITY_CONTROL_PLANE：VERIFIED/NOT_REQUESTED/UNKNOWN`。

逐文件哈希、项目状态盘点和完整证据默认不展示给操作者。只有规则根核验失败、发送方进行批次审计或操作者明确要求时，才展开实际 manifest 摘要和异常文件。

普通本地刷新不因旧预期指纹单独失败；精确版本、正式交接及封条仍严格校验，失败不降级。记录本次模式、实际内容摘要、`text_reading=COMPLETE/INCOMPLETE`、分段读取范围和终点复核证据；多目标各自成功不等于同一固定版本全体通过。工具或阅读器的单次输出截断应进入下一段读取，不得直接记为来源损坏。机器字段留在既有记录中。
