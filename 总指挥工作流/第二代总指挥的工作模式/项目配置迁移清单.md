# 项目级配置迁移清单

本清单用于已授权的项目接入、配置迁移、控制面修复，以及已授权实际动作执行前所必需的旧状态适配，不再随规则广播自动执行。规则加载成功不代表本清单已经执行；本清单存在缺口也不得降低规则加载结果。清单只描述需要检查的对象，不授权产品代码、远端或其他项目修改。

| 项目对象 | 空白项目 | 已运行项目 | 普通专项任务 | 核验结果 |
|---|---|---|---|---|
| `总指挥工作流/工作流启用声明.md` | 仅在操作者明确启用并任命总指挥后才提出新建并写入 `enabled` 的候选；否则只读并回 `WARN/UNKNOWN` | 检查并补齐（须有事件写入授权） | 只读 | |
| 动态状态索引 | 建立唯一 `CURRENT/HISTORY` | 收敛旧 CURRENT，保留历史指针 | 只读 | |

缺失、冲突或无法写入时，只阻断依赖该对象的动作，并在回执中写明恢复条件；不得把无关产品任务全部判为阻断。

## 旧状态按需适配

先识别新要求影响的字段或入口。格式缺项不等于身份冲突：现任世代、唯一写者与实际入口已有独立可核验证据，且当前授权覆盖该动作所需本地登记时，由现任唯一写者自动最小补齐、保存回读，不逐字段重复索权。新注释不能反过来自证身份；未知平台映射如实记录，真实身份冲突、破坏性变更或新增权限只暂停受影响动作。

身份分流必须先确定唯一权威：状态索引 `CURRENT` 的身份和唯一写者是规范来源，中央入口、当前视图和工作项只保存导航或与该来源一致的派生视图。若只是派生视图残留旧世代、缺少新版导航字段，且状态索引、平台任务映射和唯一写者证据一致，登记 `CONTROL_PLANE_MIGRATION_REQUIRED`，由当前唯一写者在已授权范围内最小修复、逐份回读后再继续；操作者称呼或确认本身不能替代这些证据。若状态索引 `CURRENT`、平台映射或唯一写者彼此冲突，登记 `CONTROL_IDENTITY_CONFLICT`，只暂停正式切换和控制面写入，不覆盖旧记录、不生成新封条。

迁移须在冻结或生成新候选之前完成。保留历史和旧封条；中央来源、工作区或不兼容的规则变化才使旧候选失效；公共规则源前进先按 `SAME / NEWER_COMPATIBLE / AFFECTED_RECHECK / INCOMPATIBLE / UNAVAILABLE` 分类，受影响阶段按 `RULE_REBASE_PENDING` 重读，只有新候选形成后才标为 `SUPERSEDED_BY_RULE_REBASE`。多文件迁移中断不得宣布完成。验证分别记录旧格式识别、迁移后门禁、当前真实实例预检；未做的保持未验证，不以模拟测试代替。跨项目缺口交由该项目唯一写者处理，不由规则维护者批量回写。
