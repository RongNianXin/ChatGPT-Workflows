# 第二代总指挥工作流总览

版本：2026-09-21.4

定位：适配 Codex Desktop 与 GitHub 协作的“自然语言目标 + 单窗口主执行总指挥 + Goal + 例外专项任务”工作流。

状态：受控试运行。默认采用单窗口主执行；例外专项任务按总 Token 净收益判断。远端写入确认、稳定截点、高资源授权、未知修改保护和异常回退等安全门禁继续保留。

项目是否启用本工作流由项目根目录的 `总指挥工作流/工作流启用声明.md` 决定，不由目录存在、任务标题或任务 ID 推断。声明启用也不等于已有可接管身份：每个空白任务仍须按 `10` 定位未过期的项目实例状态；状态缺失、冲突或通信握手失败时只登记 `UNKNOWN/BLOCKED`，不开始依赖中央状态的专项修改。当前总指挥、世代、单写者和租约是动态事实，交接后必须重新登记，固定规则不保存它们。

跨项目经验按 [经验索引](../跨项目经验库/经验索引.md) 按需加载：项目本地经验、脱敏候选和已采纳公共条目分层保存；候选多写者追加，公共索引单写者合并，索引或候选变化不自动等同远端阻断。

## 1. 一句话说明

本工作流面向 GitHub：使用者只向一个总指挥窗口说明自然语言目标、AI 无法读取的信息和最终授权；总指挥负责只读核验、制卡、实现、验证、状态记录与交付。专项任务只在独立并行、独立审查、证据隔离或能力缺口具有明确净收益时创建。

低风险明确任务直接执行；需要确认的协作工作先只读核验，再集中确认有界工作包。已授权阶段按 09 连续执行、分别验证，新增权限只补差额。成果、回执与授权独立，旧任务不继承远端权限。

跨任务协作把成果运输、授权请求和写入租约转移分成 `WRITE_HANDOFF`、`AUTH_REQUEST`、`LEASE_TRANSFER` 三类事件。没有目录写入租约不等于缺少用户业务授权；非写者用一次结构化交接把成果送给现任写者，只有新增动作超出授权或确需更换唯一写者时才分别进入授权或租约流程。

多项请求使用一份活跃请求清单持续核账。阶段确认文本只限定当前受控动作，不会自动取消、完成或隐藏其他事项；执行后总指挥必须返回原清单继续推进或说明具体阻断。

操作者可以只用日常语言描述目标、现象或“不确定”；输入门槛降低不等于输出标准降低。总指挥仍须主动恢复技术事实，给出完整的范围、依据、风险、验证和未验证项。输出不符合预期且根因不明时，按专项手册把实际执行过程变成可检查的输入到输出链路，并在每一步解释检查目的、证据含义和下一步，帮助操作者逐步形成可复述的因果模型。默认先交付可复制的紧凑文本执行图；需要拓扑细节时再给 Mermaid/SVG/Excalidraw，需要逐步讲解或中间证据对照时使用本地静态 HTML 步骤演示。展示形式不能改变证据等级，也不能把示意图当成实际运行产物。

每条指令在执行前都先做一次与风险相称的检查：简单、低风险任务静默快速检查，复杂、争议、影响不明或反复失败的问题按 `02` 做结构化对抗式审查，区分事实、因果、真实阻断和辅助噪声。硬门禁不降低，只暂停实际受影响的对象或阶段；审查深度不应随提示词长度机械增加。

文档以准确、可执行和可复核体现专业性，按 [专业表达与低操作负担](06-复盘与优化规则.md#专业表达与低操作负担) 减少重复人工操作；正式接管汇报统一使用 [四段模板](总指挥轻量交接启动配置.md#7-统一接管汇报模板)。

总指挥项目用中央工作项清单、轻量当前视图和状态索引保存中央断点；专项任务复用自己的短状态，普通任务复用已有计划或任务记录，不为恢复另建第二套事实库。使用者要求“写进计划、记录成果、保存进度、存档、留档”或表达同义意图时，先按语义区分未来计划、当前状态、完成成果和详细证据，再把仍影响后续决策的事项同步到中央工作项清单。规则入口、任务中断恢复、总指挥交接、会话健康与额度保护、视觉材料、远端授权和可选的本地协作画像分别由 `04/05/07/09/10/11` 维护，本总览只负责架构和导航。协作画像默认关闭，选择绑定已核验的规则根并跨项目持续；只在没有可靠选择记录时于首次总指挥主回复后介绍一次。明确启用后，各窗口在可观察的稳定里程碑、交接前及其他指定断点做本地检查，由当前总指挥默认统一写入。

总指挥换任、把未完成主线移到新聊天，以及归档仍承担工作的任务，都先执行 04 的“换窗与归档前连续性门禁”。正式换任按四阶段完成：旧总指挥准备并冻结材料、新候选只读核验、操作者停止或归档旧总指挥、第二段确认后新候选正式登记；候选阶段旧任务仍存在或仅从 active 变为 idle 不单独造成评分降级。正式换任生成便携交接快照；普通分支或归档至少生成可直接发送的新窗口续接提示词。该门禁保存已完成且不可重复的动作、结果未知项和精确断点，不复制完整聊天，也不继承旧授权。当前 AI 无法观察使用者未通过消息表达、直接在侧栏完成的归档点击。

正式交接新写入使用封条 schema v3 和 `.github/scripts/Prepare-Handoff.mjs`：跨序号时间不得倒退，轮换意图必须位于前序封条与接管封条之间，事件 ID 全链唯一，`CURRENT_ATTESTATION` 必须至少包含一项来源摘要变化。旧 v1/v2 记录只作为 `LEGACY_UNVERIFIED` 历史读取，不能继续追加旧格式。正式状态只使用 `READY / READY_WITH_RESTRICTIONS / BLOCKED / COMPLETED`，未注册颜色码或近似词不得进入封条、交接结论或接纳回执。

每个项目相关 Commit 都进入耐久提交台账；改变默认入口、运行选择器、配置、依赖、模型、资产、数据契约、部署路径、发布、合并、回滚或人工确认基线的节点标记为 `KEY_NODE`。本地 Commit 是默认的耐久检查点：在完成一个可独立核验的小批次、长任务阶段结束、人工验收前、方案分叉前或准备远端同步前优先建立；不为凑频率拆成无意义提交。远端同步不因本地 Commit 频率而自动发生，仍须按实际需要和单独授权决定。Tag 只用于已验证的版本发布、明确回滚锚点或操作者指定的稳定里程碑；普通检查点默认不打 Tag，打 Tag 时使用中文且不推送。文档精简可以迁移详情，但不能删除关键节点身份、映射、证据指针和失效条件。Commit 只证明某个代码状态存在，不自动证明已经验证或远端可见。

操作者无论用简短还是完整的自然语言表达部署与人工核验目标，都是有效入口。公开操作手册提供专业、完整、可复制的推荐模板；总指挥不得把模板完整度变成开始安全核对的前置条件。总指挥必须自行恢复目标候选，优先使用仓库维护的规范启动命令及其自检输出，并核对代码基线、实际运行入口、profile/开关、依赖、模型、资产、缓存和服务来源；交付地址前证明“打算验收的版本”与“页面实际运行的版本”一致。PR 前还要识别并存实现及选择器，明确区分代码已包含、默认已选择、测试时实际运行和干净环境可复现。

自然语言路由采用“公开通用场景 + 可选本地适配”两层。确认命中正式编号场景时，AI 在第一次实质回复开头给出一条简短场景判断和依据；没有适用场景、只是简单问答或沿用同一场景的连续反馈时不强制重复。该回执只能证明本轮做过路由判断，不能证明规则已经完整读取、授权成立、验证通过或任务完成。

工作流规则更新后，操作者可以直接用自然语言指定要通知的项目总指挥和排除对象。总指挥按 `09/10` 的跨项目规则刷新协议生成同一 `RULE_REFRESH_ID`，把“已发送、已收到、已重新加载、已完成语义接纳”分层核账；`RECEIVED`、版本号或文件指纹只证明送达或内容身份，只有目标任务完成适用范围回读、语义差异复述、冲突判断和本地耐久登记后返回合格 `COMPLETED`，才能记为已接纳。该结论仍不能保证未来每一步必然遵守，后续关键动作按失效条件复核。

本地协作画像可以保存经过抽象的自然语言路由别名，使同一套公开模板适配不同操作者；别名只帮助识别目的和选择入口，不得改变团队规则、事实标准、角色、授权、验证或停止条件。画像正文继续留在 Git 忽略且未跟踪的本地实例中，任务间只传递不含正文的修订失效通知。

### 核心设计目标与新功能审查基线

本项目的根本目标是让人类与 AI 更顺畅地协作：提高任务解决质量，减少误解和冲突，降低操作者的步骤，以及 AI 的读取、判断、时间和 Token 成本。目录、模板、分包和自动化只是实现手段，不是目标本身。

新增或调整功能时，在既有对抗式审查中额外核对：它是否有合理且可验证的协作净收益依据；是否保持已有简单入口；新增的人类操作和 AI 载入成本是否必要且与收益相称；依赖失效是否会被明确发现并只暂停受影响阶段。没有可核对的净收益依据、只是转移复杂度或需要操作者理解内部路由的机制，不应加入。该检查默认静默完成，只有发现会改变方案的冲突或取舍时才向操作者说明，不新增表单、后台任务或固定长报告。

主要实现和验证完成后，先判断实际产物、风险和证据是否需要第二次对抗式复审。只有非平凡产物、重要或高影响变更、前置审查时尚不存在可检查产物、验证暴露新事实、范围/基线变化，或仍有足以改变结论的不确定性时才启动；只复核新增产物、变化范围和最可能推翻结论的证据，不重复第一次审查。简单任务或现有验证已经充分时不增加该轮。操作者主动要求的审查与同阶段默认审查合并，不形成额外叠加轮次；该机制不替代人工效果验收、独立 Reviewer 或远端批准，也不增加新的授权。

可分发成果不得依赖作者机器的盘符、用户名、仓库绝对路径或临时目录。仓库内链接、模板指针和配置默认使用相对路径，脚本从自身位置或当前仓库根目录动态解析；仓库外输入、系统标准目录和安全边界核验可以在运行时使用当前机器的绝对路径，但不得把旧机器路径保存为跨设备事实。换位置克隆后，应先重新绑定当前根目录，只让无法重建的具体指针失效，不把可恢复的整个工作流判为失效。

## 3. 四层职责

### 使用者本人层

当前向 AI 发出指令并承担最终确认的人。提出目标、范围、验收标准、优先级和限制；默认只需在 AI 自动恢复事实、预填批量执行卡后集中确认一次。操作者不记得修改内容或无法判断表现时，可以直接选择“不确定，请继续自动核对”；AI 不得要求其猜测技术事实，也不得把空白、沉默或“不确定”记为通过。若希望真正只发一条消息就离开，可以在对象、动作和禁止项已经明确时随 Goal 提交精确预授权包，但这不是经验不足阶段的推荐默认值。

### 总指挥层

默认同时负责控制面和主执行面：完成输入完整性、事实核验、范围核账、依赖分析、优先级、资源门禁、实现、测试、localhost 交付、远端授权内执行、状态汇总、动态重规划和流程复盘。为避免角色混淆，按“控制与制卡 → 主执行 → 验证 → 稳定截点记账”分阶段工作；作者自检不得冒充仓库要求的独立 Review 或专业验收。

### 专项任务层

专项任务是例外能力，不是固定执行层。只有以下至少一项成立且预计节省的关键路径或上下文成本明确大于固定规则载入、重复取证、派发、等待、回执和再汇总成本时才创建：边界独立并有真实并行收益；规则要求独立审查；批量高成本证据适合隔离；主窗口缺少必要能力。一个专项任务只负责一个边界清楚、可独立交付和验证的单元，结束时回传最小结果增量。不得因“代码应由专项做”而拆分同一根因、同一 PR、同一 worktree、连续 UI 反馈或普通局部实现。

### 项目实例层

保存具体项目的代码、规则、Issue、PR、成员、路径、当前目标、任务状态、Base/Head、测试结果、交接记录和 `AI状态索引.md`。第二代抽象层只保存索引规范，不得写入这些实例数据。

## 4. 事实优先级

当前代码和测试结果 > 当前 Git/GitHub 状态 > 项目规则和状态入口 > 已确认的会议记录 > 旧聊天记录和旧 AI 结论。

无法确认的内容统一标记为“待确认”，不能因为旧文档写过就当作当前事实。

## 4.1 永久规则优先级

系统和平台限制 > 当前团队及目标仓库规则 > 分支保护、CODEOWNERS 和 CI 门禁 > 使用者本人本轮授权包 > Goal 与专项任务卡。批量授权不能覆盖更高层规则；团队文档禁止的动作即使被使用者本人误点同意也不得执行。在硬安全边界内，仓库具体流程优先于通用工作流偏好；缺 Reviewer 等低风险流程缺口只暂停受影响阶段，不使全量推进整体停止。

本工作流禁止 Force Push、直接写受保护分支、绕过 Review/CI/分支保护、使用未知凭据和秘密、删除远端历史。即使使用者本人误点同意也不得执行；确有灾难恢复等例外需求时，必须退出本工作流，改用团队正式事故流程和专门审计。

## 5. 八类执行模式

1. 普通目标：处理一个有限目标，默认使用一个 Goal，由总指挥在单一主窗口完成实现与验证；只有通过总 Token 净收益门禁时才增加最少量专项任务。
2. 规划转交付：把会议、问题或路线规划去重并转为 Issue；端到端模式可在精确授权后继续实现、测试和创建真实 PR，仅建档模式停在 Issue。
3. 本地闭环实现与发布准备：普通目标使用 01 场景 2；长期未同步但暂不更新时用 4H 预检，只有远端成果需进入本地时用 4J，两边都有需保留的改动时调用 4I，再回原候选与同一有效发布卡；仅更新本地不自动发布。保留工作区、运行身份、内容筛选、验证及授权门禁，本地 Commit 不等于 Push。
4. 协作队列全量接管推进：在目标和协作证据范围内重建完整候选集，区分执行、依赖和排除对象，并保存可靠截点。
5. 协作队列增量推进与覆盖核账：从可靠截点处理变化、未闭环旧账和派生对象；截点不可靠时退回全量推进。
6. 过时对象审查与收口：以远端当前事实和验证证据识别已解决、重复、被替代或不再适用的 Issue/PR；证据不足一律保持开放，关闭和替代留言分别受逐对象远端授权约束。
7. 控制面工作：只汇报进展、拓扑、状态变化、目标变更、交接或复盘，不启动产品实现。
8. 任务中断恢复：普通、专项或总指挥任务因额度耗尽、程序异常、账号切换等原因中断时，先恢复原窗口身份，并用最少元数据执行恢复收益门禁，在 `直接重做 / 快速恢复 / 深度恢复 / 必须先核账` 中选择成本更低且不会重复副作用的路线。需要恢复时再按任务实际选择当前消息、用户明确提供的精确附件、任务记录、产物、工作区、Git 或平台事实；恢复提示词本身不产生总指挥身份。只有原窗口确为总指挥且没有正式交接时，才进入中央热快照、状态索引、单写者和新世代恢复。任何分支都不继承旧高风险授权，也不重做已有可靠完成凭证的动作。

八类模式的候选算法、Review/分支判断和逐对象状态以 `02` 为准，状态恢复以 `04/10` 为准，授权以 `09` 为准。本页不复制其详细条件。

## 6. 与旧版或其他工作流的关系

新用户无需了解或准备任何旧版文件，直接从 `01-操作者操作手册.md` 开始。只有项目已经运行另一套总指挥工作流时，才按 `08-旧版兼容与迁移规范.md` 进行只读映射、事实核验和切换；旧任务、授权、进程与完成声明不得直接继承。

## 7. 推荐使用顺序

- 人类只需先看 `01-操作者操作手册.md`。
- 总指挥首次启动时读取 `02-总指挥核心规则.md`。
- 行为保持型代码精简从 01 场景 2B 进入（旧编号 2B-1 仅作兼容定位），执行细则只维护在 02 的 6.3.1；引用场景 2 的本地授权与发布门禁，沿用场景五适用协作、运行身份和 PR 交付标准。跨机器效果/速度差异按链路排查标准对照，不与精简混为一个目标。
- 只有通过专项任务总 Token 净收益门禁时，才按 `03-专项任务卡模板.md` 创建最少量例外任务。
- 动态变更和交接按 `04-状态、目标变更与交接规范.md`、`07-总指挥交接记录模板.md`；正常交接候选的第一次只读按 `总指挥轻量交接启动配置.md`。
- 自动化任务交接先区分现有任务核验与缺失任务重建；非敏感字段模板见 `templates/SCHEDULER_REBUILD_GUIDE.md`，不复制完整提示词，也不产生创建或修改授权。
- 模型配置按 `05-模型选择与资源策略.md`，复盘按 `06-复盘与优化规则.md`。
- 授权和风险分级按 `09-自动化授权与风险分级.md`。自动 ID、快照、游标和历史检索按 `10-自动状态索引规范.md`。
- 本地协作画像的首次介绍、五态开关、跨项目选择继承、触发式维护、唯一画像写者、外部资料候选、自然语言路由别名、修订失效通知、创建、读取、更新、交接或删除按 `11-操作者协作画像规范.md`；01 使用 Pe1-(a)/(b)/(c) 作为开启或接管、关闭和外部资料入口。默认关闭且只询问一次，同一规则根已有可靠选择时不再询问。
- 浏览器、真实媒体、模型、跨版本或人工结论冲突的自动化测试，按 `02` 的触发接口完整读取 `docs/AUTOMATED_TESTING_LESSONS.md`；它只约束测试结果可信度，不产生授权，也不进入 00～11 正式规则编号。
- 请求发布或推送仓库成果（即使未提 PR），以及创建或更新 PR、请求或重新请求 Review、回复阻断意见、判断可合并状态时，完整读取 `docs/PR_SUBMISSION_AND_REVIEW_STANDARD.md`；它维护 PR 的交接契约、实际验证、回复闭环和模板，不产生远端写入、Approve 或 Merge 授权。
- 输出质量不符合预期、跨环境结果不一致、根因不明或同类修补连续失败时，完整读取 `docs/PIPELINE_DIAGNOSIS_AND_ALGORITHM_TUNING_STANDARD.md`；它维护实际执行图、观测点、因果验证、最小修复和教学式协作。只有执行到等宽文本图生成步骤时，才按该手册调用仓库根目录的 `其他 Codex 技巧性提示词/文字版流程图提示词.md`，不在总指挥启动时预加载；两者都不产生产品修改、高资源运行、专业结论或远端写入授权。

执行与独立审查协作（内部子 Agent／独立任务窗口）按需读取 `docs/EXECUTION_AND_INDEPENDENT_REVIEW.md`；操作者从 01 场景五进入，03 只为需要任务卡的新建专项窗口提供接口，04 负责换任联络。执行者和独立审查者是逻辑角色，可由现有总指挥、普通任务、专项任务或内部子 Agent 承担；载体选择、环境与生命周期由主规范统一定义，不自动迁移在途任务；存在项目总指挥时仍只保留一个中央调度者和单写者。
