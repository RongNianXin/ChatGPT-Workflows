# 公开信息安全边界

## 原则

公开仓库只保留可独立理解的通用工作流、模板与虚构示例。任何能识别来源项目、个人、组织、环境或内部实现的信息都不应进入 Git 历史。

## 厂商官方反馈脱敏（核心规则）

任何向厂商官方渠道提交的公开内容（Issue、Discussion、官方论坛、反馈表单、支持工单等）都必须先制作独立脱敏副本。除常规敏感信息外，以下字段默认直接抹除或泛化，不作为公开证据：

- 姓名、电话号码、邮箱、住址、通信地址及其他联系方式；
- 国籍、国家、地区、省市、所在城市等能定位身份的信息；
- 当前实际地理位置、可由时区或日志反推的位置、公网出口 IP、代理/网关节点、VPN 出口节点；
- 设备名、本地用户名、绝对路径、任务/会话 ID 等可反查环境的字段。

当某条证据必须使用地理位置、网关节点或出口 IP 才能说明问题，而省略后会导致证据不足时，AI 不得自行决定公开或删除：先暂停该次发布，向操作者说明需要填写什么、为什么必须、公开后的可反查风险，并给出最小暴露替代方案或“宁可不报”建议，由操作者明确决定后再继续。宁可证据不足，也不硬报可能暴露真实身份或位置的节点信息。

## 禁止进入仓库的信息

- 真实项目、组织、机构、团队或人员名称；
- 本地用户名、设备名、绝对路径和任务标识；
- 真实仓库地址、分支、Issue/PR 编号和提交 SHA；
- 个人数据、受监管资料、敏感业务数据与内部架构信息；
- 截图、附件、聊天原文和未脱敏日志；
- 账号、Token、API Key、密码、私钥、Cookie、连接串或内部链接；
- 可通过组合推断出上述信息的唯一标识或细节。

## 允许的表达方式

使用虚构且明显不可解析的占位符：

- 仓库：`OWNER/REPO`
- Pull Request：`PR #<NUMBER>`
- Issue：`Issue #<NUMBER>`
- 项目目录：`<PROJECT_ROOT>`
- 任务标识：`<COMMANDER_TASK_ID>`

不得用看似虚构但实际对应真实对象的数据替换占位符。

## 发布前检查

每次 Commit 和任何公开动作前必须完成：

1. 用 `git status --short` 核对变更范围和未跟踪文件。
2. 用 `git diff --check` 检查空白错误；对首次提交同时检查已暂存差异。
3. 用 `git diff --cached --name-only` 确认只暂存明确文件。
4. 人工阅读完整的 `git diff --cached`，确认没有无关内容。
5. 搜索本地绝对路径、用户名、任务标识、真实仓库坐标和内部链接。
6. 搜索常见 Secret 形态，包括私钥头、Token、API Key、密码和连接串。
7. 检查 Markdown 相对链接是否指向仓库内存在的目标。
8. 核对既有 remote 的目标与本轮范围；已有 remote 不等于违规，也不产生新增、修改或写入远端的授权。

自动搜索只能降低风险，不能替代人工核对。若发现疑似敏感信息，应停止提交和公开动作，报告位置与类型；不得擅自覆盖、删除或重写历史。

## 事件传递边界

只有通过专项任务净收益门禁后才跨任务传递信息，并且只传递完成独立边界所需的最小内容：已脱敏规则增量、范围、验收标准、摘要、验证结果、隐私检查结果、Commit SHA、待裁决事项和授权请求。结果应直接回传总指挥，不要求使用者复制。实际来信遵守既有前台 FIFO 顺序；不因此新建后台队列、Heartbeat、标题同步或多视图逐动作传播。

运行时任务标识不得写入仓库、Commit、日志或公开内容。
