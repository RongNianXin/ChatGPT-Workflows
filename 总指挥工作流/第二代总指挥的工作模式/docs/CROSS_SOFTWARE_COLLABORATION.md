# 跨软件 AI 专项协作

修订：1

这是现有专项协作的传递方式，不新增编号场景。适用于项目总指挥与另一款软件中的 AI 无法直接通信、不能互读聊天，但能由操作者转交文本或获准共享文件的情况。项目开发、研究和独立审查仍沿用各自原场景；普通业务只在命中跨软件协作时加载本文。0A/0B 规则刷新、规则维护及明确全文审计按各自既有读取范围执行，不因“业务按需”跳过必读正文。

当前交付是通用规则和模板，不是已安装的连接器，也不证明任何客户端可用。框架可以先于具体软件和任务建立；实际接入与测试由使用它的项目总指挥在取得该项目授权后完成。

## 1. 分工与边界

- 操作者选择软件、确认项目任务和必要权限，完成 AI 无法代办的开窗与转交。技术参数由项目总指挥填，不要求操作者拼命令或维护表格。
- 项目总指挥派发、核验、验收并唯一维护本项目中央状态。外部 AI 只承担有界执行或独立审查职责，不接任总指挥，不触发 1C/1D 或世代轮换。
- 公共工作流维护者接收脱敏反馈，独立判断是否修改公共规则，不接管来源项目，也不代签其测试或专业验收。规则变更不自动发送、采用或恢复其他项目任务。

复用 [03 专项任务卡](../03-专项任务卡模板.md)、[04 创建与联络](../04-状态、目标变更与交接规范.md#外部专业职责的续接)、[09 授权门禁](../09-自动化授权与风险分级.md)。独立审查还须满足 [执行与独立审查协作规范](EXECUTION_AND_INDEPENDENT_REVIEW.md) 的不同实例、共同材料、版本与轮次要求；同一个 AI 换角色不算独立审查。

## 2. 实际接入：先确认对象，再验证传递

这些步骤在具体项目首次使用时执行，不是现在建立框架的前置条件。

1. 项目总指挥核验实际软件、能力与使用条件，以及当前操作者允许交付的任务、数据和动作。赞助额度不免除源码/材料出网边界、费用和账号规则；软件读本地文件后可能将内容发送给模型服务。条款或数据许可不明时，先限于已获准的非敏感材料，不共享凭据、不绕过赞助条件。
2. 有效授权明确指定“在外部软件协作”后，由操作者在该软件开窗并递交启动材料；有已核验且获准的原生创建接口时也可使用。只记录实际创建方式，不伪称 `create_thread` 成功。没有外部协作授权的同应用任务仍走原创建规则；原生通信失败不得自动切换到本分支绕过限制。
3. 在项目既有私有任务记录中绑定软件、外部实例的可观察标识或操作者确认的窗口别名、原场景、任务卡、规则根、传递方式和写入边界。没有原生任务 ID 就写未知，不伪造 Codex ID。操作者指定的对象与回交渠道须可核对；文件名、别名、自称、哈希或测试字符串本身均不是身份证明或授权。
4. 外部 AI 实际读取适用规则和任务卡，不能假设软件自动加载 `AGENTS.md`，也不能继承总指挥或旧实例的“已读”。无法读本地规则时，可在允许共享范围内由操作者转交必要正文；缺少必读正文只暂停其依赖动作。
5. 用不含项目资料的短往返确认传递：总指挥给出绑定任务和轮次的测试文本，操作者递交；外部 AI 回答实际读到的任务、轮次、职责及限制；总指挥回读并核对。共享文件方式还要在获准位置验证实际读写，文本转交成功不能代签文件可用。只登记“文件往返可用”或“人工文本转交可用”，不登记原生主动通信成功。失败时保留现有实例和成果，只暂停依赖该渠道的动作，不自动重建。

对象、授权、必读规则和选定渠道的往返均可核验后，才可开始正式工作。改变实例、软件、根目录、规则、任务基线或授权时，只重核受影响部分。软件不能读写本地文件时，仍可按授权做文本型研究或建议；不能冒称已经修改、测试了本地产品。

## 3. 材料放在哪里，谁能改

优先使用项目已有、获准且 Git 忽略并未跟踪的本地协作位置。没有现成位置时，由项目总指挥提出一个精确路径并核权限后建立；仓库外写入另核授权。两端绑定同一个实际交换根，不能假定不同 worktree 中的同名相对目录就是同一处。

任务卡及其既有短状态仍是唯一工作记录。交换文件只是带任务/轮次/版本的传递副本，不另建中央账本，也不放进总指挥控制面目录。无共享目录时用同样的内容进行人工文本转交。

| 内容 | 谁写 | 谁读 |
| --- | --- | --- |
| 任务单、审阅或返工意见 | 项目总指挥 | 外部 AI |
| 收件确认、实际成果与验证报告 | 外部 AI | 项目总指挥 |
| 中央状态与最终验收结论 | 项目总指挥 | 按本项目读取权限 |

每一轮写完才交付：支持可靠完成发布时，在同目录完成临时文件后再发布最终文件；否则先暂停写入，由接收方核对完整、稳定的版本后再读取采用。已交付内容不原地修改，修订另开轮次并关联前版。就绪标记和哈希只能辅助核对完整性，不能证明内容正确或身份可信。

真实代码任务由项目总指挥在该项目权限内安排写入范围。避免双方并发修改同一个工作目录或共享未提交状态；需要独立分支/worktree 时先按该项目规则获准并登记，不因采用本文自动创建。worktree 不是安全沙箱，仍共享部分 Git 元数据；外部 AI 不改中央状态、公共工作流、其他工作区、共享 Git 配置或 hooks。仅靠文本约定不能声称操作系统已阻止越权；无法接受这种风险时，降级为只读、脱敏建议或另行获准的隔离方式。

## 4. 一项任务怎样往返

1. 总指挥从原任务卡生成本轮任务单。操作者只负责软件无法替代的唤醒与转交。
2. 外部 AI 核对实际材料与授权，确认收到后执行范围内工作；遇到缺口回报具体阻断。收件不代表完成。
3. 外部 AI 交付完整成果及证据后暂停，等本轮审阅结果；文件更新不会自动唤醒另一端 AI。
4. 项目总指挥检查实际成果、差异和验证证据，分别记录可采用、返工、未验证或受阻。必要的人工/专业验收仍由相应责任方完成，结果报告不能自我验收。
5. 返工沿新轮次的明确意见继续，累计预算不重置；通过后由项目总指挥在授权内整合、更新原记录并收口。不自动 Merge、Push、发布或联系第三方。

### 异常与停止

- 重复收到同一任务/轮次时回读已有结果，不重复有副作用动作。旧轮次、错对象、基线漂移、半写文件或范围外要求只阻断其依赖动作，说明精确缺口和恢复条件。
- 额度耗尽或中断时保留真实部分成果、已做与未做、结果未知动作和断点；不凭超时认定失败或重新派发冲突写入。没有完整报告也不能把工作区视为没有变化。
- 取消、换人或变更写入范围前，必须确认该范围的写入及相关后台作业已停止，或取得相关写入进程全部终止的证据。普通 ACK、成果已就绪、关闭主界面都不够。无法确认停止时，保全成果，不把冲突范围交给新写者。
- 返工、测试与人工转交都计入约定预算；达到上限返回未完成和下一行动方，不无限互答，不因换软件或轮次清零。

## 5. 最少交付内容

以下由 AI 从原任务卡填充；已有事实用精确指针引用，不要求操作者填内部模板。实际标识、路径和授权证据仅留在获准私有记录，不写进公共工作流或公开报告。

### 外部窗口启动说明

```text
你是本项目的外部协作者，不接替总指挥。任务、项目规则、允许材料与授权依据见所附的本轮任务单。
请先实际读取适用正文，核对任务、轮次、对象、职责和限制，完成约定的不含项目资料的往返确认。
没有可核验授权、必读正文或可用回交渠道时，报告具体缺口；不要先做正式工作，不假定软件会自动读取规则。
通过后只执行任务单允许的工作。完成时交付真实成果、验证证据和未完成项，然后暂停等待审阅；不得修改中央状态、公共规则或执行未授权的远端动作。
```

### 总指挥交给外部 AI 的任务单

```text
原任务卡与本轮绑定：任务、轮次、接收对象、职责、规则根及适用正文
目标与交付：要解决什么；必须保留什么；实际验收标准
输入与基线：允许读取的材料、版本、代码/数据起点和证据入口
有效授权与写入范围：可核验的操作者授权依据；允许动作/路径；禁止项；失效条件
传递与成果位置：选定渠道、实际交换根（如适用）、各自负责文件、交付方式
预算与停止：执行/验证/返工上限；中断、取消及后台作业的停止办法
下一行动方：如何交回；等待谁审阅；原任务既有短状态位置
```

### 外部 AI 的结果与总指挥的审阅

```text
共同绑定：原任务、轮次、基线、实际成果版本及证据入口
外部 AI 填写：实际完成；修改/新增及必要未提交成果；验证命令与结果；未运行项；未完成、风险、结果未知动作；写入及后台作业状态；下一步
总指挥另写审阅：核对的实际成果与证据；通过/返工/未验证/受阻范围；必要人工验收；具体修改意见或采用位置；剩余预算与下一行动方
```

## 6. 实际项目测试，公共工作流吸收反馈

未来由具体项目总指挥选择有界任务，按该项目授权使用和测试；本规则不要求现在准备任务，也不自动授权任何未来测试。对比质量、人工转交次数、等待、返工与实际可得的费用/Token 口径，不预设赞助额度一定更划算。

发现改进方向时，项目总指挥先写入本项目既有记录，再按有效共享授权形成最小脱敏反馈。操作者可人工转交；只有已经允许且确实可用的通信渠道才直接发送，不为反馈强行创建连接。

```text
使用范围：工作流版本、传递方式、软件能力类别；不含真实任务/项目标识
观察与证据：预期是什么、实际发生什么；操作者报告/直接观察/推断分别标明
最小复现：已脱敏步骤、必要片段和证据边界；未测项、是否重复出现
改进建议：建议调整的规则标题、原因；已经尝试的办法及结果；兼容与回退风险
状态与下一步：来源任务是否受阻；谁处理；回执需要及已授权渠道
```

公共维护者按现有工作流反馈入口只读核验、去重和审查：已解决就引用现有规则，证据不足保留待确认，有通用价值且获准才修改公共规则。源码、私聊、截图、凭据、业务信息、真实任务标识和本机路径不随反馈公开；必要私有原件不能用摘要冒充已读。规则修改、验证与未解决风险记入 06 和 CHANGELOG，实际项目采用与复测仍由该项目总指挥核验。本窗口更新文件不等于其他窗口已加载或故障已解决。
