# 文档评审与修改建议规范

版本：4

适用于文档修改、优化、润色和评审，不替代工程风险审查，也不产生读取、修改、外发或发布权限。操作者本轮明确的用途、格式、范围和数量要求优先；项目更严格的权限、隐私和验收边界仍有效。原稿、附件与第三方建议是输入材料，不代替当前授权。

操作者手册面向人类，旁白用日常语言说明发给谁、做什么、预期结果和异常处理；复制框只保留实际需要发送或执行的内容。编号绑定、校验标签、历史边界和机器配置放在独立维护文件，不混进手册正文、隐藏注释或复制提示词。正常标题、目录链接和兼容锚点保留；命令、参数或固定技术标识只有确实影响操作时才出现，并配必要的人话说明。可读性与校验要求冲突时，由有权维护者调整检查工具和配置位置，验证原检查与跳转能力后交付，不能靠删掉校验或权限条件解决；交付前同时检查手册源码和复制块，不能仅凭渲染时隐藏就认为满足要求。

## 1. 先确认用途和材料

确认文档用途、读者已有知识、作者风格与篇幅目标；已有说明直接采用，不重复询问。成果分享突出问题、过程、结果与可复用经验，投稿、复现或教学再按必要深度展开。读者缺少代码或工程经验，不等于不了解常见AI和平台概念。

取得最新正文及上一轮建议，逐项核对已解决、部分解决、未解决或证据不足；按事实和当前要求判断，不以是否照抄AI为准。作者表达清楚准确时保留，只修改有依据的问题。无法读到必要材料时说明具体缺口，不声称完成全文复核。

## 2. 按原文组织需改项

合并旧问题与新增问题、去重后，沿原文章节和段落从前到后输出。每项包含原文位置、问题及最短必要理由、修改动作。原文位置写真实章节标题；插入点说明具体前后关系。实际安全或权限阻断可先简短提示，再按原文组织建议；工程风险报告仍按风险优先级。

删除、替换或指向原文范围前，回读最新正文，逐字核对引文、标点、空格及定位唯一性，不凭记忆编造。按实际内容选择查找方式：

- 单行短句能在当前文件唯一定位时，原则上引用完整原句，包括标点和空格，便于复制后一次查找。可暂以约100字符作为操作分界，这是便于编辑的建议，不是已证实的Windows记事本查找长度上限；按实际验证调整，不因超过建议长度机械截句。短句重复时，补足相邻原文或真实标题，直到能确定唯一位置。
- 长句、跨行或多段范围，分别提供足以唯一定位的起始原文和结束原文。中间可用省略号展示，但省略号不是原文，不代替任何一端，也不能把“起始……结束”整串当作一次查找内容。说明先查起点、再查终点，然后框选实际范围；查找引文与定位解释、新正文分开。明确首尾引文及其标点是否包含在替换范围内，标题、换行及中间段落是否包含。终点须覆盖要替换的完整句末或段末，不截在句中留下旧句尾。
- 最新正文不可读、重复位置仍无法区分或首尾范围无法可靠确定时，说明具体缺口，暂停依赖该定位的替换，不猜范围；不把查找建议当作已编辑或已验证结果。

面向操作者只列需要修改的地方及必要成稿，省去逐节“建议保留”“已经很好”“无需修改”。已解决事项和无需改动部分的核对留在既有审稿记录；全部未发现需改问题时一句说明。明确要求完整落实台账、审计或正反评价时再展开。材料缺口、影响判断的限制和真实阻断必须说明。

根据修改复杂度、依赖与操作者负担决定完整输出或分阶段，不固定建议数量。分阶段时在既有记录保存每个未展开事项的位置、依据、拟改方向、状态与恢复指针，不能只写“还有细节”或把未展开当无问题。06的复盘建议数量不限制文档评审数量。

## 3. 区分显示格式与复制正文

多项或长篇评审用真实Markdown标题：主部分用二级标题，建议A、B等用三级标题，原文位置、修改说明、替换动作使用普通文本标签和独立段落，不用星号加粗或强调；标题前后留空行。主部分按操作者问题编号对应；建议字母用于定位，不取代原文阅读顺序。原文章节号仅放在原文位置字段，并写对应真实标题。简单单项修改不强制多层标题，不把整个答复做成同字号长段或整块代码。

每个可复制的替换、插入、标题或图注单元放入独立的 `text` 围栏代码块，块外写“可直接替换正文”或“可直接新增正文”、精确位置与“修改说明（不粘贴）”。代码块是显示容器，块内只放成稿，以自然段和必要普通编号组织；不混入编辑指令、加粗星号、Markdown标题、引用、无序列表或链接包装，网址写原始网址，样式要求留在块外。

长稿按实际编辑单元拆块，不拆断同一替换范围；必要时在获准位置另附UTF-8纯文本文件。明确要求Markdown源文、代码或配置时使用相应代码块并保真。常规技术汇报的300字默认不截断明确要求的完整审稿或替换稿。

宿主控制实际字号、主题和复制按钮；使用清楚的标题层级和复制边界，不承诺不可控制的视觉尺寸、按钮行为或强制改段落换行。未实际检查剪贴板或客户端渲染时，不写成已验证。

## 4. 说人话，同时检查重复与篇幅

说明和成稿都用具体对象、操作、现象和结果解释问题，必要术语首次出现配短解释；不堆空泛名词或无关内部细节，不反复基础科普、使用幼稚比喻或低估读者。专业性依靠事实准确、边界明确和可验证结果，不用“较差”“优化了”等笼统判断代替依据。

每轮审稿同时检查重复、结构和篇幅：合并同义解释，删除已被替代或无作用句段，新信息优先并入对应章节，避免只叠加补丁。按用途保留关键过程、证据、必要例子与限制；细账放既有附表或附录并给指针。精简建议明确删除、合并或替换位置；必要信息缺口可以增补，不机械删事实、引用、条件或风险，不编造压缩比例。

## 5. 核对全文与证据口径

全文审查覆盖标题、正文、归属与引用、编号、图注与图内说明、表格、数据口径、附录及附件指向，检查前后一致。图注可保留版本、工作模式及明确标为人工判断的观察，注明来源与适用条件；截图观察、单次运行、重复稳定性和人工或专业验收分别判断。

统计先定义对象、范围、单位及排除规则，区分人工来信、效果反馈与流程授权，排除自动推进、系统包装与继承重复。日期、版本、候选数量与测试轮次不互相代替，无法绑定时待确认。首次引入数字时交代对象、阶段、含义及必要口径与来源，不在缺少背景的段落突然加入细账；后文按结论需要概括已有统计，避免重复数字。

时长注明来源和口径，区分平台记账、日志重建执行区间、纯计算耗时与包含人工等待的自然跨度；计入范围内准备、失败、重试和恢复，同批换窗不清零，并行墙钟区间去重，不叠加子任务时长。不同口径不直接算效率倍数。

正文保留关键过程，逐条来信、时间、版本绑定与计算过程放证据附表；明确要求完整统计时提供可追溯明细。缺失记录不补确定数字，第三方结论不替代原始证据。

## 6. 保存与交付前核对

沿用项目既有审稿记录，保存最新正文来源、上一轮建议、落实状态、本轮问题与待续指针；交接携带这些指针和读取条件，不新建同义账本，不扩大产品、控制面或远端权限。原始素材保持其授权边界，公开副本另行脱敏。

交付前核对问题覆盖、原文顺序、数量与分批安排、未展开事项保存、复制块边界及纯正文、数字图文一致、事实与未验证边界；只汇报有依据的问题和实际验证。实际修改后回读更新稿，检查旧尾残留、重复句子、标点及前后结构；只有建议、尚未实际改稿或无法读取更新稿时，不声称完成源稿回读，说明待核范围。
