# 知乎只读导出：研发与维护记录

应用0.6.7；资料修订2026-11-10.5。面向后续维护者与开发者。它是ChatGPT Workflows中的有限维护开源工具，不是用户数据备份；不包含账号、用户采集正文、截图或其他项目业务。源码采用本仓MIT许可，第三方知乎内容不在该许可的授权范围内。

0.6.6资料修订2026-11-10.4移除了整题选项后重复的“关闭菜单”文字按钮，保留右上角×、两种检索范围及关闭行为；采集、取消、保存和下载逻辑不变。0.6.7补齐双语入口、MIT许可、有限维护说明及持续集成中的离线验证，并修正问题原文未知、跨页层计数变化时的完整性判断，补齐独立楼中楼分页回归；不增加采集请求或权限。原交接ZIP与evidence内历史回执继续绑定原基线；当前文件指纹以本次delivery-manifest.json为准。本地重载读取的是所选目录中的文件，不会从维护者处下载更新。

## 目标与验收口径

在一个问题页或回答页点一次扩展，由使用者选择当前回答或整个问题，取得问题原文、回答及正常返回的评论、楼中楼。避免让使用者学习URL差别、逐篇复制或从仅有初始实体的下拉列表选人。

操作者接受媒体不采集；单篇重点要求楼中楼核齐，整题接受少量回答未返回，举例100篇取得约97篇即可。此偏好不构成硬覆盖率，也没有改写程序严格完整性。程序只能核对已返回范围，不能证明站点隐藏内容或未返回项不存在。

## 架构与数据流

`worker.js`处理手动点击、校验知乎问题/回答URL，将点击时的问题及回答ID绑定后，在页面MAIN环境注入自包含`collector.js`函数。没有常驻内容脚本、定时调度或上传服务。

collector先读取`js-initialData`，显示两个范围按钮。选中前零请求。单篇用URL及同问题实体确认当前回答；整题如从回答页启动，经同一请求门禁读取该问题正常总页，只提取唯一初始JSON脚本，不执行HTML，不切换用户页面。随后读取回答feed、根评论、内嵌及分页楼中楼，校验ID、归属、数量、父链和分页进展。最终生成本机JSON并更新面板。

请求函数是唯一网络门禁：同源、精确路径、GET、拒绝重定向、串行、启动间隔至少1500毫秒、每次20秒或剩余预算较小值，1000请求及20分钟总预算。等待提前唤醒时重查；每次成功JSON后再次核对取消、时间及导航。后台计时器暂停可延迟检查，不是硬墙钟终止。刷新关闭不恢复。

错误策略：HTTP非成功、网络、解析、超时和归属异常全局停止，不重试。只对明确分页重复、未结束或无进展作有限局部处理。最新排序仅在响应明确提供时补查；声明折叠层才读取，不探测审核层。不得添加隐藏接口、换身份、绕过限制或自动重跑。

## 数据契约

schemaVersion=3，exporterVersion=0.6.7。兼容增补字段，不把顶层complete改为“实用可接受”。

| 字段 | 含义及维护注意 |
| --- | --- |
| question | 问题标题、原始detailHtml及声明回答数；缺失或类型异常的文字为null，textComplete=false并在notes保留缺口，明确空字符串不等于字段缺失 |
| answers | 回答、评论、原始HTML、正文和关系变体；去重不覆盖冲突证据 |
| collectionScope | question或single_answer_comments，后者带目标answerId |
| selectedAnswerComplete | 只表示选定单篇严格核齐 |
| complete | 整题严格核齐；单篇模式仍false，不表示单篇失败 |
| coverage | 已取得数量、已处理范围及各回答缺口；returnedScopeProcessed不等于网站全量 |
| requests / diagnostics | 状态、相对时序、类型、数字ID、计数、可见性和内部游标标签，不存原游标、Cookie、头或任意响应体 |
| performance | 等待、网络和处理时间，不能仅凭后台较慢推断具体浏览器节流原因 |
| mediaPolicy | 不下载视频、不转写；图片只保留引用，不核字节 |

数量只接受安全非负整数或纯数字串，未知保留null，不能默认0。评论正文变体、跨组、缺父、环、截断、声明变化均保留；列表声明和评论接口声明冲突也不能悄悄覆盖。正常根评论各页的折叠或审核计数变化时，保留变化notes；后页为0不能抹去缺口。问题文字未知会阻止整题和单篇核齐，已取得的回答和评论仍保留。

正文原始HTML只作为数据，不执行。已知知乎图片域名和唯一8位十六进制source参数表示变化仅记warning；图片路径、其他参数、文字、未知域名及结构变化仍严格保留缺口。比较等价不证明图片字节相同。空正文为empty_unknown，不凭未验证video字段或硬编码回答ID判为视频。

## 验证证据与可复现范围

当前三个纯合成测试共63项：portable40、menu15、text-scope8。直接运行生产collector，伪造网络、DOM和时钟，无真实网站请求。覆盖两按钮、入口组合、正常总页启动、35页单篇、取消竞态、等待取消、停止保存、失败下载、导航、限速、数量未知、变体、原文与隐私；新增7组检查覆盖问题文字未知、明确空详情、层计数双向变化及稳定计数、楼中楼多页补取、重复/失败保全和越源/越路径拒绝。分组包含多个输入反例，不把分组数冒充输入组合总数。

扩展本身没有打包第三方库，仅使用浏览器API。离线检查需要已安装Python 3.9或更新版本及支持node:内置模块的Node；测试使用fs、path、vm、assert等标准库，不需要npm依赖或联网安装。verify-delivery会移除子进程中的COLLECTOR_SOURCE覆盖变量，保证验收本包collector而非环境指定的其他文件。未逐一验证所有Python/Node版本；已执行环境以接收回执为准。基线核验要求固定文件集合，接收方自己的回执应放在包外；新增文件或后续改动应创建新版本清单。

## 已知限制与后续优先级

1. 当前为MIT许可的本地源码工具，未上架扩展商店；不承诺固定维护频率或响应时效。后续公开平台回复、远端写入和商店发布仍按具体授权处理。
2. 新版真实取消、下载异常、干净安装/升级移除及跨浏览器证据仍不齐。正常采集成功不能反推这些均已现场验证；只有明确需求和授权时才补有界验收，不要求使用者重复大题。
3. 任意问题的最低覆盖率、隐藏/已删/站点未返回内容不保证。预算较大的问题可能提前停止，不能通过自动并发或无限重试解决。
4. 未来上游结构变化可能被拒绝或记缺口；以实际样本和失败用例修补，不猜接口、字段或页面DOM。
5. 暂无断点恢复、批量话题采集、视频转写、离线阅读器或内置AI总结。这些是范围排除，不是已授权待办。
6. 任何新版本先建立能暴露问题的最小反例，再必要修补；按影响回归并保持版本、文档、清单和证据绑定。

## 接手、维护与回退

新维护者首个动作：核交付清单，运行verify-delivery.py；记录目录、版本、collector哈希和接收状态。历史来源保留原始证据，当前工具由ChatGPT Workflows维护；工具维护不授予其他项目的调度或业务权限。

维护时保留已接收基线和用户原输入，不reset、clean、覆盖未知变更或改写历史证据。修复只改必要链路，报告真实验证及未验证项。回退加载留存旧源码目录并刷新目标标签，不删除已下载文件。交付清单用于基线核对；后续正式变更需生成新版本清单，不能让旧清单为新代码背书。

推荐按需使用诊断故障Skill建立复现，用humanizer-zh核中文说明；无需安装新工具或重走总指挥接管。独立审查应由不同实例完成，角色不增加权限。所有后续业务实施、发布和通信另核用户当前授权。
