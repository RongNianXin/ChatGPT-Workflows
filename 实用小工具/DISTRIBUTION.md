# 实用工具的独立分发

[English](DISTRIBUTION.en.md)

## 给使用者

从[工具目录](README.md)选择一个工具，下载对应的ZIP，完整解压后按包根的 `START-HERE.md` 操作。无需克隆仓库，也不需要下载其他工具。目录没有下载链接时，表示这个统一包尚未发布；不要把GitHub自动生成的整个仓库源码ZIP当成单工具包。

每包保留必要的原相对目录，例如 `实用小工具/Markdown阅读器/index.html`。这只是包内布局，包中没有其他工具或总指挥工作流。不要单独拖出启动脚本；解压目录以后也应保留。

独立分发仍有运行环境要求。知乎助手需要浏览器，阅读器需要现代浏览器，会话工作台需要Windows和已有Codex数据，任务定位需要Node与Python，续执行守卫需要已有Codex CLI和经授权的任务。具体要求以各包启动说明为准，不自动安装或登录。

下载后可用系统SHA-256工具计算ZIP摘要，与同一发布页的 `SHA256SUMS.txt` 对照。摘要检测传输或文件变化，不是作者身份签名。包内 `PACKAGE.json` 列出其他成员的路径、字节数和摘要；它不包含自己的摘要。

## 维护入口与职责

源码继续在各工具目录维护，运行逻辑彼此独立。本地工具的分发声明放在各自的 `tool.json`；已迁出的工具登记在本层 `external-tools.json`，其指针目录继续只留README。共用 [manage_tools.py](manage_tools.py) 负责验证、目录生成和打包，不执行工具、不访问会话数据、不联网、不退出服务、不发布远端。

| 文件 | 唯一用途 |
| --- | --- |
| `<工具>/tool.json` | 稳定工具ID、分发版本、包修订、显式文件白名单、入口、运行要求和启动步骤 |
| `external-tools.json` | 外部工具的稳定ID、原指针目录及独立仓库，不向指针目录放产品文件 |
| `release-index.json` | 经维护者核实的实际发布回执；与包声明分离，避免循环摘要 |
| `catalog.json`、本目录双语README | 自动生成的最新工具目录；不手工修改，不使用仓库全局latest代表各工具 |
| `<工具>/DOWNLOAD.md`、`DOWNLOAD.en.md` | 自动生成的本工具专属下载、环境和启动页；发布状态留在包外，不进入固定交付清单 |
| `dist/tools/<id>/<版本>-r<修订>/` | 本地生成的ZIP、SHA256SUMS和build-report，不进Git |

在仓库根运行，或从任意目录使用脚本的实际路径：

```powershell
python -B "实用小工具/manage_tools.py" list
python -B "实用小工具/manage_tools.py" catalog
python -B "实用小工具/manage_tools.py" check
python -B "实用小工具/test_manage_tools.py"
python -B "实用小工具/manage_tools.py" build zhihu-export
```

打包只需要Python 3标准库。`check` 检查本地声明、目录与已登记指纹，不代替GitHub发布回读、应用测试或安全审计。`build` 只生成指定工具的新目录，已存在时拒绝覆盖。调整文件后使用新的输出父目录做未发布候选验证；正式发布过的包必须递增版本或修订。

## 单工具页面的交付约定

本约定只适用于实用小工具。对外答疑可以直接提供工具子目录或其README链接，读者无需先打开仓库主页或了解总指挥工作流。各工具的说明页应包含用途与适用场景、不能解决的问题、运行环境、专属下载入口、安装与首次成功的表现、更新及脱敏报错方法；有关个人数据和服务退出的要求按工具明确说明。

README开头链接到自己的DOWNLOAD页，读者在该工具的页面中阅读说明，再进入专属下载页取得ZIP。下载页直接展示当前精确版本和资产，不跳回聚合目录找包；未发布时只显示真实状态。迁到独立仓库的工具保留明确指针，由独立项目负责自己的介绍与分发，不在这里复制第二份产品。

下载页由原工具声明与发布回执共同生成，维护者不为每个工具另写发布脚本。它不随ZIP分发；包内完整使用说明通过稳定的上游地址链接到它，离线启动仍按START-HERE及包内README操作。新增发布回执只更新包外页面，不改变已发布ZIP的指纹。`check`同时核生成页及双语README中的本工具下载链接，禁止把动态下载页列入包白名单。知乎的固定交付检查只豁免根部这两个生成页，其他未知文件仍拒绝。

## 新增、更新与退役

1. 新工具先独立运行，列清入口、依赖、状态存放位置与许可。在直属目录添加 `tool.json`，明确列出每个公开文件；不递归复制目录，不携带个人数据、Office原件、密钥、依赖缓存或运行记录。
2. `files` 只取本工具目录；确需共用的公开脚本逐个列入 `sharedFiles`，打包时复制进同一个ZIP，运行时不回仓库找文件。第三方库及其许可一并列入。已迁出工具在 `external-tools.json` 使用 `kind: external`、`directory` 和独立仓库链接，不生成空壳ZIP；目录只允许README。
3. 应用行为变化按工具自身约定更新版本；只有包布局、文档或依赖集合变化，增加 `packageRevision`。没有应用版本的工具可使用独立分发版本；目录和启动说明必须明确这一含义。
4. 执行 `catalog`、`check`、分发测试，并把ZIP解压到与源码不同的位置，验证自身入口及必要旧功能。每项只读取授权数据；合成测试和真实环境验收分别记录。
5. 发布前冻结文件、记录来源Commit、执行仓库要求的验收和隐私检查，并取得目标、版本和资产清单的远端确认。发布不属于打包命令的副作用。
6. 退役时保留稳定ID、最后可用版本和替代入口，按原有保全规则处理历史资产。单工具停更不阻断其他工具；不要重用已发布ID或覆盖旧资产。

新增直属工具目录既无本地声明、也未登记为外部指针时，验证会失败。已知私有状态与生成目录不作为新工具读取。机器可读目录按ID索引，展示页按声明生成；维护者只改工具声明和必要发布回执，工具数量增加不会要求复制发布脚本或维护上百套CI。

## 发布命名与回读

每个工具分别使用以下标识：

```text
Tag: tool-<id>-v<version>-r<packageRevision>
ZIP: <id>-<version>-r<packageRevision>.zip
```

每次只发布有变化的工具，互不捆绑版本。每个Release放本工具ZIP和 `SHA256SUMS.txt`，说明运行要求、变更、已验证/未验证项及有限维护边界；预览版标为prerelease。不依赖仓库全局“Latest”决定工具的最新版本，使用聚合目录的精确Tag链接。既有历史Release保留原状。

实际发布并回读Tag、来源Commit、资产名及下载字节后，才把回执加入 `release-index.json`。每条包括 `id`、`version`、`packageRevision`、`tag`、`asset`、`sha256`、`sourceFingerprint`、`sourceCommit`、`prerelease`。回执索引不进工具包，加入回执不会改变ZIP。历史回执保留，目录只显示与当前声明匹配的那一版。

正式发布的包必须从固定Commit的干净隔离检出生成，并将该检出的 `core.autocrlf` 固定为 `false`，遵守仓库已有的精确字节属性；核对输入与提交一致后重新打包、解压并验证，再上传该份新产物。普通工作区包只是候选，不能直接声称来自一个干净Commit。当前脚本保留源字节，不改换行；LF/CRLF导致的摘要差异不等于功能变化，但也不能跳过字节绑定或覆盖旧资产。工具迁为external后，已登记ID的历史回执仍可保留，不再参与当前本地包绑定；未知ID仍拒绝。

回执是维护者核验记录，本地脚本无法证明远端当前仍存在或未被替换。公开下载可用性必须由发布阶段回读，不把填入URL当作已发布。本轮只建设本地分发能力，不新增后台发布、商店安装、自动更新或服务。

## 安全与验证边界

白名单路径拒绝越界、链接和Windows重解析点、私有状态目录、常见密钥与Office原件。输入单文件上限64MiB、合计512MiB；输出只允许本仓库 `dist/` 或 `.planning/`，不能覆写已有包目录。源文件读取前后检查变化，并在组包后复核已读字节；维护和打包期间应停止并行修改候选。它不是对抗恶意同账号进程的操作系统隔离。

固定成员排序、时间戳和权限，使相同输入在同一打包环境下产生相同ZIP。不同Python或压缩库版本可能改变ZIP字节；发布回执以实际发布字节为准，不能只凭应用版本相同断言两个包相同。文件摘要证明内容一致性，不证明软件没有漏洞。

CI只验证声明、目录、打包反例和已有工具检查，不创建Tag、Release、部署或下载个人数据。后续如确需自动发布，应复用此入口，再单独核权限、审批、版本不可变和发布回读；当前没有启用。
