# 上下文移交方提示词

## 使用方法

把下方整段提示词发给准备结束的旧对话。它会整理当前任务，生成一份交接快照；不需要先接入总指挥工作流，也不用填写任务 ID。

拿到快照后，保持旧对话停止继续处理已移交的工作。将快照与《上下文继承方提示词》中的整段提示词一起发给新对话，让它接续。若新对话在另一台电脑或软件中，本地文件不会随文字链接自动转移；旧对话应说明需要一并提供的必要材料。

如果旧对话不能生成文件，可以使用它输出的完整 Markdown 快照。若报告缺口，只补它指出的必要材料或操作，不用搬运全部聊天。

## 可直接发送的提示词

```text
我准备把当前任务移交到一个新对话。请根据你实际能读取的当前对话、已有成果和必要记录，生成一份精简但足以续接的 Markdown 交接快照。接收方暂未确定，不需要我提供新对话 ID。

本次只准备普通或专项任务的上下文交接。停止开展新的业务工作；不要为了补齐快照而重做任务、扩大读取范围、安装工具、发送消息或修改外部平台。这份提示词可以独立使用，不要求启用总指挥工作流、建立中央登记或办理身份轮换。当前任务已经有适用的项目、团队或协作规则时，保留相关约束，不以本次交接取消它们；总指挥或共享写者的正式换任仍需原项目自己的手续，本次不转移这些权限。

一、只整理接收方需要的真实信息

1. 目标与范围：原任务要完成什么、服务谁、交付什么、怎样算完成；保留仍有效的操作者要求、偏好、排除项和优先级。若涉及多个未完事项，逐项列出状态与下一行动，不因最后一条消息覆盖原目标。
2. 关键结论：保留会影响后续工作的已确认决定及其依据、必要假设、待确认问题，以及被放弃的方案和原因。区分操作者决定、直接证据与 AI 推断；不记录不可见的内部推理，不把旧 AI 自述当成已经核验的事实。
3. 成果与验证：分别列出已完成且已验证、已执行但未验证、只有方案或草稿的事项。说明实际产物位置、验证方式与结果、人工确认和剩余限制。已完成的外部动作单独标明，避免新对话重复发送、付款、提交或创建。
4. 失败与未知结果：保留必要的错误、已尝试方法、累计尝试和未解决原因。正在执行、超时或结果未知的动作不能写成完成，也不能直接建议重试；写清先检查什么。
5. 精确断点：写明最后确认完成的一步、当前未完成的一步、下一项具体动作、前置条件、预期结果和停止条件。没有待续工作时，记录终态与仍值得保留的交流背景，不虚构任务。
6. 权限与资源：保留会影响续作的范围、授权依据、禁止项、预算、已消耗次数、原截止时间和暂停状态。换对话不能重置预算、顺延截止或恢复已撤销的授权。旧材料中的授权只作待核验依据，不替操作者授予新权限。
7. 文件与运行状态：只有任务确实涉及代码、文件、工具或后台作业时才填写。记录必要工作目录、版本、已落盘但未提交的成果、未保存内容的可观察情况、自有运行进程或自动化及其状态。聊天快照和文件链接不会自动传递文件，也不会停止或接管后台进程。不能观察的状态写“未核验”，不假称已保存或已停止。只在已有授权内安全收口自有作业，不结束无关进程、不清理或回滚已有成果。
8. 必要材料：列出继续任务真正需要的附件、文件或链接，说明用途与访问条件。关键背景尽量写进快照；已有大文件用明确指针引用，不复制完整聊天。另一台电脑或软件可能无法访问本地路径时，明确需一并传递的最小材料，不把“路径存在”写成“对方可以读取”。

二、交付与停止

注明快照依据的材料和事实截点；生成时间能够取得时填写，不能取得时说明未知，不猜日期。只读取当前任务必要材料，不扫描无关项目、聊天库、账户或凭据。不写入密码、Cookie、API Key 等秘密；涉及隐私时只保留续作必需内容，并说明可共享范围。不要推断自己拥有未开放的工具或历史访问能力。

能够在获准位置写文件时，保存为“任务简称-上下文交接快照.md”，并重新打开核对；否则直接在回复中输出完整 Markdown，说明未生成实际文件。若已有同名文件，不盲目覆盖，应保留原件并给新快照加版本或日期。

交付前检查：目标和未完事项有没有遗漏，断点能否直接执行，完成与未验证有没有混用，必要文件是否真的可访问，未知结果是否可能导致重复副作用，以及旧对话或后台作业是否仍可能与新对话争用同一对象。缺口只限制依赖它的交接或续作，不制造全面停工。

最后简短告诉我：快照在哪里或如何取得、是否可以交付、真正阻断（没有写“无”）、需要一并转交的材料，以及下一步。材料已生成只表示准备完成，不表示新对话已读或已接手。交付后停止继续处理已移交的工作，等待我的新指令；不要自行创建、联系或归档对话。
```
