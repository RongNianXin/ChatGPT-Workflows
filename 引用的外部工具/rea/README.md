# EXT-004：REA

[English](README.en.md)

## 它是做什么的

REA（Reverse Engineer Anything）让 AI 或终端通过统一接口检查软件制品、追踪具体实现并保留分析证据。它提供 CLI（终端命令）和 MCP（AI 工具接口）；原生程序的深入分析还需 Ghidra、Hopper 或 IDA 等对应引擎。它不是一键恢复原始源码、完整工程或克隆产品的工具。

- 安装状态：`NOT_INSTALLED`；本次没有安装、注册 MCP、安装上游 Skill 或运行 REA，也没有证明其他机器已可调用。

- AI 按需入口：[`调用指南.md`](调用指南.md)；状态与验证边界：[`安装与维护记录.md`](安装与维护记录.md)。

登记后，已加载新版工具目录和共同选择规则的 AI 可以按当前目标发现并评估 REA，不需要操作者记编号或命令。登记不等于已安装、已调用或所有旧窗口已采用；本次没有广播或远端发布。

## 你只需要怎样说

直接描述想做什么、想弄清什么即可，例如：

> 我想做一个塔防游戏，但不知道怎么设计。请先研究同类游戏的公开资料和我提供的材料，帮我形成一份原创游戏设计书。你判断是否需要 REA，负责选择方法和填写可靠参数；缺少关键事实再问我，超出现有权限的操作先说明。

AI 应先把目标拆成可回答的问题，而不是让操作者先学会逆向。写设计书通常先研究玩法、关卡、反馈、经济与玩家决策；只在需要查明具体实现、已有可分析制品且权限齐备时，才考虑 REA。未安装 REA 不阻断不依赖它的策划与资料研究；操作者明确把 REA 实际分析列为验收条件时，不能以其他方法冒充已使用。

预期结果是带依据和未知项的分析，以及区分观察事实、推断和新设计的交付物，不是原产品内部设计书。若 AI 声称已经使用，请让它回读本次调用和结果证据；缺工具时由 AI 给出具体缺口和最小准备范围，不要求操作者拼装命令。

## 什么时候用，什么时候不用

| 当前问题 | 建议路径 |
| --- | --- |
| 想做同类游戏、理解玩法或编写设计书 | 先做公开资料与可观察行为研究，必要时由领域策划辅助；不默认逆向 |
| 想确认某个反弹、弹幕、文件格式或客户端模块的实现 | 有合法样本、对应能力和权限时，考虑 REA 的定点制品分析 |
| 想检查 JavaScript/Electron 模块或 .NET 元数据与 CIL | 按目标类型检查静态路线，不必一律安装原生引擎 |
| 想恢复整套开发工程、服务器实现或受保护资产 | 不承诺；先说明客户端材料和工具能力的边界 |

## 使用前必须知道的边界

- 安装、静态分析、运行目标、附加进程、抓包、设备操作和原始结果外发分别核权；没有工具能力不自动安装，也不把工具可用性当作授权。
- 本地分析不等于数据永不出机：结果交给云端 AI 时，代码、流量或个人数据可能进入模型服务。先核数据范围和允许的接收方。
- 编译后的程序可能缺失原始名称和结构；伪代码、静态调用关系和工具退出成功都不能代替真实行为验证。
- .NET 静态检查不解码 IL2CPP 元数据，不能泛称支持所有 Unity 游戏；也不承诺自动恢复 Unreal 工程。
- Windows 原生 Ghidra 路线仍是实验性 P0，有主机、文件系统、格式及依赖限制；详见上游[Windows 支持说明](https://github.com/morluto/rea/blob/rea-agents-6.4.0/docs/windows-ghidra-p0.md)。
- REA 的 MIT 许可不授予目标软件、资产或商业分析器的权利。合法持有副本不等于获准全部分析和复用；不得据此绕过 DRM、许可、反作弊或未授权访问控制。

首次使用宜选有权分析、可对照源码的受控小样本。CLI 适合一次性检查；持续追踪同一目标可考虑项目限定的 MCP。独立安装目录不是安全沙箱；不可信目标的运行需另核隔离条件。
