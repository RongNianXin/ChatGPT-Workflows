# RTK：终端输出整理

[English](README.en.md)

编号：`EXT-005`。RTK 把命令输出整理后交给 AI，适合快速浏览重复日志；它不是更聪明的模型，不保证整项任务更快或费用按同一比例下降。发现入口为[通讯录](../外部工具目录.md)，共同权限与接入规则沿[统一规范](../外部工具自动对接规范.md)，版本和实测范围见[维护记录](安装与维护记录.md)。

## 适用范围与调用

操作者只需说：“这次终端输出很多，请判断是否适合用 RTK，保留必要证据。”AI 自行核目标、原命令授权、已安装实物、版本和过滤器适配，不让操作者拼命令。简单短输出直接用现有工具；没有收益证据时不强制包装。

Windows 已有安装时，先用 `Get-Command rtk.exe` 和 `rtk --version` 核实。当前约定的便携位置可在运行时从 `$env:LOCALAPPDATA` 组合 `Programs/RTK/1.1.0-oss/rtk.exe`；路径存在不等于版本或哈希有效，实际安装证据仍从本地维护记录核对。新终端可继承用户 PATH；已有宿主未继承时可用已验证绝对路径，不要求为当前任务重启软件。未安装或版本失配时沿原命令安全继续，不自动安装。

已核显式形态包括 `rtk git log -3`、`rtk git status --short` 和 `rtk run node --version`，但真实项目每次仍须核底层命令的配置、过滤程序与副作用。`run` 可以仅透传，不代表有压缩；Git状态摘要不代替完整路径库存，短提交输出不代替完整提交身份、精确时间、授权或原始提交正文核验。不绕过本工作流既有 Git/LFS 门禁。

`rtk test node --test` 在已测版本不能可靠保留测试总数、通过数；切换 TAP 格式也不解决，当前不用于测试验收。不将此结论扩大成其他测试生态都不可用，也不为通过验收而安装新测试工具或伪装命令名。未测过滤器先限范围验证，不给所有命令统一加前缀。

## 安全、证据与退出

- 包装不改变底层动作的授权要求；不自动包装写入、删除、发布、网络请求或其他受控动作，不通过自动重跑来取回日志。
- 完整规则、原始要求、身份、结构化协议及必须逐字读取的证据不用有损摘要代读。摘要不足时读取原有原始日志；关键任务在首次运行时按已有日志机制保全原文，不为使用 RTK 重复执行可能有副作用的命令。
- 遇到真实提示 `rtk recall <HASH>` 时，用 `rtk recall <HASH> --full` 取完整已存输出；默认回取可能仅返回尚未显示部分。无提示不编造 HASH。恢复库有大小限制、可能不可写或未存成功，不能当作永久原件备份，也不能据摘要省略就断言原文不存在。
- 当前采用显式调用，不执行 `rtk init`，不注入全局 AGENTS、Hook、命令别名或审批放行。当前工具接口与上游 Bash Hook 输入不同，宿主映射未实测；不承诺 PowerShell/Codex 透明改写。
- 遥测已配置关闭，但v1.1.0的历史关闭配置在部分已测路径无效：仍记录命令、工作目录、时间和估算用量，并按上游固定期限清理旧历史。已改用新的专用历史库，隔离后验证原默认库字节未变；首次调用前未捕获默认库原状，不能追溯证明其旧历史零影响。不将历史库当作原始证据档案；恢复库另行配置不按年龄或条数淘汰，也不等于永久原文备份。记录可能含私有信息，不能公开。
- 停用只需不再用 RTK 前缀；用户 PATH 仅移除本次新增片段即可撤销命令发现，不覆盖其余 PATH。保留安装、配置及证据，不需要删除业务文件或运行上游卸载器。

可观察输出应包含：原命令范围、实际包装方式、退出码、关键结果、原文入口、未观察内容与下一行动方。当前仅保留无敏感合成验证，正式业务接入暂缓；待历史记录及保全控制验证有效后再评估，不能仅凭配置文件写着关闭就放行。跨项目、新窗口实际发现、其他系统及真实总 Token/费用收益仍待实测。当前 Node/Git 子进程方案不在 iOS 本机运行，不因此改变历史纯文本工作流的可用性。
