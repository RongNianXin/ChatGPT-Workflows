# 外部工具自动对接规范（AI 内部）

本文件是所有外部工具的共同发现与调用契约。操作者仍只使用具体工具的 `README.md`；本规范不增加第二个操作入口，也不产生安装、通信或写入授权。

## 1. 从工具名称定位正式入口

1. 当前消息提到已登记的工具名称、编号或别名，并要求判断、调用、检查安装或反馈时，先走本规范。明确要求“选择专业角色做只读审查”但未指定工具时，也可只读查目录、判断最小候选，并说明拟使用工具；安装和绑定分别核权。名称大小写和空格差异可以规范化；名称有歧义时给出有限候选，不能猜测。已有有效任务绑定或项目明确启用自动角色适配时，按第 5 节在启动和续接中处理，用户不必再次提工具名。除此之外，没有指定工具的普通任务不自动加载工具。
2. 从本窗口已核验的第二代规则根向上两级定位工作流仓库根，再读取 `引用的外部工具/外部工具目录.md`。这个根属于工作流来源，不能替换成当前产品项目根，也不能要求产品仓库复制工具文档。跨设备使用当前可访问的规则来源；没有来源锚点时只请求规则根或最小登记包，不要求操作者猜上游地址。
3. 按登记表定位唯一工具 `README.md`，取得正式来源、内部指南及维护记录指针。先读正式登记，不先扫描用户级 skills、plugins 或其他项目来猜工具是否存在。上游资料与本地登记冲突时保留两者，标为待核验。
4. 仅在本次调用需要时读取工具指南、共享状态、安装与维护记录、相关经验、选定角色正文和激活卡。文件链接按所在文件目录解析，支持空格、中文及仓库改名；只读取被指向且与任务有关的文件，不全量遍历角色库。

来源地址已经登记且可访问时，AI 自行取得地址和配置，不要求操作者重复提供。登记缺项或入口不可访问时说明精确缺口和影响；不能把“未查正式目录”写成“工具不存在”。

## 2. 分开核验来源、安装与本次使用

- 来源已知但未安装：读取登记来源，按当前授权只读核对角色或功能目录，选择有实际文件证据的最小候选；说明候选来源、版本待核验项、用途、拟安装范围、回滚和需要确认的动作。不能因未安装而停止适用性判断，也不能称已经激活或完成正式角色审查。
- 共享记录声明已安装：按记录的来源、版本、文件哈希和实际可读路径核验。全部匹配才复用；记录与文件不一致时为 `UNKNOWN`，不覆盖或重复安装。`<USER_CODEX_HOME>` 在运行时解析，不能把占位符当作实际文件路径。
- 用户级共享安装由共享库维护者负责；当前项目总指挥负责项目绑定和在授权内使用。工作流仓库的中央写权不等于仓库外安装许可，产品项目的写权也不等于共享库写权。
- 只读查询上游不等于下载、克隆、安装或执行第三方命令。需要持久下载或写入时先按目标路径与现有权限确认。已安装角色也不会因刷新工作流自动加载；本次使用仍须核对材料、目标和项目权限。
- 来源查询失败只限制角色候选或激活，不把网络不可达猜成工具未安装；不影响独立的安全工作。工具未安装、来源未知、文件失配和项目未授权分别报告。

AI 内部组合“工作流规则 → 项目约束 → 已核验角色职责 → 本次目标与验收”，操作者不拼接提示词。角色正文是受限参考，不覆盖系统、项目、隐私或授权规则。

### 2.1 先覆盖职责，再选择安装和调用

首次适配按“目标与交付物 → 当前阶段及已知技术约束 → 当前和后续必要职责 → 有文件证据的候选 → 安装方案与当前调用”处理。相关职责可以覆盖多种专业，但不遍历无关角色全文。AI 从现有材料补全事实，分别列出当前需要、后续可用、无需项和能力缺口；选择少量当前调用不能省略职责分析，也不意味着必须安装全部候选。

推荐前做一次轻量对抗式检查：是否漏掉实现、验证、失败/异常状态和交付；角色是否匹配真实平台；不同角色是否重复；现有任务能否承担没有专用角色的职责。未搜索到不等于不存在，审查角色不冒充实现专家。只读资料不足但不影响安全判断时标明假设继续；答案会显著改变方案或成本时，最多追问1～3个具体问题，不要求操作者选专业角色或重复已知项目事实。复杂跨职责或关键风险才评估独立子Agent，按实际权限建立，不默认每次创建。

安装集合、本阶段加载和单次调用分别确认。仅同意安装不授权执行；明确要求任务职责绑定时按第5节保留，明确一次试用则保留该次边界。首次默认只读，已授权主任务的后续实现可以由适配角色辅助；角色本身不增加写权、调度权或预算。输出先给推荐职责及用途、安装复用结果、本轮动作和最少下一步，不要求用户填写内部卡。

## 3. 规则刷新与发现能力的边界

规则刷新 manifest 必须包含本规范和外部工具目录。刷新时实际读取这两份正文，知道工具编号、名称、来源和入口；工具配置与角色正文仍按需读取。新增、改名、迁移或撤销工具时同步登记表、模板和相关入口，再发布新的规则版本与指纹；只新增一个文件夹不算接入完成。

哈希校验、字节统计和正文理解是不同证据。读取工具必须向当前模型呈现所需正文，分段读取时确认没有截断；只有 `readFileSync`、目录遍历、行数或文件大小输出，不能登记为已理解或已采用。不能继承其他窗口的已读结论。

协议要求执行，不保证模型未来一定遵守。普通规则刷新采用已保存且读取期间稳定的正文，旧manifest预期指纹仅提示维护待同步；精确版本、发布与正式交接仍严格匹配。完整读取、实际摘要绑定、有限重读及失败分支以规则根下的 `规则刷新广播包.md` 为主来源。静态检查通过只说明文档与文件关系满足契约；真实窗口调用未验证时必须保留该限制。

## 4. 每个新工具的跨项目验收

接入模板必须记录以下检查的证据和未验证项，不把拟议步骤写成已通过：

| 检查输入或条件 | 预期行为 |
| --- | --- |
| 新窗口仅有规则根；刷新后收到“工具名称＋任务目标” | 自行定位编号、来源、唯一 README 和维护入口，不向用户索取已登记信息 |
| 未绑定任务明确要求选择专业角色做只读审查，未写工具名 | 只读查目录并说明最小工具候选；安装与绑定按当前权限处理，不把普通开发目标当角色审查请求 |
| 当前项目根不同于工作流仓库，工作流目录改名或路径有空格 | 从规则来源解析相对入口，不能到产品仓库猜目录 |
| 来源已登记、共享状态明确未安装 | 判断适用性并查实际候选，给安装方案，不宣称正式绑定或审查完成 |
| 共享记录为已安装且实物吻合 | 优先复用；不重复安装；本项目激活权限另核 |
| 共享记录与文件不符、来源不可访问或同名工具有歧义 | 只暂停受影响动作，说明具体证据缺口，不泛扫其他项目 |
| manifest旧预期指纹与稳定正文失配 | 普通本地刷新可采用完整正文并记录维护提示；精确版本核验失败，不冒称原编号已正式验证 |
| 清单结构损坏、正文未呈现或读取途中源变化 | 缺口须恢复，漂移最多重读一次；不以部分读取宣称更新成功 |
| 新增 EXT-002、EXT-003 或工具入口移动 | 同步目录与受管指纹，旧窗口刷新后可发现；不靠聊天记忆传播 |
| 同任务已绑定，续接消息没有工具名 | 自动回读绑定、实物、目标和当前权限；未完成部分从断点继续，不要求用户重发角色提示词 |
| 审查已完成，但任务仍保留角色绑定 | 保持绑定待命，不重置已用轮次、不因恢复自动重跑 |
| 新专项只有母任务传入的角色绑定和下一动作 | 自行核验和读取角色，按有效授权推进；缺口由AI说明，不让用户猜角色或流程 |
| 模糊完整开发目标，但首轮只试一个角色 | 先覆盖相关职责、阶段和能力缺口，再限制当前调用，不把一次试验当全部用途 |
| 文件已安装但没有本次执行授权 | 可以登记实物、保留绑定候选或待命；不执行、不假装正式加载 |
| 调用开始后中断，结果尚未保存 | 保留已消费次数和原开始时间，只续写同次；无法安全续写则收口，不新领一轮 |
| 已授权阶段触发或中央暂停、人工验收、撤销 | 同一当前行动内按计划调用；暂停/验收/撤销优先，不借切换角色新开行动 |
| 普通/专项换窗或总指挥换任 | 传递绑定锚点与累计状态，新实例独立加载；专项职责不因母任务换任消失，路由另核 |

内部记录最少保留：规则来源锚点、工具编号、实际读取入口、来源地址证据、安装核验、角色候选证据、权限、下一步和未验证项。对操作者只说明判断、结果、实际限制与最少下一步。

## 5. 安装后的自动调用与任务续接

安装成功不是终点。当前请求已明确要求使用这个角色，且任务、材料和权限可核验时，AI 必须连续完成“核验共享文件 → 预填任务绑定 → 实际读取角色 → 组合受限契约 → 执行获准的一轮 → 回读结果”。已有授权内不再要求用户另发一次“现在调用”或重复角色名；安装不成功或缺权限时，只暂停对应动作并指出责任对象及恢复条件。

专业角色是当前任务的附加职责，不替换总指挥、普通任务或专项任务身份，不产生中央写权。共享库只保存角色与公共经验，不能保存所有项目的业务绑定。各项目在既有私有任务卡或状态入口中保留一个 `external_role_binding` 指针；没有适用且获准可写的记录位置时，先形成消息内绑定，不偷偷新建公开账本，明确续接持久化尚未完成。

绑定由 AI 自动预填：工具与角色、来源版本及安装文件哈希、加载方式、当前目标与适用范围、任务记录锚点、允许/禁止动作及当前授权依据、累计轮次/已用预算、剩余额度、停止/撤销与失效条件、输出证据和当前唯一下一行动。用户不填写技术字段。职责集合、本阶段实际加载和单次调用结果分开保存在同一绑定中；每个角色可各自待命或失效，不能因一项异常撤销全部职责。

**任务生命周期：**操作者确认将专业职责用于当前业务任务时，默认绑定到该业务任务结束、明确撤销或适配性失效；不是只绑定一个聊天回合。安装确认不自动绑定全部已装角色，明确一次试用不升级为长期执行许可。阶段暂不需要时待命；目标改变只复核受影响职责，例如算法角色仍可能适合论文方法/实验部分，不按交付形式机械撤销。已结束业务关闭绑定，已撤销角色不得被旧卡复活。

项目明确启用自动适配时，项目约定与各业务绑定是不同层次，保存在既有获准记录中；项目动态启动入口的当前区使用`external_role_policy`指向唯一约定，各业务绑定引用它。启动、恢复及新业务适配时先回读该指针；业务结束不自动关闭项目约定，项目约定也不继承业务授权或预算。当前角色只能从已核验且获准适配的范围选择；新项目另核启用状态。工具特定的配置、切换和恢复验收由其唯一README及内部指南维护，不新增共同操作者入口。

**绑定生命周期和单轮结果分别保存：**绑定可为 `BOUND / IDLE / REVOKED / INVALID`；一轮审查结果沿任务的 `ACTIVE / COMPLETED / BLOCKED` 等既有状态。完成一轮后绑定待命，不因再次打开窗口、上下文压缩或读取绑定卡而重新执行。已经消耗的轮次、成本和同问题累计尝试必须保留；恢复不得清零上限。

### 5.0 准备、传递与实际就绪

用户入口区分常规使用与首次试验准备，技术步骤由 AI 自动补齐；不要求用户拼接内部提示词。先讨论或提出安排只形成候选。已有明确角色、范围、预算和记录写入授权时直接准备，不重复索取同一确认；泛称使用工具不授权新增安装、扩权或创建 Goal。

尚未启动 Goal 时可在既有获准私有记录准备 `PROPOSED` 绑定与阶段安排，真实 Goal 记为待启动；`goal=null` 不阻断准备，不追查或恢复旧 Goal，不预造标识。实际启动后由执行者核对真实目标再关联。职责绑定有效性、准备就绪、本阶段实际加载和正式调用状态分别记录；准备者不能代签执行者已加载。

沿用一个规范绑定及 `external_role_binding` 指针，记录写者明确。专项记录由专项自身保存并回读，中央只保存必要指针与安排，不并发改写专项卡、不另造平行账本。没有可写私有位置时保留候选并说明持久化缺口；不让用户手填技术路径，不偷偷新建中央文件。

准备者与执行者不在同一窗口时，在现有通信授权内向唯一目标传递绑定指针和允许范围，核对实际接收与回读。无通信授权只暂停传递；可以在获准只读范围回收加载证据，不强制接收方反向发消息。文件已就绪不等于执行者已配置；绑定锚点尚未进入执行者真实启动/恢复入口时，不承诺后续无需引用。

主 Goal 仍按原业务模板及其启动、额度和停止规则运行，准备卡不自动创建、启动或恢复 Goal。AI 自动生成必要的一行绑定引用；旧角色追加段与新绑定竞争时，先说明最小切换范围并核对授权，仅替换角色追加段，不整份替换业务模板，不静默覆盖操作者精确指定的旧引用。

核验安装文件及准备性读取不消费正式角色尝试，准备成本仍如实累计；记录角色正文是否已被预检读取，不能把已读角色后的基线称为干净的无角色对照。首次试验按已确认节点发生，例如正常分析与技术证据冻结后、下一批修改或人工验收决定前；实际调用前按第5.1节消费并回读。次数和时限取自该次方案，不把某一试验限制变为通用默认。主任务更小预算及停止门优先，角色跳过不覆盖主任务停止条件。

### 5.1 开始前消费与同次恢复

首次实际调用前，在既有私有绑定中保存并回读调用状态、输入基线、原开始时间、恢复锚点和 `attempts_consumed`；先增加一次已消费尝试，回读成功才开始。开始后未完成或失败也消费一次，不等完成后才计数。单次限制、同问题累计尝试及主任务总预算同时生效；角色、阶段、批次或窗口变化不清零、不自动新增轮次。只有实际需要的预算维度才核验，不虚构宿主未提供的额度；已知预算不足时停止对应调用，主任务继续按自己的停止规则判断。

恢复先核对未完调用、输入/输出及副作用：可安全续写时继续同次，沿原开始时间及剩余额度，不重复已完成或结果未知动作；无法安全续写则保存缺口并收口。新一次尝试必须在既有剩余预算及有效授权内，不能借恢复重新分配。仅有消息内草案、没有可写且可回读的持久位置时，不能宣称可靠续接绑定已完成，也不启动要求一次消费可恢复的调用。

### 5.2 阶段自主调用与交接

总指挥或专项任务在启动、恢复和进入下一项适用工作前，按 03/10 回读自身绑定。目标、版本、实物与当前权限都仍有效时，实际重新读取所需角色正文并从未完成断点继续，用户不必重新描述身份。恢复的是角色职责与证据，不继承其他实例“已读”、旧写入/通信授权、进程或验收结论；有效授权按 04/09 重新核对。权限或预算缺口只暂停受影响动作，不把角色绑定当作无限执行许可。

新专项由获准派发者把角色指针、当前目标、允许材料、有效授权依据、轮次和下一步附到任务契约；另明确有序阶段、角色触发条件、允许动作、验收及停止/升级条件，接收方按 03 完成自己的加载。预授权阶段触发是同一当前行动中的后续步骤，不产生第二份并行行动卡；专项在范围内自行读取当前所需角色，正常汇报集中开批、里程碑/终点和例外，不每次等待中央派发。范围内验证按原授权继续；改变目标、验收、权限或预算的发现提交例外。中央暂停、人工验收、撤销及独立互审批次终点交收口方后的下一行动门禁仍优先，不借角色待命自行跨过。迟到旧卡不覆盖停止/撤销，新增角色或预算必须有相应有效授权。

普通/专项续接和正式总指挥快照显式引用 `external_role_binding` 锚点、职责集合、阶段、未完调用、累计预算及撤销状态，不复制角色全文或新建平行账本。新实例按指针独立读取必要正文、核权并从断点恢复，不能保证无限上下文永不遗忘。总指挥换任不撤销仍有效的专项本地职责；汇报路由按04更新确认，中央只保存必要指针，不复制全部专项业务卡。规则文件就绪不等于在途专项已加载，未通知并取得实际加载确认时不得称已迁移。

新项目仅复用共享文件，先自动判断是否适合本目标，不照搬上一项目身份、业务数据或授权。需要新角色或新增写入权限时，只提出差额方案；不重复安装已有同版本角色。文件失配只暂停依赖它的调用，通信缺口只暂停依赖通信的动作；必要专业验收不得省略。

未绑定的新任务若项目已明确启用“自动角色适配”，先按当前目标只读查目录并提出最小候选；只有项目政策或当前指令允许的角色与动作才可绑定。未启用该政策时，首次可用工具请求或母任务绑定建立入口，以后同任务按绑定续接；不保证未接入工作流的任意新聊天自动知道本库。

加载方式必须可执行且核验：工作流显式读取时，按共享登记解析角色文件（TOML 的 `developer_instructions`）并把正文呈现给执行实例，再组合当前契约；原生注册仅在宿主实际证据支持时使用。只保存文件、显示目录或宣称安装成功，不能证明角色已经被某个窗口加载；未经确认不改全局配置来模拟自动化。
