## 7. 跨项目自动对接验收（AI 填写）

按 [`外部工具自动对接规范.md`](外部工具自动对接规范.md) 第 4 节逐项记录。复制到工具子目录后，将此链接改为 `../外部工具自动对接规范.md`。

- 新窗口输入：仅提供规则根与“工具名称＋当前目标”，不另给工具网址、安装命令或角色名。
- 来源发现证据：规则根 → 登记表 → 唯一 README → 维护与配置入口。
- 不同项目根、工作流目录改名及含空格路径：
- 未安装、已安装复用、记录与文件失配：
- 上游不可访问、角色名称待核验、项目权限不足：
- manifest旧指纹（普通刷新维护提示 / 精确验收失败）、正文未呈现、刷新时源变化：
- 实际验证方式与结果（静态 / 文件回读 / 真实窗口）：
- 安装后连续调用：当前请求已要求使用时，核验后自动绑定、实际读角色并执行，不让用户另发一次调用指令。
- 任务启动与续接绑定：项目既有私有记录指针、专业职责叠加原身份、当前权限重核、累计预算和唯一下一动作。
- 任务长期职责、阶段实际加载与单次结果分开；同一业务任务确认绑定默认保留，明确单次试用不升级权限。
- 开始前持久消费/回读、原开始时间与同次恢复：按共同规范第5.1节，失败/未完成也占一次，换阶段/批次/窗口不清零。
- 专项按预授权有序计划触发，同一当前行动内连续执行；中央暂停/人工验收/终点收口门优先，规则就绪与专项实际加载分开。
- 普通/专项/总指挥交接显式携带绑定锚点、职责、阶段、未完调用、累计预算和撤销状态：
- 没有工具名的同任务恢复、已完成审查不重跑、新专项接收绑定、跨项目不继承旧权限：
- 未验证项与恢复条件：

静态检查不能代替真实窗口验收；未试用时仍可登记，但不声明跨项目自动调用已经验证。
