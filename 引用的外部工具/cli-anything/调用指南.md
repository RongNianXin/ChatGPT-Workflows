# EXT-002 调用指南

本指南供总指挥按需读取。操作者只需提供目标；工具发现、安装核验、权限组合和结果收口仍按本仓库的共同外部工具规范执行。

## 1. 先分清两条轨道

| 轨道 | 解决什么问题 | 主要副作用 |
| --- | --- | --- |
| CLI-Hub 消费端 | 查找、安装、更新、卸载和启动已有 harness | 网络、用户目录、依赖和目标软件安装变化 |
| Harness 生成端 | 为有源码或稳定后端的目标软件生成/优化/验证新 CLI | 读取源码、生成代码和测试、调用真实软件、可能安装到 PATH |

“有现成工具”不等于“本项目已安装”；“能生成”不等于“生成结果可靠”。

## 2. 推荐的五步流程

1. **发现**：从本仓库登记入口定位官方来源，只查当前目标所需工具；记录来源、提交/版本、目标软件和依赖，并确认是否存在遥测或网络调用。
2. **适配**：确认目标软件存在、版本兼容、输入输出可隔离、命令支持 JSON 或可解析输出，并列出读/写/网络/费用副作用。
3. **准备**：选择“已有 harness”或“生成 harness”；形成有界激活卡，写明精确路径、预算、回滚和停止条件。
4. **试用**：先运行 `--help`、`info`、`list`、`status`、`validate` 或等价只读入口；再执行一项最小可回滚动作。生成端必须保留测试计划和真实后端验证证据。
5. **收口**：回读输出、文件变化、进程、网络和错误；把本轮记为 `COMPLETED`、`SKIPPED`、`BLOCKED` 或 `UNKNOWN`。未知副作用不能写成成功。

## 3. 和 Agency Agents 的组合方式

固定顺序是：总指挥规则与项目边界 → Agency Agents 的已核验职责 → CLI-Anything 的已核验 harness/命令 → 当前目标、输入、输出和验收。

例如游戏项目：

- Game Designer：定义关卡目标、可接受行为和验收样例；
- Technical Artist：定义资源格式、导入和渲染检查；
- CLI-Anything harness：执行只读场景枚举、资源检查或无头验证；
- 总指挥：决定是否允许写入、是否需要人工试玩、如何回滚和是否可以提交。

角色不会给工具增加权限；工具也不会改变 Goal、单写者或交接状态。

## 4. 结果与验证

至少保留：

- 来源 URL、提交/版本和本地实物路径；
- 目标软件版本、运行前基线和精确工作目录；
- 实际命令、参数、退出码、标准输出/错误和结构化 JSON（如有）；
- 文件、进程、网络和远端副作用核对；
- 领域结果验证，例如 PDF/OOXML 结构、图像像素、音频时长、游戏无头退出与报告；
- 未验证项、停止原因和恢复条件。

不能用以下内容单独证明成功：

- 上游 README 的测试数量或“生产级”宣传；
- 进程退出码为 0；
- 生成了 CLI 文件；
- 平台显示“已完成”；
- 角色或工具被目录登记。

## 5. 立即停止条件

遇到来源提交漂移、依赖缺失、安装路径不明确、权限超界、目标版本不兼容、输入来自不可信内容且无法安全转义、文件写入超出激活卡、远端动作未获确认、结果无法独立验证或副作用未知时，只暂停受影响动作。无关的只读分析可以继续。

## 6. 维护与回滚

维护时先记录旧来源和实物指纹，再核对新来源、依赖和安装范围；不要用更新后的 README 直接覆盖旧成功记录。回滚按激活卡移除生成的包、恢复隔离工作区或卸载已登记 harness；无法证明回滚完整时标记 `UNKNOWN`。
