## 研究结论

CLI-Anything 的核心是“方法论/生成器 + CLI-Hub/社区 harness”两层：生成器通过代码分析、架构设计、实现、测试规划、测试实现、SKILL.md、文档和发布/安装形成 Agent 可用 CLI；消费端通过 CLI-Hub 发现并管理已有 CLI。官方 HARNESS 要求 CLI 尽量调用真实软件后端，提供探测/状态/JSON 输出，并用真实后端和实际文件做端到端验证。CLI-Hub 还提供 preview 的只读查看器，并在官方文档中说明默认发送匿名使用事件。

上游 README 的类别、软件清单、测试数量和“生产级”表述均是上游声明。本仓库只把它们作为候选能力，不把它们当成本地安装、兼容性、质量或安全验证。README 不同位置的测试数量会随上游更新变化，因此本记录不固定宣传数字。

## 与本工作流的关系

- 可作为 EXT-002 被发现和提出适配方案；登记不产生安装、项目激活、Goal、写入、通信、远端或部署授权。
- Agency Agents 负责职责与审查视角；CLI-Anything 负责可执行工具面；总指挥工作流继续负责单写者、权限、证据、回滚和人工验收。
- 默认先做只读发现和隔离试用；真实软件调用、生成代码、PATH 安装、用户目录写入、网络和远端 API 都逐项核权。

## 风险与未验证项

1. Codex 接入在上游 README 中标为实验性/社区贡献；Windows PowerShell 安装路径已见于官方文档，但本机未安装、未验证。
2. 目标软件是必需依赖；没有软件、源码、后端 CLI 或稳定 API 时，生成的 harness 可能不完整或不可用。
3. 生成器和社区 harness 会执行子进程、读写项目文件、调用网络或真实软件；必须防路径穿越、脚本/XML 注入、凭据泄露和未预期副作用。
4. 直接编辑项目文件可能绕过 GUI 内部不变量；即使生成了有效 JSON，也必须做真实后端和领域验收。
5. 上游社区注册表、依赖和提交会变化；使用时必须锁定提交/版本并重新核对许可证、变更和回滚。
6. 本轮没有验证 CLI-Hub 可用性、遥测实际网络行为、任何 harness 的 Windows 兼容性、真实游戏项目效果、性能、费用或安全性。
