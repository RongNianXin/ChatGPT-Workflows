# 个性化配置建议

## 结论

不建议把 Agency Agents 的所有角色正文复制进个性化配置。那会让每次对话都带着大量无关规则，增加 Token 消耗，也容易和项目权限、Goal 状态、总指挥单写者规则冲突。

更合适的是只放一条“路由提醒”：当任务需要外部专业视角时，先读取本目录的登记和指南，再推荐一个最小角色，并要求填写激活卡。角色正文只在确认要试用时加载。

## 可选的短配置

下面是建议文本。它只是候选内容；本轮没有修改 ChatGPT 的全局个性化设置，也没有修改受保护的全局提示词文件。

```text
当任务可能需要外部专业角色时，先查阅项目中的“引用的外部工具/agency agents/README.md”和“调用指南.md”。Agency Agents 是可选的角色提示词库，不是新的运行模式。先核验安装状态、来源版本、项目基线和权限，只推荐一个最小角色并填写“角色激活卡模板.md”。不得自动安装、加载全部角色、改变 Goal、越过单写者或执行未授权的产品修改、跨任务通信和远端写入。没有角色文件或版本证据时标记 NOT_INSTALLED/UNKNOWN。角色输出必须和基线逐项对照，没有新增可核验价值就停止试用。
```

## 为什么只放短配置

- 个性化配置适合稳定的行为提醒，不适合存放会更新的第三方角色正文。
- 第三方仓库更新后，目录中的来源和版本记录可以单独维护，不必修改每个用户配置。
- 项目总指挥仍然要根据当前目标做判断，避免所有项目都被同一个角色强行介入。

## 什么时候才考虑写入

只有在操作者明确要修改个性化配置，并确认目标平台、可见范围和最终文本后，才把上面的短配置作为候选载荷再次审查。这个动作与安装 Agency Agents 是两件事；当前状态仍是“未写入”。
