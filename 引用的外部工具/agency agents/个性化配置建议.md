# 个性化配置建议

## 结论

不建议把 Agency Agents 的所有角色正文复制进个性化配置。那会让每次对话都带着大量无关规则，增加 Token 消耗，也容易和项目权限、Goal 状态、总指挥单写者规则冲突。

如确需个性化提醒，只保留正式登记的定位方式；项目总指挥先覆盖目标所需职责，再选择本阶段角色并自动预填激活卡，不要求用户填技术参数。共同对接规范已承担路由，本配置是可选提醒，不是发现或调用工具的必需前置。角色正文只在确认要使用时加载。

## 可选的短配置

下面是建议文本。它只是候选内容；本轮没有修改 ChatGPT 的全局个性化设置，也没有修改受保护的全局提示词文件。

```text
当前消息提出 Agency Agents 或已登记的外部工具及任务目标时，先从已核验第二代规则根向上两级定位工作流仓库，读取其中“引用的外部工具/外部工具目录.md”和“外部工具自动对接规范.md”，再按正式目录进入工具唯一 README。不要以产品项目根替代规则来源，不先扫描技能或插件目录，也不让用户补已登记的来源地址。没有来源锚点时只请求规则根或最小登记包。Agency Agents 是可选角色提示词库，不是新的运行模式；AI 核验来源、共享安装实物、版本、项目基线和权限，先覆盖相关职责，再分开安装集合、本阶段角色与单次调用，自动预填激活卡。已绑定同任务按共同规范第5节续接，保留已消费次数及撤销状态；未安装时先做只读适配与实际候选核验，不宣称正式激活。不得自动安装、加载全部角色、改变 Goal、越过单写者或执行未授权的产品修改、跨任务通信和远端写入。角色输出与基线逐项对照，没有新增可核验价值就停止对应试用。
```

## 为什么只放短配置

- 个性化配置适合稳定的行为提醒，不适合存放会更新的第三方角色正文。
- 第三方仓库更新后，目录中的来源和版本记录可以单独维护，不必修改每个用户配置。
- 项目总指挥仍然要根据当前目标做判断，避免所有项目都被同一个角色强行介入。

## 什么时候才考虑写入

只有在操作者明确要修改个性化配置，并确认目标平台、可见范围和最终文本后，才把上面的短配置作为候选载荷再次审查。这个动作与安装 Agency Agents 是两件事；当前状态仍是“未写入”。
