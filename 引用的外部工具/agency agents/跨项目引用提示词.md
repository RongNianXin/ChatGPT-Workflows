# 跨项目引用契约（AI 内部）

本文件供 AI 在内部组合执行契约，不是第二个操作者入口，不要求用户复制、填写或转交。用户只使用本目录 README 的自然语言或标准模板。AI 从当前对话和目标项目的可核验状态恢复目标；未知项不猜测。

```text
我们中央工作流已经登记了一个外部角色提示词库 Agency Agents：
https://github.com/msitarzewski/agency-agents

请把它作为专业方法参考，按阶段辅助规划、已授权实现或检查。首次默认只读，不因工具或角色取得额外安装、写入、通信、Goal或预算权限。

先从已核验第二代规则根向上两级定位工作流仓库，按其引用的外部工具/外部工具目录.md 进入 Agency Agents 的唯一 README。这个入口属于规则来源，不要求当前产品项目有同名目录。按共同对接规范读取调用指南、安装记录、共享角色状态和必要激活卡；操作者不拼接提示词，也不补已经登记的来源地址。

当前项目：[项目名称]
当前目标：[目标或待确认]
我想让你判断：Agency Agents 是否适合这个目标，当前和后续需要哪些职责，以及本阶段适配的角色和能力缺口。

请按以下顺序处理：
1. 从现有目标、交付物、阶段和技术约束盘点相关职责，列出当前需要、后续可用和无需采用的职责，以及能力缺口。简要检查是否遗漏职责或选择了不适配的角色；有关键未知项时，最多提出1～3个问题。仅在任务复杂或存在关键风险时，评估是否需要独立子 Agent。只暂停依赖未知状态或权限的动作，不把缺口扩大成全局阻断。
2. 先读取共享角色状态；如果已有相同来源、版本、哈希和共享路径，直接复用，不重复安装。
3. 分别列出拟安装的角色和本阶段实际调用的角色，说明候选文件依据、输入、预算和停止条件。首次少量试用不缩小对整个任务所需职责的分析范围；代码审查角色不冒充引擎实现专家。
4. 核验文件、版本和权限，按共同规范第5.0节区分准备与执行。在既有获准私有记录中预填唯一 external_role_binding，明确记录写入者和实际执行者。Goal 尚未启动时可以准备；与实际 Goal 的关联在启动后核验，不提前编造编号，也不恢复旧 Goal。准备阶段不计入正式尝试次数，预检读取和成本如实记录；跨窗口传递时核验通信授权和实际回读证据，不得代替执行者确认角色正文已加载。
   保持主 Goal 模板不变，必要时由 AI 生成一行引用；旧角色追加段仅在说明替换范围并核验权限后，进行最小范围替换。职责默认随同一业务任务保留，明确只试一次时仍按一次执行。到获准节点形成输入基线，按第5.1节持久记录本次尝试占用的次数，并回读核验后再执行。在已有使用授权范围内连续推进；仅确认安装，不构成角色执行授权。恢复时只继续同一次尝试中尚未完成的部分，不重跑完成部分或清零次数；新实例按实际恢复入口自行加载角色正文并核验权限。
5. 角色本身不授权安装 Agent、修改产品、联系其他任务或执行远端写入；已有主任务实现授权时可在其范围内辅助实现。如未安装，先从正式来源只读核对候选，返回最小共享安装方案。只有隔离要求明确时才提出项目范围例外；共享目录写入另核授权，不因当前项目或中央身份获得许可。
6. 审查输出区分基线已有内容、带证据的新发现和最小验证办法；规划或已授权实现的结果，按主任务要求交付成果和验证证据。上述输出均应记录额外耗时和额度消耗、未验证项，以及是否继续执行。

如果角色尚未安装，请明确写 NOT_INSTALLED，不要把“知道这个 GitHub 地址”写成已经接入。发现角色问题、建议优化或缺少角色时，把自然语言转成结构化反馈包交给中央总指挥，不要求操作者另找反馈窗口。
```

## 组合与传递边界

普通对话的持续适配按本工具README与调用指南第5节执行：项目约定与业务绑定分别保留，Goal可不适用；真实启动/恢复入口引用项目约定，再定位当前任务绑定。新项目不继承旧项目启用状态或权限，同项目关闭状态不被旧材料复活。操作者只表达启用与目标，内部记录由AI核验和维护；没有可达入口或实际回读不承诺长期恢复。

- 当前项目总指挥自己执行时，将必要条款组合进本轮契约，不向用户输出另一份待填写模板。
- 委派或跨窗口传递仅在已有明确通信授权内进行，不能因本文件存在而自动发送。
- 概念问题只回答用途与边界；适配判断和角色审查分别核对前提，不把所有请求都升级为安装。

## 最小核账

项目总指挥应返回角色建议或明确的 `NOT_INSTALLED`、`UNKNOWN`、`BLOCKED`，并说明证据和下一步。它不应直接把这段消息当成安装授权、产品修改授权或远端写入授权。
