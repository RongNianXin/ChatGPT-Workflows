# Agency Agents 调用指南（大白话版）

## 1. 它到底是什么

Agency Agents 是 GitHub 上的一组专业角色提示词。每个角色文件都描述一种工作方式，例如 Game Designer、Level Designer、UI Designer 或 Technical Artist。把一个角色文件交给现有 AI，等于请它用这个角色的检查清单重新看一遍材料。

它本身不提供新的模型，也不会自动读取我们的项目。它不会因为装过一次就自动参与所有对话，更不会自动接管总指挥权限。

## 2. 它和我们当前工作流怎么分工

用三层记忆最容易理解：

| 谁 | 负责什么 |
| --- | --- |
| 中央总指挥 | 记录 Agency Agents 的来源、版本、安装范围、更新方式和安全边界。负责安装或升级。 |
| 项目总指挥 | 判断当前项目是否值得使用，选择最小的角色，填写激活卡，决定是否继续。 |
| 专项任务 / 执行 AI | 在激活卡允许的范围内读取材料、执行角色审查并交付证据。不能自行安装、扩大权限或联系其他任务。 |

因此，操作者不需要记住每个角色的细节。你只需要把需求告诉项目总指挥；项目总指挥再根据这份目录选择角色。

## 2.1 提示词怎样组合

操作者不需要把两段提示词手工拼接。项目总指挥在内部生成一份组合后的执行契约，顺序固定为：

1. 总指挥工作流的安全、权限和停止规则；
2. 当前项目规则和专项任务边界；
3. 已核验的 Agency Agents 角色职责；
4. 本次目标、输入材料、输出格式和验收标准。

角色提示词只提供专业视角，不能覆盖前面的权限、隐私、单写者、远端写入或人工验收规则。发生冲突时，以项目规则和总指挥工作流为准。执行 AI 只接收总指挥生成的组合契约，不要求操作者转发原始角色文件。

## 3. 什么时候适合用

适合的情况：

- 任务已经有一份可运行或可评审的基线，需要第二个专业角度检查遗漏。
- 角色的输入、输出和停止条件可以写清楚。
- 这轮工作可以先只读，结果能和现有方案逐项对照。

不适合的情况：

- 目标、素材或权限还没有确认。
- 正在处理 Goal 中断、交接冲突或中央状态不一致。先恢复主任务状态，再考虑角色审查。
- 想靠“多装几个角色”代替需求、试玩、测试或人工验收。

推荐顺序是：先保存项目基线，再让一个角色进行一轮有限审查；只保留会改变决策的新发现。没有新增可核验价值，就停止角色试验，继续原项目任务。

## 4. 怎么接入

### 第一步：先确认是否已经安装

先看 [`安装与维护记录.md`](安装与维护记录.md)。记录是 `NOT_INSTALLED` 时，不要在项目任务里假装角色已经可用。

当前有两种技术路径：

1. **项目范围安装（推荐用于试用）**：使用 Agency Agents 官方网页或项目范围的安装入口，只把需要的角色放到指定项目可见范围。优点是影响面小，便于删除和回滚。实际入口和当前版本要由中央总指挥现场核对，不能凭旧教程猜测。
2. **Codex 角色目录安装**：官方仓库提供转换/安装脚本，转换后的角色可能进入用户级 `~/.codex/agents/`。这会影响同一用户下的多个任务，试用前必须明确范围、版本和回滚办法。本项目当前没有执行这条安装命令。

不要把“能访问 GitHub”理解成“已经安装”。没有安装记录、角色文件和版本证据时，状态写 `UNKNOWN` 或 `NOT_INSTALLED`。

### 第二步：选择一个角色

先从一个角色开始。示例游戏项目项目的首轮可以考虑 Game Designer；关卡结构问题可以考虑 Level Designer，界面问题可以考虑 UI Designer，美术管线问题可以考虑 Technical Artist。这个映射只是候选，不是自动授权。

### 第三步：填写角色激活卡

复制 [`角色激活卡模板.md`](角色激活卡模板.md)，至少填上：角色来源、版本或提交、目标任务、输入材料、只读/写入范围、禁止项、输出格式、预算、停止条件和证据位置。

### 第四步：把激活卡和材料交给执行 AI

要求它只使用卡片里指定的角色和材料，并在输出中分开写：

- 与基线重复的内容；
- 新增且有证据的发现；
- 最小验证办法；
- 额外时间或额度成本；
- 未能验证的部分。

没有真实试玩观察时，角色只能评价设计和证据缺口，不能声称玩家体验已经改善。

### 第五步：回读结果并决定是否继续

项目总指挥把角色输出和基线逐项对照。只有新增发现确实改变决策，才安排下一步；否则标记 `SKIPPED` 或 `COMPLETED` 并回到原 Goal。角色审查不改变目标、预算、停止条件、单写者或远端权限。

## 5. “自动接入”到底是什么意思

这里的自动接入只是“AI 根据任务描述推荐一个已经登记的角色，并生成激活卡草案”。它不包含自动安装、自动加载全部角色、自动修改代码或自动联系其他任务。

如果以后要做自然语言路由，推荐只把一个很短的路由规则放入个性化配置，具体内容见 [`个性化配置建议.md`](个性化配置建议.md)。不要把几十个角色全文塞进个性化配置。

## 6. Goal 中断时怎么办

Agency Agents 和 Goal 是两件事。角色审查完成后，Goal 是否继续运行取决于 Goal 自己的状态：

1. 先查看项目总指挥记录中的目标、停止条件和当前状态。
2. 如果 Goal 因人工反馈暂停，按当前平台的 Goal 恢复操作继续；普通聊天消息只会处理这条消息，不一定会恢复长任务。
3. 恢复后先确认它从哪一个精确断点继续，再决定是否重新启用角色。

不要因为角色输出已返回，就把 Goal 误判为已经恢复或已经完成。

## 7. 常见错误

| 现象 | 正确处理 |
| --- | --- |
| 项目 AI 说“有 Agency Agents”，但拿不出角色文件和版本 | 标记 `UNKNOWN`，回到中央记录核验。 |
| 想一次装完全部角色 | 暂停，先说明范围和回滚成本，只安装当前需要的角色。 |
| 角色要求修改代码或联系其他任务 | 按项目权限拒绝越界动作，只保留允许的审查结果。 |
| 角色输出只是重复基线 | 结束试用，不把重复内容算成效果提升。 |
| Goal 收到人工反馈后停住 | 单独核对 Goal 状态并执行平台恢复操作，不把普通对话当作恢复命令。 |

## 8. 最小成功标准

一次 Agency Agents 试用至少应留下：

- 一份试用前基线；
- 角色来源和版本证据；
- 一张完成的激活卡；
- 角色逐项输出及证据；
- 与基线相比的新增价值判断；
- 未验证项、停止原因和下一步。

缺任何一项，都只能说“完成了部分审查”，不能说 Agency Agents 已经改善了项目。
