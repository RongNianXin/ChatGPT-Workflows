# 角色共享状态与复用规则（AI 内部记录）

本文件说明所有项目总指挥如何共享外部角色安装状态。操作者不需要直接维护它；项目总指挥读取后只报告与当前目标有关的结果。

## 共享安装位置

同一用户配置下的共享角色默认使用 `<USER_CODEX_HOME>/agents`，运行时按当前用户的实际 Codex 标准目录解析。这是用户级共享目录，各项目在实际访问权限允许时读取同一份角色文件；默认不各自复制。项目隔离要求或共享不可用时可以提出项目范围例外，但必须单独记录范围，不能当作用户级共享安装。当前登记工作流架构师及六个游戏相关角色，共7个；具体文件、版本与加载状态以 JSON 和实物回读为准。六个已有文件只补登记，没有重新安装，宿主原生发现和项目实际调用分别核验。

安装前，共享库维护者必须记录角色名、官方来源、版本或提交、文件哈希、共享路径、安装时间、回滚方式和状态，并核对目标目录写入许可。本仓库中央身份不能代替该许可。没有这些证据，角色只能标记为 `UNKNOWN` 或 `NOT_INSTALLED`；目录不可访问时不能推断所有项目都未安装。

## 复用规则

1. 项目总指挥先读取 [`角色共享状态.json`](角色共享状态.json)，再读取 Agency Agents 的本地维护记录。
2. 角色名称、来源、版本、文件哈希和共享路径全部匹配时，直接复用，不重复安装。
3. 任一项不匹配时，先标记 `UNKNOWN`，由中央总指挥生成最小更新或安装候选；不得静默覆盖已有角色。
4. 项目使用仍需建立本项目激活卡；共享安装不等于所有项目自动激活。
   任务职责集合、阶段加载和单次结果在同一私有绑定内分别保存；开始前消费、同次恢复及交接按 [`共同规范第5节`](外部工具自动对接规范.md#5-安装后的自动调用与任务续接)，共享 JSON 不存业务绑定或执行许可。
5. 角色更新后，中央总指挥回读状态并把影响范围通知后续使用的项目总指挥。

## 状态含义

- `NOT_INSTALLED`：没有可核验的角色文件。
- `READY_FOR_ACTIVATION`：共享文件、来源、版本和哈希均已核验，可以绑定专项任务。
- `IN_USE`：已有项目在激活卡范围内使用，不代表其他项目自动继承任务数据。
- `UNKNOWN`：证据冲突、路径不可读或版本不明，暂停复用。
- `RETIRED`：停止新项目使用，但保留历史记录。

## 反馈和经验

项目总指挥收到“角色有问题”“这个角色应该怎么改”“缺少某类角色”或类似自然语言时，不要求操作者填写表单。它先把反馈转换成结构化建议包，写入当前任务的本地记录，并交给中央总指挥在维护窗口统一去重、验证和更新。详见 [`角色经验与反馈记录.md`](角色经验与反馈记录.md)。
